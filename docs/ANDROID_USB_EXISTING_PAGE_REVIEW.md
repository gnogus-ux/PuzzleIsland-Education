# USB로 연결된 안드로이드의 기존 웹 초안 검수

2026-11-09 공식 Android ADB 문서·Chrome DevTools 문서·AOSP 입력/브라우저 소스와 ADB 도움말의 필요한 범위를 대조한 절차다. [공식5자료의 실제 열람·적용 범위](../reports/ExternalLearning/20261109_ANDROID_USB_EXISTING_PAGE_STUDY.json)를 함께 확인한다. 문서 학습과 실제 휴대폰 검수 성공은 별개다. 설치·USB 디버깅/RSA 허용·계정 인증·휴대폰 설정 변경을 이 절차가 대신 승인하지 않는다.

## 목표와 시작 조건

사용자가 오류가 난 휴대폰을 USB로 연결해 검수를 직접 요청한 경우, 이미 설치된 ADB와 이미 허용된 USB 연결을 사용해 **현재 열려 있는 웹페이지의 오류와 미저장 초안을 먼저 보존**한다. PC의 다른 프로그램·휴대폰 다른 앱·다른 기기의 내용을 작업 대상으로 확대하지 않는다. 사용자가 이후 현재 연결된 다른 폰에서 별도 USB 로컬 시험을 명시적으로 요청했다면, 그 폰을 새 시험 대상으로 확인하고 아래 별도 절차를 적용한다. 이를 원래 오류폰의 재현이나 외부망 해결로 기록하지 않는다.

[공식 ADB 문서](https://developer.android.com/tools/adb?hl=en)의 device 상태는 ADB 연결 상태이며, 정상 부팅·현재 앱 준비 완료·사용자가 의도한 오류폰과의 일치를 보장하지 않는다. 새 장치가 연결되거나 USB 연결이 바뀌면 목록을 다시 확인한다. 모델명·배터리·화면은 대조 단서이며 단독 증거가 아니다. 사용자가 보낸 오류 사진과 현재 USB 화면의 앱·오류·작성 상태를 대조하고, 다르거나 사용자가 다른 기기라고 알리면 **입력·앱 열기·포트 전달을 모두 중지**한다. 대상 휴대폰에 대한 사용자 확인을 받은 뒤 다시 읽기 전용 관찰부터 시작한다.

## 1. 읽기 전용으로 대상과 현재 화면 확인

다음은 명령의 형태다. 실제 실행 경로·serial·개인 저장 경로는 비공개 작업 기록에서만 사용한다. 모든 장치 명령에 현재 확인한 단일 대상의 `-s SERIAL`을 붙인다. 여러 연결 중 임의의 첫 항목을 선택하거나 이전 기기의 serial을 재사용하지 않는다.

```text
adb version
adb devices -l
adb -s SERIAL exec-out screencap -p
adb -s SERIAL shell input help
```

공식 문서는 screencap의 파일명 생략과 PNG 옵션·exec-out으로 원시 이미지 바이트를 PC로 전송하는 방법을 설명한다. PNG 출력은 텍스트가 아닌 바이트로 보존한다. 텍스트 파이프나 인코딩 변환을 거치지 않는다. 예를 들어 기존 Python의 subprocess stdout을 bytes로 받아 비공개 PNG 파일로 저장할 수 있다. 새 캡처 도구나 휴대폰 앱 설치는 필요하지 않다. 이 흐름은 폰에 임시 screenshot 파일을 쓰지 않는다.

캡처는 잠금·PIN·인증·다른 앱의 개인 화면일 수 있다. 이를 발견하면 대상으로 조작하지 않고 필요한 사용자 직접 단계를 알린다. 대상 페이지가 확인되지 않았다고 브라우저를 강제로 열거나 URL을 실행하지 않는다. 홈 화면 위젯·주소·알림·제품 사진이 담긴 원본 캡처는 공용 자료실에 게시하지 않는다.

## 2. 기존 화면에서 오류 읽기와 초안 보존

1. 현재 페이지와 오류폰이 일치함을 확인한 후 전체 화면을 보고 상단 저장 상태·오류 상세·편집점·미저장 표시를 기록한다. 읽힌 오류와 추정 원인을 구별한다.
2. 오류 상세가 화면 아래/위에 있으면 **캔버스·슬라이더·새로고침 제스처가 아닌 문서 여백**을 먼저 확인한다. 한 번의 짧은 스크롤만 수행하고 새 캡처로 위치와 데이터 불변을 확인한다. 화면 상단에서 당겨 새로고침을 일으키지 않는다.
3. 새로고침·뒤로가기·주소 변경·탭 전환·브라우저 종료·재인증·서버/터널 재시작을 하지 않는다. 오류 확인을 위해 저장 버튼을 반복해서 누르지도 않는다.
4. 현재 앱에 이미 제공된 **초안 내려받기** 동작을 식별한 경우에만 한 번 실행한다. 새 파일은 기존 다운로드를 덮어쓰지 않는다. 다운로드 성공·파일 존재·내용/점 좌표가 보존됐는지를 확인한다. 파일 선택/권한/인증 창이 나타나면 사용자 직접 단계로 넘기고 우회하지 않는다.
5. 초안 보존 기능이 없거나 실행 결과가 불명확하면 화면을 유지한다. 앱 내부 데이터/브라우저 저장소를 임의 덤프하거나 APK·root·DB 접근으로 대체하지 않는다. 보호된 사용자 초안이 확보되기 전에는 새로운 검수 데이터로 덮어쓰지 않는다.

[AOSP InputShellCommand](https://github.com/aosp-mirror/platform_frameworks_base/blob/main/services/core/java/com/android/server/input/InputShellCommand.java)는 tap·swipe·draganddrop·keyevent 등의 입력이 실제 이벤트를 발생시킴을 보여 준다. 실행 기기의 `input help`와 화면에서 확인한 좌표만 사용한다. 캡처 픽셀과 입력 좌표의 방향·해상도·시스템 UI 영역이 맞는지 대조하고 추측 좌표를 연속 실행하지 않는다. 키보드가 열렸거나 화면이 회전/이동했다면 이전 좌표를 버린다. 텍스트 입력·삭제·키 이벤트는 필요한 대상과 초안 보존이 확인된 뒤 별도 동작으로 수행한다.

이 소스의 motion-event 생성은 pointerCount=1이다. **ADB tap/swipe 성공은 두 손가락 pinch 검증이 아니다.** 여러 독립 swipe 프로세스를 동시에 실행해 다중 터치라고 주장하지 않는다. 사용자의 실제 두 손가락 입력이나 검증된 별도 경로가 없다면 해당 검사는 미검증으로 남긴다.

## 3. 기존 Android Chrome 페이지의 선택적 원격 검사

[Chrome 공식 원격 디버깅 문서](https://developer.chrome.com/docs/devtools/remote-debugging?hl=en)는 USB로 연결된 실제 기기의 **기존 탭**을 Inspect할 수 있음을 설명한다. 장치의 Chrome 버전에 맞는 DevTools가 열린다. 문서의 Open tab with url·Reload·Close·Pause·인증 초기화·설정 변경 예시는 이 보존 작업에 적용하지 않는다.

현재 도구·권한으로 이미 허용된 원격 검사 경로가 확인된 경우, 대상 기기·기존 페이지를 정확히 선택해 보이는 오류 텍스트나 DOM 상태를 읽는 데 한정한다. Attach가 새로고침을 요구하거나 다른 탭·앱을 선택하게 하면 중단한다. Cookies·인증 토큰·PIN·모든 저장소를 수집하지 않는다. 콘솔에 임의 코드를 실행해 save·fetch·navigation·초안 변형을 일으키지 않는다.

공식 문서의 수동 CDP 예시는 `adb forward tcp:PORT localabstract:chrome_devtools_remote`이다. 이것은 **PC에서 휴대폰 디버깅 소켓에 접근하는 전달**이며 폰의 웹 요청을 PC 서버로 돌리는 `adb reverse`와 다르다. 새 forward가 필요하다면 기존 전달을 먼저 읽고 소유한 빈 localhost 포트 하나에만 한정하며, 검사 후 그 항목만 해제한다. 다른 전달을 덮어쓰거나 전체 remove-all로 정리하지 않는다. 대상 확인/권한 확인 전에는 추가하지 않는다. 연결 불가를 USB 디버깅 설정·RSA 승인 초기화·드라이버 설치·ADB 서버 재시작으로 자동 복구하지 않는다.

Screencast의 PC 클릭은 폰 터치로 전달되고 키 입력도 전달될 수 있다. 단순 관찰 창으로 간주하지 않는다. Screencast는 프레임률에 영향을 주므로 그 상태의 속도를 정상 실사용 성능으로 단정하지 않는다. 이번 목적에서는 원본 화면/초안을 보존하는 최소 관찰과 입력만 사용한다.

## 4. USB 조작 연결과 외부 통신을 구분한다

ADB USB로 기존 외부 페이지를 관찰할 때는 폰의 웹 통신이 기존 보호 HTTPS 경로를 유지하도록 한다. `adb reverse`, 휴대폰 LAN/localhost 접속, VPN, 테더링·Wi-Fi 설정 변경을 외부 이동통신 시험의 대체 근거로 쓰지 않는다. USB가 연결됐다는 사실만으로 현재 웹 트래픽이 어느 망을 쓰는지 확정하지 않는다. 외부망 사용은 사용자가 설정한 현재 상태와 관찰 근거로 별도 기록한다. 사용자가 이동통신 검수를 미루고 USB 로컬 시험을 명시한 경우에는 다음 절차로 구분한다.

[Cloudflare 이슈1752](https://github.com/cloudflare/cloudflared/issues/1752)는 보호된 Quick Tunnel에서 짧은 인증 세션 후 GET 재인증·변경 요청401을 보고한다. [지정 버전 소스](https://github.com/cloudflare/cloudflared/blob/2026.10.7/quicktunnelauth/session.go#L99)는 세션 만료를 identity 만료와 현재+4시간 중 빠른 시점으로 정하므로 **최대4시간은 보장 기간이 아니다.** 다만 비슷한 오류·원본 서버 POST 부재만으로 현재 실패를 이 이슈와 같은 원인이라고 확정하지 않는다. 정확한 오류/응답·시간 대응과 로그 연속성을 확인하며, 보호 제거·쿠키 수명 조작·반복 재인증을 해결책으로 만들지 않는다.

## 5. 명시 승인된 별도 USB 앱 경로 시험

이 절차는 사용자가 **현재 연결된 폰의 USB 로컬 시험**을 별도로 요청한 경우에 한한다. 원래 오류폰의 미저장 페이지를 이어 쓰거나 기존 외부 인증을 해제하는 작업이 아니다.

1. 현재 기기·현재 화면과 사용자의 시험 대상 지정을 대조한다. 기존 페이지의 초안이 있으면 먼저 보존하고, 원래 오류폰은 변경하지 않는다. PC의 이미 실행 중인 시험 서버와 분리된 시험 프로젝트를 사용한다. 생산 원본/실제 사용자 입력을 시험값으로 덮어쓰지 않는다.
2. [AOSP adb 도움말](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/docs/user/adb.1.md)의 reverse 목록을 읽는다. 선택한 폰 포트에 기존 매핑이 있으면 소유권과 대상을 확인하며 덮어쓰지 않는다. 새로운 한 항목만 `--no-rebind`로 추가한다. 충돌 시 기존 항목을 지우지 말고 다른 비점유 포트를 선택하거나 중지한다.

```text
adb -s SERIAL reverse --list
adb -s SERIAL reverse --no-rebind tcp:PHONE_PORT tcp:PC_PORT
```

3. 폰의 localhost PHONE_PORT 요청이 USB를 거쳐 PC의 해당 서버로 향하는 **별도 로컬 앱 경로**임을 기록한다. 기존 외부 HTTPS 터널·이메일 보호·Host/Origin 정책은 유지한다. 브라우저 localhost의 원점도 외부 HTTPS 원점과 다르므로 기존 앱의 로컬 지원 계약 안에서만 시험한다.
4. 새 시험 탭을 명시적으로 요청한다. [AOSP Browser.EXTRA_CREATE_NEW_TAB](https://github.com/aosp-mirror/platform_frameworks_base/blob/main/core/java/android/provider/Browser.java)은 Boolean extra 값 `create_new_tab`을 정의한다. ACTION_VIEW와 함께 이 extra를 사용하더라도 해당 Chrome의 실제 동작을 캡처로 확인해야 한다. 기존 탭이 재사용되거나 초안이 사라질 위험이 있으면 중지한다. 앱 열기/새 탭은 승인된 이 별도 경로에서만 수행하며 보존 중인 원래 오류 탭에는 적용하지 않는다.
5. 분리된 시험 프로젝트에서 실제 화면의 점 선택·수정·저장·다시 열기를 확인하고 PC 저장본의 revision/좌표와 대조한다. USB 로컬에서의 저장 성공과 외부 인증·이동통신 경로의 저장 성공을 구별한다. ADB 단일 포인터 입력의 다중 터치 검증 한계도 유지한다.
6. 시험 후 처음 추가한 매핑과 현재 매핑이 같은지 확인하고 **자신이 추가한 항목만** 해제한다. 다만 사용자가 열린 시험 탭으로 계속 사용하도록 명시한 경우에는 해당 탭과 소유 매핑을 유지하고 유지 이유·연결 수명·나중의 정리 대상을 기록한다. USB/ADB 연결이 끊긴 뒤에도 같은 매핑이 유지된다고 보장하지 않는다. 사전 존재 항목은 남기며 `--remove-all`을 사용하지 않는다. 기존 공유 ADB 서버·다른 탭·외부 터널을 종료하지 않는다.

```text
adb -s SERIAL reverse --list
adb -s SERIAL reverse --remove tcp:PHONE_PORT
```

## 6. 후속 제한 실기 — 실제 폰의 USB 측정 경로

2026-11-09 별도 Codex 독립 검수 담당이 사용자가 지정한 현재 USB 연결 폰에서 분리된 측정 시험을 수행했다. 이 매뉴얼 게시 담당은 저장된 결과·보존 보고를 읽고 대조했으며 폰·앱·런타임을 새로 조작하지 않았다. [익명화한 제한 실기 기록](../reports/ToolInventory/20261109_ANDROID_USB_SCOPED_REVIEW.json)을 함께 확인한다.

실제 화면에서 확대, 점 선택, 원본 사진 좌표 기준 한 픽셀 미세 이동, 저장을 수행했다. Chrome 메뉴의 실제 다시 로드 후 같은 점을 다시 선택해 수정된 좌표와 저장 revision이 유지됨을 확인했다. PC의 전체 측정 구성을 대조한 결과도 의도한 한 점의 한 픽셀 변경만 일치했다. 원본 자료·이전 코드의 보호 해시 대조는 검수 담당 보고에서 유지됐다. 이는 **USB 로컬 측정 화면의 해당 핵심 경로 통과**이며 전체 프로그램이나 실제 두 손가락 입력 검증이 아니다.
