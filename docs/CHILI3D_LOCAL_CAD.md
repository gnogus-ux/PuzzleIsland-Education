## 설치 전 확인

[공통 도구 규칙](COMMON_TOOL_POLICY.md)과 [설치 목록](AVAILABLE_TOOLS.md)을 먼저 읽는다. 새 프로그램 설치는 해당 사용자의 명시 승인 범위에서 수행한다. 설치 보류의 예외를 다른 프로그램으로 확대하지 않는다.

Chili3D는 브라우저에서 실행하는 CAD다. .blend 편집기나 Blender 리그·재질을 그대로 옮기는 도구가 아니다. 기본 CAD 작업은 외부 모델 API 키 없이 시작할 수 있다. AI 제공자와 유료 Pro 작업은 별도 범위로 확인한다. 주 소스는 AGPL-3.0, C++ 부분은 LGPL-3.0으로 안내되므로 수정·배포 시 저장소 라이선스를 직접 확인한다.

공식 소스를 독립 폴더에 받고 커밋을 고정한다. 기존 Node와 lockfile을 사용해 `npm ci`, 공식 `npm run dev` 경로를 따른다. 이번 제한 실기는 기존 Node 24.22.0/npm 11.19.1에서 실행했다. 포함된 WASM을 먼저 사용하고 필요하지 않은 C++/Emscripten을 일괄 설치하지 않는다. 설치 중 경고를 임의 전역 업데이트로 해결하지 않는다.

로컬 전용 작업은 loopback 주소와 고정 포트를 사용한다. 포트가 이미 다른 프로그램에 점유됐으면 종료하지 않는다. 제품을 열기 전에 로컬 HTML의 외부 분석 코드를 확인한다. 이번 독립 로컬 설치에서는 기본 Clarity 분석 코드를 제외했다. 외부 커뮤니티 링크까지 모든 네트워크 기능을 차단한 상태라는 뜻은 아니다.

## Blender 제품을 검토 문서로 옮기기

1. 현재 저장 버전·원본 해시·승인 참고자료를 확인하고 독립 사본을 만든다. 다른 담당의 라이브 장면을 읽는 것만으로도 점유가 생길 수 있으므로 진행 중인 장면에 무단 연결하지 않는다.
2. [Blender 제작 절차](BLENDER_SKILLS_WORKFLOW.md)의 사본·평가 메시 읽기/해제·단위·왕복 검증을 적용한다. [애드온 목록](BLENDER_ADDONS.md)을 먼저 확인하되 기본 읽기 기능으로 충분하면 새 애드온을 설치하지 않는다.
3. 기준 좌표계와 단위 변환을 기록한다. Chili3D 길이는 mm, 각도는 도다. Blender 장면 단위 설정·실제 평가 좌표·알려진 제품 치수를 함께 대조한다. 일반적인 m 좌표에는 1000을 곱하지만 파일마다 이를 확인한다.
4. 정확 곡면은 STEP/BREP를 우선한다. STL은 삼각면으로 변환되며 매끈한 CAD 곡면·UV·재질·리그·설계 이력을 되살리지 않는다. 큰 평가 메시 전체를 무조건 B-rep로 바꾸지 말고 검토 목적에 필요한 단면·부품부터 옮긴다.
5. 단면 교선에는 열린 조각·분기·중복·짧은 선이 있을 수 있다. 곡선 단순화를 썼다면 허용 편차와 누락 가능성을 기록한다. 단면 문서를 제조용 재단 패턴이나 완전한 제품 CAD로 표시하지 않는다.
6. 몸판·포켓·내피처럼 층을 별도 이름으로 유지한다. 두 점 거리, 선택한 형상의 길이·면적·체적은 해당 형상에 맞는 측정으로만 사용한다. 선 문서의 체적으로 가죽 부피를 판정하지 않는다. 높이 좌표 범위는 재료 두께와 다르다.
7. 외형을 실제 바꾸려면 [공통 작업 규칙](COMMON_WORK_RULES.md)의 실제 Guide→담당 인계→단독 점유→동일 solid/wire 검수 절차를 별도로 따른다. CAD 검토가 이 절차를 대체하지 않는다.

이번 로컬 선 형상 시험에서는 OCCT `boundingBox()`에 공차 여유가 포함되어 실제 꼭짓점 범위보다 크게 나왔다. 정확한 길이 확인에는 꼭짓점·끝점/커브 측정을 대조한다. 커널 바운딩 박스를 곧바로 제품 실측값으로 쓰지 않는다.

## 저장·재열기와 운영

- 자동 저장이 없다. Ctrl+S는 해당 브라우저 원점의 IndexedDB에 저장하고, 파일 저장은 .cd를 내려받는다. 중요한 시점에는 별도 .cd와 STEP/BREP를 함께 보관한다.
- 이 버전의 .cd는 문서 형식 0.7.1을 엄격히 확인한다. 앱 버전 0.8.0과 혼동하지 않는다. 버전 이동 전 백업하며 자동 마이그레이션을 가정하지 않는다.
- 이름 변경은 새 문서 ID를 만들지 않는다. 최근 프로젝트 삭제는 문서 본체도 삭제한다. 닫기 확인의 취소 역시 저장 없이 닫는 동작이다.
- 문서 저장→페이지 새로 열기→동일 .cd 로드→노드 수·형상·실측값 대조를 실행한다. STEP는 최종 형상 교환용이며 파라메트릭 이력과 문서 설정은 포함하지 않는다.
- 최소 화면 검수는 읽을 수 있는 카메라와 맞춤 보기로 한다. 최소화된 창에서 캡처가 실패하면 같은 작업 공간의 창을 정상 복원한 뒤 viewport 크기와 맞춤 보기를 갱신한다.
- 개발 서버는 해당 폴더의 소스와 의존성을 사용한다. 실행 중 서버·저장 문서·로컬 파일을 구별한다. 공개 코드 저장소에 비공개 제품 파일이 섞이지 않도록 로컬 제외 규칙과 실제 Git 상태를 확인한다.

## 2026-11-04 제한 실기

명시 승인된 독립 로컬 설치에서 의존성 설치, 앱 컴파일/형식 검사, ego-browser의 WASM 초기화·표시, 검토용 선 형상 생성, .cd 저장/재열기 및 STEP 출력을 실행했다. 재열기 후 10개 노드의 CAD 형상 검사를 통과했다. 실제 꼭짓점 범위를 대조했다.

이 결과는 Blender 원본 수정·전체 제품 폐합/충돌·물리 시뮬레이션·제조 공차 검증·AI API 연결·유료 Pro 기능 검증을 포함하지 않는다. STEP 출력 성공과 다른 CAD의 재수입 검증도 구별한다. 현재 실기는 STEP 재수입까지 확인하지 않았다. 개별 제품 자료·개인 경로는 공용 매뉴얼에 게시하지 않는다.

## 전체 제품을 참고 메시로 표시하는 별도 경로

단면 검토와 전체 제품 표시는 목적이 다르다. 큰 삼각 메시를 OCCT의 개별 B-rep 면으로 변환하면 비용이 커질 수 있다. 고정 버전의 기본 MeshNode 문서 구조를 사용하면 원래 삼각 형상을 참고 메시로 표시할 수 있다. 정밀 CAD 솔리드·스케치 특징 이력이 생기는 경로는 아니다.

이 경로를 위해 같은 고정 커밋의 공식 소스 세 묶음을 실제 검토했다: [MeshNode와 옵션](https://github.com/xiangechen/chili3d/blob/4600206f9b354421f4de288e853efcde926da080/packages/core/src/model/meshNode.ts), [Mesh와 TypedArray 필드](https://github.com/xiangechen/chili3d/blob/4600206f9b354421f4de288e853efcde926da080/packages/core/src/shape/meshData.ts), [직렬화·역직렬화](https://github.com/xiangechen/chili3d/blob/4600206f9b354421f4de288e853efcde926da080/packages/core/src/serialize/serializer.ts). 노드 트리의 parentId와 재료 목록은 modelManager.ts/node.ts, 실제 표시 조건은 threeVisualObject.ts의 MeshNode 처리와 대조했다. 일반 사용자용 안정적 교환 API라는 보장은 없으므로 버전을 고정하고 작은 시험 문서를 먼저 열어 필드 호환을 확인한다.

평가된 좌표·삼각 인덱스·법선을 독립 문서에 기록하고 부품 이름·개수·삼각 수·단위·실제 꼭짓점 범위를 대조한다. 원래 메시를 줄이거나 형상을 변경하지 않는다. 원본 보존, 고정 자세, 좌표 정밀도, 재질/UV/리그 손실을 명시한다. 단순 검토 재료를 원래 PBR 재현으로 표시하지 않는다. 큰 문서는 파일 크기·메모리·열기/저장 제한을 실제 시험하고, 브라우저 저장이 성공하지 않으면 디스크 파일과 검증 범위를 구분해 남긴다.

후속 제한 실기에서 작은 시험 부품을 먼저 열어 호환을 확인한 뒤 전체 부품의 참고 메시 문서를 열고 IndexedDB에 저장·재열기했다. 실제 앱 메모리의 Float32 좌표와 Uint32 삼각 인덱스 바이트 해시가 이관 자료와 모두 일치했다. 면 수를 줄이지 않은 형상 보존의 근거이며 원본 PBR·UV·리그나 CAD 솔리드 기능의 재현 검증은 아니다.

Windows 개발 서버는 큰 파일을 복사하는 동안 정적 파일 감시가 EBUSY로 종료될 수 있었다. 이 로컬 구성에서는 Rspack의 정적 파일 watch를 끄고 .cd를 Copy 플러그인과 코드 감시 대상에서 제외해 보완했다. 문서는 loopback 정적 파일로 제공한다. 실행 바로가기는 저장된 문서 ID를 먼저 열고 없을 때만 디스크 기준 파일을 읽어 저장하므로, 매번 초기 파일을 다시 열어 사용자의 저장 내용을 덮어쓰지 않도록 한다.

## 외부 휴대폰 접속의 준비와 승인 경계

로컬 주소 127.0.0.1은 해당 기기 자신을 뜻한다. 같은 Wi-Fi의 LAN 접속과 외부 이동통신 접속은 다른 구성이다. 사용자 요청이 외부 사용이면 기존 프로그램을 먼저 확인하고, 필요한 새 프로그램의 명칭·용도·설치/계정 조건을 제시해 승인받는다. 관리자 설치, 휴대폰 VPN 구성 허용과 계정 로그인은 실제 사용자 직접 단계와 구분한다.

2026-11-04 다음 공식 문서를 실제 읽었다: [Windows 설치](https://tailscale.com/docs/install/windows) 전체, [Android 설치](https://tailscale.com/docs/install/android) 단일 계정 로그인·VPN 구성 범위, [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve) 동작·HTTPS·접근 제한·예시·제한, [Serve CLI](https://tailscale.com/docs/reference/tailscale-cli/serve) 대상/배경 실행/상태/끄기 범위. 공식 Windows 다운로드 페이지의 배포 링크도 확인했다. 아래는 이 자료에 따른 준비 절차이며 현재 Tailscale 설치·로그인·휴대폰 실기 검증 완료를 뜻하지 않는다.

Tailscale Serve는 같은 tailnet의 접근 허용된 기기에 로컬 웹 서비스를 제공한다. PC와 휴대폰을 같은 계정에 연결하고 접속 범위를 확인한다. 이 목적에는 공개 인터넷 서비스인 Funnel을 사용하지 않는다. 기존 Serve 설정이 있다면 읽고 보존하며 전체 reset으로 다른 서비스를 없애지 않는다. 프로그램 다운로드와 서명 검증, 설치 완료, 로그인 완료, Serve 활성, 실제 외부 접속을 각각 기록한다. 새 결제나 유료 플랜을 자동 선택하지 않는다.

웹 앱은 loopback에서 계속 실행하고, 승인·인증 후 실제 CLI 도움말/상태에 맞춰 `tailscale serve --bg http://127.0.0.1:18080`처럼 해당 서비스만 연결한다. HTTPS 활성에 사용자 웹 동의가 요구되면 사용자가 직접 완료한다. 실제 주소를 얻기 전에 임의 주소를 완료 링크로 제공하지 않는다. 개발 서버 Host 검사가 걸리면 실제 발급 도메인만 허용하고 모든 호스트 허용으로 우회하지 않는다. 브라우저의 주소·모델 파일 경로도 같은 HTTPS 원점에 맞춘다.

PC 전원·인터넷·서버 실행과 휴대폰 연결 앱이 유지돼야 한다. PC와 다른 네트워크인 휴대폰의 이동통신에서 실제 열림을 별도로 확인한다. PC 내부에서 주소가 응답한 것만으로 휴대폰 실기를 통과 처리하지 않는다. 큰 전체 메시 문서는 실제 휴대폰 메모리와 로딩 시간을 확인한다.

Chili3D의 문서 저장은 브라우저별 IndexedDB다. PC의 localhost, 사설 HTTPS 주소와 휴대폰 브라우저는 저장소가 서로 다르며 자동 공동 편집·자동 동기화가 아니다. 외부 접속을 설정해도 이 특성은 그대로다. 기기 간 최신 내용을 옮길 때는 .cd 파일을 명시적으로 저장·전달하고 기존 수정본을 보존한다.

### 후속 설치·기기 연결 확인

사용자의 PC 설치/안드로이드 사용 승인 후 공식 Tailscale 1.104.5 설치 파일의 Windows Authenticode 유효 서명과 발행자를 확인하고 설치했다. 관리자 승인은 사용자가 직접 완료했다. 설치 종료 코드 0과 실제 CLI 버전, PC의 Running 상태 및 온라인 Android 피어를 확인했다. CLI 도움말의 Serve 배경 실행·상태 옵션을 현재 설치 버전과 대조했다. 이는 HTTPS 사용 동의·Serve 활성·휴대폰 이동통신 접속 성공을 의미하지 않는다. 현재 Serve 명령이 계정의 HTTPS 활성 동의를 요청했으며, 사용자 직접 처리 단계에서 기다리고 있다.

로컬 개발 서버에는 실제 발급된 개별 사설 도메인만 허용하고 HTTP Host 검사를 했다. 허용 도메인의 HTML/문서 200과 임의 호스트의 403을 확인했다. 자동 갱신 클라이언트를 꺼서 외부 브라우저의 잘못된 로컬 WebSocket 시도와 모델 보기 중 자동 새로고침을 줄였다.

후속 사용자 직접 HTTPS 동의가 완료돼 Serve 배경 프록시 활성과 설정을 확인했다. 실제 유효한 HTTPS 연결로 모바일 첫 화면과 전체 문서의 200 응답을 확인했다. 모바일 시작 페이지에는 최초 기준본 열기와 브라우저 저장본 이어서 열기를 구분했다. 휴대폰의 다른 네트워크에서 실제 모델 표시와 성능을 확인하는 단계는 별도이며, 사용자의 이동통신 접속 결과를 기다리는 상태다. 접속 도메인·장치 정보·동의용 URL은 공개 매뉴얼에 기록하지 않는다.

## 개발 서버에서 Loading이 계속될 때

실제 외부 접속에서 초기 Loading 정지가 보고됐다. PC에서도 같은 HTTPS 원점으로 새로 열어 재현했고, HTML/JS/WASM 200 응답 뒤 앱 준비 완료에 도달하지 않는 상태를 확인했다. HTTP 응답만으로 앱 실행을 검증하면 이 실패를 놓칠 수 있다.

설치된 [Rspack CLI 2.0.3 배포본](https://registry.npmjs.org/@rspack/cli/-/cli-2.0.3.tgz)의 dev 초기화 코드, [core 2.0.3 배포본](https://registry.npmjs.org/@rspack/core/-/core-2.0.3.tgz)의 hot/lazy-compilation-web.js, [Chili3D appBuilder.ts](https://github.com/xiangechen/chili3d/blob/4600206f9b354421f4de288e853efcde926da080/packages/builder/src/appBuilder.ts)의 시작 시 동적 import를 실제 읽고 대조했다. 해당 CLI는 웹 개발 서버의 lazyCompilation 미지정 시 동적 import 지연 컴파일을 켠다. lazy 클라이언트는 비활성 모듈을 켤 때 HMR이 없으면 프로세스 재시작을 기다린다고 명시한다. 따라서 개발 클라이언트/HMR을 끈 구성에는 루트 `lazyCompilation: false`도 명시한다. 실행 중 서버는 설정 파일만 저장해도 시작 설정이 바뀐다고 가정하지 말고, 소유한 서버만 정상 재시작한 뒤 새 HTTPS 페이지에서 확인한다.

또한 모바일에서 AI 설정 패널이 뷰포트를 덮을 수 있다. 공식 Editor.ts·editor.module.css와 AI 매뉴얼의 패널 열기/닫기를 대조해 기존 모바일 분기점 680px 이하에서는 초기 AI 자동 열기를 생략한다. 사용자가 명시적으로 AI 메뉴를 열 수 있는 기존 기능은 유지한다. 문서/형상 데이터는 바꾸지 않고 첫 표시만 조정한다. 393×851 모의 화면에서의 검증과 실제 안드로이드 재확인은 구별한다.

수정 서버를 재시작한 뒤 새 HTTPS 페이지의 앱 준비 완료, 지연 컴파일 프록시 요청 0, 전체 기존 조립 형상 로드와 393×851 모의 화면의 실제 표시를 확인했다. TypeScript 검사가 통과했고 기존 사이드바 회귀 검사 5개도 통과했다. 다만 실제 안드로이드 첫 재확인에서는 Loading이 계속된다는 사용자 응답이 남아 있다. 따라서 실제 기기 해결 완료로 표시하지 않으며, 기존 인앱 브라우저 창을 닫고 Chrome 새 창에서 수정 주소로 다시 여는 단계를 확인 중이다. 브라우저 저장소를 일괄 초기화하지 않고 기존 저장본을 보존한다.

## 자연어 명령을 내리는 두 경로

사용자는 담당 채팅에 원하는 작업을 구체적으로 전달할 수 있다. 이것과 Chili3D 내장 AI는 별도 경로다. 앱 안에서 자연어로 모델을 조작하려면 [공식 AI 매뉴얼 9장](https://github.com/xiangechen/chili3d/blob/4600206f9b354421f4de288e853efcde926da080/docs/manual/09-ai-assistant.md)의 제공자·API 주소·모델·API 키 설정이 필요하다. 9.1–9.6 본문을 실제 읽고 키 저장·전송·모델 도구·문서 저장 범위를 확인했다. 계정 구독 상태만으로 API 연결 성공을 가정하지 않는다. 키 직접 입력과 추가 비용 승인은 별도로 지킨다.

API 설정이 없으면 AI 입력창은 표시되지 않지만 비 AI 메뉴는 사용할 수 있다. 연결 후 오른쪽 AI Assistant의 입력창에 대상·mm 치수·기준 위치·보존 대상·완료 조건을 적고 전송한다. 예를 들어 기존 노드 이름을 지정해 보기/표시 변경을 요청하거나, 기존 참고 메시를 보존하면서 별도 치수 스케치를 요구한다. 일반 메시를 파라메트릭 CAD처럼 수정할 수 있다고 가정하지 않는다. 실패·형상 변경은 화면·프로젝트 트리·수치로 확인하고 저장한다. 원격 모델을 사용하면 명령과 필요한 문서·선택·스크린샷 등이 해당 제공자에게 전송될 수 있다.
