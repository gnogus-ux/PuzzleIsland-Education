# 도구 확인 공통 규칙

2026-11-01 사용자 지시: 제작하려는 작업에 필요한 프로그램과 매뉴얼을 먼저 확인하고, 없거나 적용 근거가 부족하면 요청한다. 이 규칙은 여러 프로젝트에서 공통 사용한다.

## 매뉴얼 사전 확인

- 작업 전에 [공용 교육 목록](../README.md)과 해당 주제의 매뉴얼을 읽는다. 필요한 매뉴얼이 없거나 내용이 부족하거나 버전 차이로 적용 근거가 부족하면 사용자에게 필요한 주제·작업 목적·부족한 내용·추가 학습/작성 필요사항을 요청한다.
- 이미 명시 승인된 강좌 학습·매뉴얼 작성 범위는 중복 질문 없이 수행한다. 매뉴얼이 없다는 이유로 승인받지 않은 새 강좌의 대규모 학습·설치·무근거 제작을 임의 시작하지 않는다. 현재 설치·설정 보류와 앱 조회 금지는 유지한다.

## 프로그램 사전 확인

1. 제작·분석·자동화 도구를 새로 만들거나 설치하기 전에 [사용 프로그램 목록](AVAILABLE_TOOLS.md)을 읽는다. 필요한 기능을 기존 프로그램·검증된 스크립트·승인된 연결로 수행할 수 있는지 먼저 확인한다.
2. 목록의 ‘최근 실행 근거’, ‘설치만 확인’, ‘미완료/보류’를 구별한다. 파일이 있다는 이유만으로 실행·라이선스·모델 다운로드·외부 API 연결까지 완료됐다고 가정하지 않는다.
3. 필요한 프로그램이 없거나 사용할 수 없으면 프로그램명, 작업 용도, 현재 부족한 점, 설치/계정/비용 필요 여부를 정리해 사용자에게 요청한다. 임의 설치·구매·우회·대체 프로그램 제작을 시작하지 않는다.
4. 이미 해당 프로그램 설치·사용을 명시 승인받았으면 같은 승인을 반복 요청하지 않는다. 최신 보류·금지 지시, 사용자 직접 로그인·필수 승인 단계는 유지한다. 현재 프로그램 설치·설정 작업은 재개 지시 전까지 보류다.
5. 금지된 앱을 목록 확인 명목으로 조회·연결·시작·재시작하지 않는다. 다른 담당의 실행 중 작업과 도구 점유를 보존한다.
6. 새 확인이나 설치·장애가 발생하면 날짜·버전·검증 범위·남은 조건을 이 공용 목록에 갱신한다. 같은 장애를 반복 확인하거나 여러 프로젝트에 목록 사본을 만들지 않는다.
7. 공유 PC의 실제 설치와 다른 PC의 환경을 구별한다. 공개 문서에는 인증정보·개인 절대 경로·비공개 제품 자료를 기록하지 않는다. 정확한 경로와 진단 로그는 담당의 비공개 환경 기록에서 확인한다.
8. 공용 자료실의 단일 작성자·정상 커밋/푸시·manifest/링크/원격 해시 검증 규칙을 따른다.
