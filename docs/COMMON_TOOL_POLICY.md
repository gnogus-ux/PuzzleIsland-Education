## 반복 승인 방지와 실제 권한 확인

1. 작업을 배정하기 전에 실제 실행 창의 작업 폴더·프로젝트·산출물 경로·현재 쓰기 허용 범위·승인 모드를 확인한다. 전역 기본 설정, 새 창 기본값, 기존 창의 실제 실행 권한을 서로 같은 것으로 가정하지 않는다.
2. 산출물이 허용 범위 밖이면 사용자가 승인한 프로젝트 경계를 정상 설정·지원 도구로 먼저 맞춘다. 유효한 상위 경로 허용이 있으면 그 범위 안에서 작업한다. 무관한 폴더까지 일괄 허용하거나 다른 경로·도구로 필수 권한 검사를 우회하지 않는다.
3. 기존 창의 권한을 바꾸는 지원 기능이 없거나 사용자가 직접 선택해야 하는 설정이면, 대상 창·권한 메뉴·필요한 프로젝트 범위와 직접 조작의 근거를 구체적으로 알린다. 같은 기본 설정을 다시 쓰거나 진행 중 작업을 재시작하는 것을 해결로 삼지 않는다. 사용자가 허용한 정상 방법만 적용한다.
4. 요청 종류와 범위를 구분한다. 파일 쓰기·앱 제어·네트워크·로그인·유료 실행은 서로 다른 권한이다. ‘항상 승인’의 세션·경로 한정 여부와 현재 유효 범위를 기록하고 같은 유효 권한을 중복 요청하지 않는다. 일반 승인 문구를 필수 사용자 버튼의 자동 누름이나 보안 장치 해제 권한으로 해석하지 않는다.
5. 변경 뒤 실제 실행 권한·대상 경로와 작업 결과를 확인한다. 적용 대기·세션 한정·미검증·추가 사용자 조작을 구분하며, ‘이제 승인창이 전혀 안 나온다’고 검증 없이 보장하지 않는다. 기존 승인·조회 금지·비용·원본 보존을 유지하고 독립적으로 가능한 작업을 병행한다.

7. 공유 PC의 실제 설치와 다른 PC의 환경을 구별한다. 공개 문서에는 인증정보·개인 절대 경로·비공개 제품 자료를 기록하지 않는다. 정확한 경로와 진단 로그는 담당의 비공개 환경 기록에서 확인한다.
8. 공용 자료실의 단일 작성자·정상 커밋/푸시·manifest/링크/원격 해시 검증 규칙을 따른다.
