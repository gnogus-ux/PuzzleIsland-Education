# 공통 작업·인계·검수 규칙

2026-11-01 사용자 요청으로 기존 협업에서 사용한 작업 방식을 여러 프로젝트의 공통 규칙으로 정리했다. 프로젝트별 실제 저장소, 승인 디자인, 특정 후보 버전, 한시적 앱 금지·설치 보류는 각 프로젝트의 최신 지시를 함께 확인한다. 공통화가 기존 금지·승인 범위를 해제하거나 확장하지 않는다.

## 1. 작업 시작·승인·보고

- [프로그램 목록](AVAILABLE_TOOLS.md), [프로그램·매뉴얼 확인 규칙](COMMON_TOOL_POLICY.md), 프로젝트 README/AGENTS와 해당 매뉴얼부터 확인한다. 프로그램 또는 매뉴얼이 없거나 적용 근거가 부족하면 해당 규칙에 따라 사용자에게 요청한다.
- 현재 사용자 지시를 우선하고, 실제 프로젝트 경로·브랜치·변경 상태·승인 범위를 확인한다. 다른 프로젝트의 제품코드·에셋·승인 디자인을 섞지 않는다.
- 이미 승인된 일상 조사·제작·저장·검증·수정은 반복 승인 질문 없이 마무리한다. 중요한 범위 변경·복구하기 어려운 삭제·새 비용·보안/접근 변경 등은 승인된 범위와 도구의 필수 승인 조건을 확인한다. 필요한 확인은 가능한 준비·검증을 마친 구체적 결과를 기준으로 요청한다.
- 중요한 진행·결과·장애·사용자 결정이 필요한 사항을 간단히 보고한다. 총괄·담당 전달은 사용자가 허용한 프로젝트와 대상 범위에서 수행하며, 담당의 실제 인수·진행·검증을 구별한다.
- 실행하지 않은 생성·학습·저장·테스트·업로드를 완료라고 보고하지 않는다. 완료/부분 완료(PARTIAL)/미검증/미실행을 구분하고 실제 근거·남은 문제를 기록한다.

## 2. 승인 자료·원본 보존

- 이미지·모델·게임 아트 작업 전 프로젝트의 제작 규칙과 승인 기록, 접근 가능한 승인 원본을 직접 확인한다. 원본이 없으면 요청한다. 문서 설명만으로 외형을 확정하지 않는다.
- 승인된 자료는 출처·승인 범위·버전과 함께 해당 프로젝트 자료실에 저장한다. 시험 자산·후보·최종 승인 자산을 구별하며 승인되지 않은 후보를 최종 자산으로 취급하지 않는다.
- 사용자의 미저장 작업·로컬 변경·원본을 보존한다. 최신 상태를 기록하지 않고 오래된 파일을 다시 열어 덮어쓰지 않는다. 요청받은 수정 범위와 방법을 따르고 지정하지 않은 부위·동작·재설계로 확대하지 않는다.

## 3. 3D 수정은 가이드 → 인계 → 실제 수정

- 면 정리와 모양·형태·윤곽·비율 변경 모두 먼저 실제 수정 가이드를 만든다. 모호한 설명만 담당에게 넘기지 않는다.
- Blender 등의 별도 Guide 컬렉션에 수정 범위, 보존 경계·랜드마크, 면 흐름·접속 위치를 표시한다. 형태 수정에는 목표 윤곽, 이동 방향·범위, 유지할 기준점을 표시하고 필요한 정면·사선·측면에서 확인한다.
- 가이드 작성만으로 원본 피부/제품 메시를 수정하지 않는다. 원본 보존 가이드 파일과 실제 수정 후보를 구분하고 캡처·대상 오브젝트·좌표/영역·필요한 정점/면 인덱스를 함께 전달한다.
- 담당에게 목표·완료 기준·제외 항목·최신 저장 상태를 인계한다. 시각 입력을 읽지 못하는 담당에게는 구조화한 위치 정보를 보충한다.
- 기본 형태 작업을 움직임·애니메이션·리깅 작업으로 임의 확장하지 않는다. 가이드 절차 자체가 이미 승인된 수정에 새 승인 질문을 추가하는 이유는 아니다.

## 4. 단일 점유·실제 검수

- 같은 Blender 파일·공유 체크아웃·문서를 여러 담당이 동시에 변경하지 않는다. 가이드 담당의 점유를 정상 해제한 후 수정 담당이 정상 점유를 받아 작업한다.
- 다른 담당의 진행 중 호출을 임의로 끊거나 강제 점유 해제·무조건 재시작으로 인계하지 않는다. 마지막 실제 변경·저장·미저장 상태를 확인한다.
- 같은 카메라·조명·표시 조건에서 실제 solid/wire 전후를 비교한다. 형태·실루엣·연결·겹침·법선 등 요청 범위의 품질을 확인한다. 수치 검사·저장 성공만으로 시각적 개선을 통과 처리하지 않는다.
- 새 후보 저장과 필요한 재열기·좁은 검사를 마친다. 수행하지 않은 엔진·변형·베이크·실기 성능 검사는 별도 미검증으로 남긴다. 제작자의 자체 확인과 독립 검수를 구별한다.

## 5. 담당 실패·사용량·비용

- 사전에 정한 시도 횟수/실패 기준을 넘으면 같은 실패를 무한 반복하지 않는다. 가이드·최신 후보·실패 원인·남은 문제를 보존해 승인된 다음 담당에게 인계한다.
- 외부 AI 사용량이 소진되면 해당 앱 조회가 허용된 범위에서 실제 표시된 리필 시간을 확인하고 한국 시간으로 보고한다. 표시나 시간대가 불명확하면 미확인으로 기록한다. 사용자 앱 조회 금지가 있으면 해제 전까지 조회하지 않는다.
- 미완료 중 사용량이 끝나면 전담 Codex가 승인 범위·기존 가이드와 최신 저장 상태를 인수하고, 기존 호출과 점유가 안전하게 끝난 뒤 필요한 수정·저장·검증을 마무리한다. 리필 대기만 하거나 처음부터 재조사하지 않는다. 해결하지 못한 품질은 PARTIAL이다.
- 보유 잔액은 적합한 실제 검사·정리·단순 코드 등 필요한 작업에 사용한다. 소진 목적의 불필요한 호출, 추가 충전·자동 결제·한도 우회는 만들지 않는다.
- 필요한 도구 연결만 사용한다. 불필요한 대규모 도구 조회·반복 테스트를 피하며, 앱·연결의 사용/조회 금지와 정상 권한 절차를 지킨다.

## 6. 교육·분석·매뉴얼

- 사용자가 승인한 강좌·자료의 정확한 목록과 중복을 확인한다. 제목/회차 번호와 실제 목록 순번을 구별하고, 영상·글·코드·시연 자료를 정확히 분류한다.
- 전체 흐름과 주요 제작 구간의 실제 화면 표본, 제공되는 공개 자막을 대조한다. 실제 본 시간·시점·자막 범위와 준비만 한 자료를 분리한다. 표본 분석을 연속 전음성/모든 프레임 학습으로 과장하지 않는다.
- 보조 AI의 부위·시점·UI·문자 오독을 원본으로 교정한다. mock 결과나 의미 분석이 비어 있는 결과를 실제 내용 분석 근거로 쓰지 않는다.
- 원본에서 확인한 사실, 공통 제작 원리, 프로젝트 적용 제안, 미포함·미검증 사항을 구별해 매뉴얼·시간 색인·검수표·자체 도식·증거 기록을 만든다. 구버전 조작/수치/에셋을 현행 프로젝트의 보편 규칙으로 복제하지 않는다.
- 학습 완료와 실제 제품·캐릭터·게임 제작/리깅·엔진 검증 완료를 구별한다. 교육 요청을 실제 씬·게임 수정·앱 실행·설치·유료 구매로 임의 확대하지 않는다.

## 7. 공용 정본·Git·중복 정리

- 재사용 교육 매뉴얼·자체 도식·공개 가능한 검증 기록의 정본은 이 공용 자료실이다. 프로젝트에는 정본 링크를 두고 중복 사본을 다시 만들지 않는다.
- 원본 영상/음성/전문 자막/대량 캡처/외부 전체 코드/유료 에셋/비공개 제품 자료/개인 경로·인증정보는 허가 없이 공개하지 않는다. 링크·제작자·라이선스·실제 학습 범위와 자체 작성 내용을 중심으로 게시한다.
- 공용 자료실은 한 작성자가 한 배치씩 변경한다. 다음 담당은 이전 게시 종료 SHA와 점유 해제를 인수하고 최신 상태를 확인한다. 다른 담당의 미게시 변경을 덮어쓰거나 함께 커밋하지 않는다.
- UTF-8·문서/도식·상대 링크·manifest 바이트/해시를 검사하고 정상 커밋/푸시 후 로컬·원격 SHA와 고정 본문을 검증한다. 기존 무관한 자료·manifest 순서를 보존하며 강제 푸시·이력 재작성·전역 Git 설정 변경은 하지 않는다.
- 중복 삭제는 모든 공유 가능한 교육 내용의 원격 정본 반영과 내용/해시 대조를 마친 뒤 검증한 명시 파일만 수행한다. 원자료·미공개 증거·제품 자산·미게시 사용자 변경을 보존하고 대응 목록·정본 주소·삭제/링크 교체 결과를 기록한다.

## 8. 작업 단계 완료 후 새 창·인수·보관

- 사용자가 승인한 새 창 인계 절차에 따라 한 작업의 완료·검증을 확인한 뒤 다음 작업을 새 대화로 인계한다. 적용 도구의 새 대화 생성 조건도 따른다.
- 인계서에는 목표·승인 범위·최신 규칙·실제 산출물/정본 주소·검증·잔여 문제·마지막 저장·점유·비용·다음 완료 조건을 담는다.
- 완료 확인 → 인계서 저장 → 새 담당 인수 확인 → 기존 호출 안전 종료/파일 저장 확인 → 이전 완료 창 보관 순서로 진행한다. 진행 중 작업이나 인수 확인이 없는 창을 먼저 보관하지 않는다.
- 보관을 삭제로 대체하지 않는다. 기능 부재·실패·인수 미확인은 그대로 보고한다. Codex 대화 보관을 다른 앱의 대화 보관이나 자동 압축 완료로 주장하지 않는다.
