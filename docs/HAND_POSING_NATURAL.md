## 1. 쉬는 손은 '굽힘 순서'가 있다 (자료 내용)

- 쉬는 손의 손가락은 조금씩 굽어 있다. **검지가 가장 덜, 새끼가 가장 많이** 굽는다(Finger Flexion Cascade).
  - 손목을 떨어뜨리면 긴 굽힘근의 수동 장력(tenodesis) 때문에 손가락이 한꺼번에 부드럽게 굽는다.
  - 쉬는 손가락 끝들은 손바닥 아래쪽(주상골 근처)을 가리킨다. JCDR 서론의 설명이다.
- 측정값은 아래와 같다. JCDR 표 13, 우세손, 손을 받친 쉬는 자세, 단위는 °(평균).

| 손가락 | 사무직(마우스·키보드) MCP / PIP / DIP | 힘을 쓰는 직업 MCP / PIP / DIP |
|---|---|---|
| 검지 | 27 / 39 / 14 | 32 / 67 / 24 |
| 중지 | 33 / 41 / 14 | 38 / 71 / 21 |
| 약지 | 29 / 45 / 14 | 33 / 74 / 22 |
| 소지 | 26 / 43 / 16 | 29 / 70 / 26 |

- 읽는 법:
  - 쉬는 손에서 가장 많이 굽는 것은 가운데 마디(PIP)다.
  - 중지는 손등 마디(MCP), 약지는 가운데 마디, 새끼는 끝마디(DIP)가 가장 크다.
  - 하는 일에 따라 같은 '쉬는 손'도 30° 가까이 다르다(힘을 쓰는 사람이 더 쥐어 있음).
  - 손등 마디(MCP)는 검지·소지가 비슷하거나 소지가 오히려 작다. 그래서 "새끼일수록 더 굽는다"는 느낌은 주로 **가운데·끝 마디**와 손가락 길이에서 나온다.

## 2. 넘으면 안 되는 범위 (자료 내용)

PMC 2024 논문의 능동 범위다. 390손 평균이고 손 측정 오차는 약 10°다.

| 관절 | 굽힘 최대(평균) | 젖힘 최대(평균) |
|---|---|---|
| MCP(손등 마디) | 84–87° | 22–26° |
| PIP(가운데 마디) | 92–97° | 13–16° |
| DIP(끝마디) | 82–85°(검지→소지로 증가) | 6–8° |

- 보조 자료(Physiopedia 팔 표, AAOS 값)의 손목·아래팔 범위:
  - 손목: 굽힘 60–80°, 젖힘 60–70°, 노쪽 기울임 20°, 자쪽 기울임 30°.
  - 아래팔: 엎침·뒤침 80–90°.
- 리그에 그대로 쓸 수 있는 한계로 정리하면 아래와 같다.
  - 굽힘: MCP 85°, PIP 95°, DIP 85°.
  - 젖힘: MCP −25°, PIP −15°, DIP −8°.
  - **쉬는 자세는 최대 범위의 절반도 안 된다**(1번 표).
- 키보드를 칠 때는 MCP가 굽어 두드리고, PIP·DIP는 상대적으로 펴지며 충격을 받는다(JCDR 논의, 인용 연구).
  - → 손가락 끝으로 '톡' 치는 동작은 **손등 마디 중심으로** 움직인다.

## 3. 보기 좋게 만드는 디자인 규칙 (자료 내용)

Animator Island 글의 두 가지 규칙이다.
- **손가락을 고르게 두지 않는다.**
  - 모두 같은 간격, 같은 모양(대칭, twinning)으로 붙이지 않는다.
  - 몇 개는 붙고 몇 개는 벌어지게 묶어 리듬을 만든다.
- **한두 손가락은 각도를 다르게 준다.**
  - 흔한 동작(가리키기 등)일수록 한 손가락에 다른 굽힘을 하나 더 넣는다.

## 4. 교차 해석 → 자세를 잡는 순서

1. **세 손가락에 쉬는 순서를 먼저 준다.** 중지 < 약지 < 소지 순서로 조금씩 더 쥔다. 1번 표 수치를 시작점으로 하고 장면에 맞게 키운다.
2. **세 마디를 똑같이 굽히지 않는다.** 가운데 마디(PIP)를 가장 크게, 끝마디는 그 절반쯤으로 한다.
   - 한 컨트롤로 세 마디를 같은 각도로 돌리는 리그(Copy Rotation)는 출발점일 뿐이다. 마디별로 다시 맞춘다.
3. **주인공 손가락(검지 등)은 다르게 준다**(3번 규칙). 다만 그 손가락을 조이면 긴장돼 보인다.
   - 쉬는 순서보다 **덜** 굽히고, 끝마디만 살짝 내린다.
4. **엄지는 따로 본다.**
   - 엄지 끝이 검지 쪽(손가락 끝 방향)을 향하게 가운데 마디(MCP)와 끝마디(IP)를 굽힌다.
   - 뿌리까지 접으면 손바닥 밑으로 말려 들어간다.
5. **손 전체의 기울기(아래팔 엎침·뒤침)를 준다.**
   - 책상에 놓인 손은 손등이 완전히 수평이 아니라 엄지 쪽이 낮은 경우가 많다.
   - 범위 안(80–90°)에서 조금(20–30°)만 굴린다.
6. **범위 표(2번)로 넘친 관절이 없는지 확인한다.**

## 5. 실제 적용 기록 — 책상 위에서 검지로 톡 치는 손 (2026-11-21)

제품 영상(탑뷰 책상, 손가락으로 책상을 쳐 지갑을 튀기는 장면)에서 사용자의 실제 손 사진과 맞추며 고친 순서다. 리그는 손 스캔에 마디별 DEF 뼈와 손가락별 굽힘 컨트롤을 넣은 것이다.

| 회차 | 시도 | 결과·사용자 지적 | 고침 |
|---|---|---|---|
| 1 | 세 손가락 75°씩(세 마디 같은 각도) + 검지 ㄱ자(가운데 마디 88°) | 검지를 끝까지 굽혀도 끝이 책상에 2.5 cm 못 닿음. 엄지가 가장 낮은 지지점이 됨 | 가장 낮은 곳이 어느 뼈 그룹인지 재서 원인을 찾음 |
| 2 | 사용자 사진 2장(위·옆): 세 손가락 말아 넣음, 검지 앞으로 뻗고 끝만 내림 | 세 손가락이 덜 말림, 엄지가 너무 벌어짐 | 세 손가락 마디별로 다시(MCP 55–70 / PIP 95–100 / DIP 55–60°) |
| 3 | 사용자 "검지를 조이면 자연스러워 보이지 않아", "4·5번째를 순차적으로 더 쥐어야" | — | 중지 55/95/55 → 약지 68/100/60 → 소지 80/105/65°, 검지 12/28/12°(조이지 않음) |
| 4 | 사용자 "엄지가 조금 더 펴져야", 이어서 사진 3장(엄지 가운데 마디 굽힘) | 엄지를 펴니 손등 높이로 뜸 | 엄지 뿌리는 펴고 가운데 35°·끝 25° 굽혀 끝이 검지 쪽 아래로 |
| 5 | 사용자 사진: 검지에서 엄지로 가는 손등을 엄지 쪽으로 내림 | — | 손 전체를 긴 축으로 25° 굴림 → 엄지 끝이 책상에 닿는 지지점이 됨 |

배운 점은 아래와 같다.
- **지지점을 먼저 정한다.** 책상 위 손은 '어디가 책상에 닿아 무게를 받는가'가 자세를 정한다.
  - 예: 말아 넣은 손가락 끝, 엄지 끝.
  - 뼈 끝점이 아니라 **변형된 메시의 가장 낮은 정점과 그 정점의 주 뼈 그룹**으로 확인한다.
- **치는 손가락은 닿을 각도를 계산해서 찾는다.** 치는 순간 손가락 끝 정점들이 책상에 닿는 손등 마디 각도를 탐색해 키로 넣는다.
  - 쉬는 각도는 그보다 조금 작게 두고, 들 때는 손등 마디를 젖힌다(2번 범위 안).
- **확인은 세 방향으로 한다.** 위(최종 구도), 옆(책상 높이, 엄지 쪽), 손가락 끝 쪽(사용자 사진 방향)에서 근접 렌더로 본다.
  - 위에서만 보면 말린 손가락이 길어 보이는 문제를 놓친다.
- **사용자의 실제 손 사진이 최종 기준이다.** 표 수치는 출발점이다. 사진과 다르면 사진을 따른다.

## 6. 점검표

- [ ] 중지 < 약지 < 소지 순서로 더 쥐었는가(쉬는 손 순서).
- [ ] 세 마디 각도가 서로 다른가(PIP가 가장 크고 DIP는 작게).
- [ ] 주인공 손가락을 조이지 않았는가.
- [ ] 엄지 끝 방향이 장면에 맞는가(검지 쪽 / 책상 쪽).
- [ ] 손 전체의 굴림·기울기가 사진과 맞는가.
- [ ] 2번 범위 표를 넘은 관절이 없는가.
- [ ] 지지점이 책상에 닿고, 책상을 뚫은 정점이 없는가(가장 낮은 정점 측정).
- [ ] 위·옆·손가락 끝 쪽 세 방향 근접 확인을 했는가.

## 미검증과 한계

- **엄지 범위:** 엄지 관절(CMC·MCP·IP)의 정상 범위 수치를 직접 준 자료를 이번에 읽지 못했다. 엄지 각도는 사용자 사진과 대조한 값만 있다.
- **표본:** 두 논문의 표본은 인도 성인이다. 인구·성별·나이·체질량에 따라 값이 달라진다(PMC 논의). 표는 '흔한 범위'이지 특정 손의 정답이 아니다.
- **애니메이션 자료:** 짧은 글 1편만 읽었다. 손 자세를 체계적으로 가르치는 강좌는 열지 못했다.
- **적용 기록:** 실제 적용 기록은 정지 자세와 치는 동작의 확인 렌더까지다. 완성 영상에서의 움직임, 가중치 문제(주먹 쥘 때 손바닥 주름 등)는 확인하지 않았다.
