# 매끈한 코팅 가죽 · 면광원 반사와 미세 요철 검수

2026-11-03 Codex 작성. 목적은 사진의 매끈한 반광을 재질·광원·미세 요철·노이즈 제거로 나누어 판단하는 것이다. 아래 공식 자료 3개의 해당 절을 직접 읽고 대조했다. [학습 범위](../reports/ExternalLearning/20261103_LEATHER_LOOKDEV_STUDY.json)를 함께 확인한다. 특정 가죽의 측정 물성·사진 조명 복원·제품 외관 합격을 입증한 자료는 아니다.

## 1. 확인한 원자료와 적용 한계

| 원자료 | 직접 읽은 범위 | 확인 내용 |
|---|---|---|
| Blender Foundation, [Principled BSDF / 5.2](https://docs.blender.org/manual/en/5.2/render/shader_nodes/shader/principled.html) | Specular, Coat | 비금속 Specular Tint의 예술적 조정과 코팅층의 흡수 Tint를 구분. Coat의 거칠기·IOR·별도 Normal 역할 확인 |
| Blender Foundation, [Light Objects / 5.2](https://docs.blender.org/manual/en/5.2/render/lights/light_object.html) | Common Settings, Area Light, Power of Lights | 면광원 형상·두 크기·Normalize·방사 출력 의미 확인 |
| Intel, [Open Image Denoise API](https://www.openimagedenoise.org/documentation.html) | RT, Auxiliary feature images, Albedos, Normals, Quality | 색/알베도/법선 보조 입력과 잡음·prefilter·cleanAux의 조건 확인 |

Blender 문서 대상은5.2, OIDN은 확인일의 공식 API 문서다. 설치된 Blender에 포함된 정확한 OIDN 라이브러리 버전·내부 옵션 대응은 이번 문서 학습에서 확인하지 않았다. API 예제를 Blender UI 설정과 일대일로 간주하지 않는다. 해당 페이지의 모든 절·링크·영상·샘플 장면을 학습했다는 뜻도 아니다.

## 2. 비금속 가죽과 코팅층을 구분한다

외관 목표를 사진에서 먼저 기록한다. 색, 결의 실제/추정 크기, 하이라이트 폭과 방향, 반사가 드러나는 부위와 곡면을 나눈다. Base Color에 사진의 조명·반사 패치를 그려 넣지 않는다. 채널 규약은 [표면 맵 매뉴얼](WALLET_SURFACE_MAPS.md)과 [출력 연결](PAINTER_TO_BLENDER.md)을 따른다.

금속성으로 가죽 광택을 만들지 않는다. 비금속 Specular Tint를 흰색에서 바꾸는 것은 공식 문서상 예술적 제어이므로, 따뜻한 사진을 보았다는 이유만으로 가죽의 측정 물성이라고 주장하지 않는다. 먼저 중립 반사와 조명의 위치·색을 확인한다. Coat Tint는 코팅층 내부 흡수 모델이므로 반사 하이라이트를 원하는 색으로 칠하는 입력으로 혼동하지 않는다.

Coat Weight는 두께(mm)가 아니다. 공식 문서는 물리적 재질에서 보통0/1 및 공간 마스크 사용을 설명한다. 중간값을 시각 조정에 썼다면 측정된 코팅 두께·실제 코팅 면적이라고 해석하지 않는다. 매끈한 코팅 아래 거친 표면을 표현할 때는 기본층 Normal과 Coat Normal을 구분하고, 임의 코팅 추가가 참고에 맞는지도 비교한다. 모든 가죽에 특정 Coat 수치를 강제하지 않는다.

## 3. 밝은 막은 거칠기 수치만으로 판단하지 않는다

회색·반사 기준과 고정 카메라에서 광원별 기여를 본다. 실제 월드 위치·방향·Rectangle의 두 크기·출력·Normalize·색·노출을 기록한다. 광원이 표면 앞/뒤 어디에 있는지 확인하며 이름이 Key/Rim이라는 이유만으로 해당 역할을 한다고 간주하지 않는다.

면광원을 줄이면 반사의 폭뿐 아니라 밝기와 그림자 인상도 달라질 수 있다. Normalize가 켜져 있을 때 크기 변화에 총출력이 유지되는 조건을 확인한다. 같은 Watt 값을 유지했다는 사실만으로 표면의 조도·하이라이트 밝기·확산광 분포까지 동일하다고 말하지 않는다. 전기 소비전력과 렌더러의 방사 출력도 다르다.

카메라·광원·평면 거울을 단순화한 반사 폭 근사식은 계획용 추정일 뿐이다. 기울기, 유한 광원 방향, 렌즈, roughness, 곡면을 포함한 합격 공식으로 쓰지 않는다. 실제 반사 패치를 렌더하고 필요하면 광원 위치와 크기를 각각 바꾼 대조군으로 판단한다. 최종 재질 전후는 채택한 동일 조명으로 다시 비교한다.

## 4. 결의 늘어짐과 디노이즈를 구분한다

1. 원본 기하·UV·Displace를 보존한다. 먼저 셰이더의 색 대비·roughness 변화·normal을 하나씩 비교한다. 반복 좌표를 바꾸면 동일 요철에 쓰는 맵들의 대응과 기존 실제 변위의 다른 좌표 크기를 기록한다.
2. 결이 남으면 원시/평가 표면, 변위 마스크·세분화 밀도·텍셀의 물리 크기를 필요한 범위만 확인한다. 실제 변위의 변경은 별도 형상 Guide 절차를 따른다. 샘플 UV 밀도만으로 완전한 이방성 검사를 통과시키지 않는다.
3. 디노이즈 대조는 같은 장면·카메라·해상도·노출·샘플·seed·adaptive 조건에서 실시한다. 가능하면 동일 noisy 결과를 기준으로 비교하고, 재렌더했다면 그 차이를 기록한다. 낮은 샘플의 OFF 이미지가 더 매끈하다는 사실만으로 실제 결이 없거나 OIDN이 결을 생성했다고 확정하지 않는다.
4. OIDN 보조 알베도·법선은 디테일 보존에 유용하지만 잡음과 필터 조건의 영향을 받는다. cleanAux는 실제로 깨끗한 보조 입력에만 해당한다. Blender 내부 prefilter/옵션을 확인하지 않고 외부 API 플래그를 강제로 대응하거나 기본 입력을 일괄 제거하지 않는다.
5. 필요하면 RGB+Albedo+Normal과 RGB+Albedo, OFF를 최종 샘플에서 비교한다. 노멀 입력 제거가 보편적 해결책은 아니다. 예산·기존 검사 제한으로 하지 못한 대조는 미실행으로 기록하고 원인 확정을 유보한다.

## 5. 검수·기록과 중단 기준

전체·정면·사선·확대에서 참고를 직접 대조한다. 픽셀 ROI 비교는 위치·선택 조건·색변환을 기록하고, 미지의 조명으로 촬영된 사진의 sRGB 값을 실제 알베도로 간주하지 않는다. 임의의 RGB 오차 한 개를 보편 합격선으로 만들지 않는다. 질감, 하이라이트, 형태 차이와 별도로 평가한다.

저장 성공·맵 연결·문서 학습과 외관 합격은 구분한다. 같은 조건의 유효한 이미지, 실제 설정, 남은 차이를 남긴다. 형상을 보존한 채로 사진의 곡면 반사를 재현할 수 없으면 차이를 보고하고 재질만 무한 조정하지 않는다. Claude는 기존 매뉴얼을 읽고 제작·검토를 하며, 새 교육·매뉴얼 보강 필요는 Codex에게 알린다.

이 문서는 절차 보강이다. 새 애드온 설치·기본 사용자 장면 변경·리깅/재생·베이크·충돌/전체위상 검사·유료 호출을 승인하지 않는다.
