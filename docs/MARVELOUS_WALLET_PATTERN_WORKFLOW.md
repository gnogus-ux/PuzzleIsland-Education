# Marvelous Designer로 겹 가죽 지갑의 패턴을 설계하는 절차

2026-11-05 Codex 작성·영상 보강. **공식 문서 10개의 필요한 본문**을 읽고, 후속으로 **영상 3편의 시간대별 화면 109개와 공식 영상 2편의 영어 자동 자막 전체**를 대조했다. [문서 열람 범위](../reports/ExternalLearning/20261105_MARVELOUS_WALLET_STUDY.json)와 [영상별 확인 시점·자막·교정 기록](../reports/VideoLearning/20261105_MARVELOUS_WALLET_VIDEO_STUDY.json)을 구분한다. 영상은 표본 화면 검토이며 전 구간 연속 재생·청취나 현재 앱 실기 완료를 뜻하지 않는다. 지갑 강좌는 CLO 화면의 다른 제품이며 그대로 복제할 재단 원본이 아니다.

## 1. 적용 버전과 준비

현재 확인한 실행 프로세스의 제품명은 Marvelous Designer 9 Enterprise, 파일 ProductVersion은 `5, 1, 381, 28577`이다. 파일 버전과 상품 이름을 같은 번호 체계로 해석하지 않는다. 실행 중 프로세스·창 제목·파일 메타데이터 확인까지 수행했으며 실제 작업 화면의 메뉴·패턴 편집·저장·시뮬레이션은 이번 학습에서 실행하지 않았다.

공식 웹 문서는 현재 갱신본으로, 2025~2026 갱신 사항과 구버전 기능 설명이 섞여 있다. 문서의 ver2.x/4.x/5.1.0 표시는 기능의 과거 도입 근거로 참고하되 MD9의 모든 기능 호환을 보증하지 않는다. 특히 **2026.0 Turned 봉제선 용접과 2026.1 충돌 두께 방향 개선은 MD9 절차에서 제외**한다. 해당 기능이 필요한 단계는 현지 UI에서 확인하기 전 실행하지 않는다.

1. 원본 제품 파일·열린 문서·사용자 변경을 보존한다. 새 패턴 후보는 별도 프로젝트로 저장한다.
2. [지갑 모델링](WALLET_MODELING.md), [겹 구조와 외피 여유](WALLET_LAYERED_SHELL_VOLUME.md)와 대상의 현재 참고 사진을 읽는다. 기존 매뉴얼의 예시 치수를 실측값으로 복제하지 않는다.
3. 앞·뒤·내부·측면 사진별로 시점과 자세를 분류한다. 펼친 측면의 중앙이 올라간 사진과 내려간 사진을 같은 포즈로 맞추지 않는다.
4. 펼침 폭·높이, 층별 두께, 모서리, 입구, 접힘 범위를 기록한다. 모델 입력값·사진 비율 근사·실측을 분리한다. 한 장의 원근 사진에서 물성이나 숨은 재단을 정확히 복원했다고 하지 않는다.
5. 실제 형상 제작으로 넘어갈 때는 [공통 가이드·단일 점유·전후 검수](COMMON_WORK_RULES.md)의 순서를 적용한다. 계획 도식과 실제 제품 수정은 구별한다.

## 2. 재단 계획을 먼저 확정한다

| 판의 역할 | 패턴 계획 | 개방·연결의 구분 |
|---|---|---|
| 연속 외피 | 펼친 외곽과 중앙 접힘을 포함하는 몸판 | 중앙을 임의 절단하지 않는다. 내측과 외피의 자연 길이를 무조건 같게 만들지 않는다. |
| 외부 포켓 | 몸판과 다른 별도 판 | 꺾인 입구를 개방하고 지정 외곽만 연결한다. 앞뒤 사진의 좌우 반전을 확인한다. |
| 지지 내피 | 포켓군과 외피 사이의 지지층 | 연속형/좌우 분리형/중앙 연결 조각 여부를 대상별로 확인한다. |
| 왼쪽 겹 포켓 | 서로 겹치는 각 판을 분리 | 기울어진 입구를 닫지 않는다. 가려진 재단 경계는 추정으로 표시한다. |
| 카드 슬롯판 | 한 판의 절개인지 여러 판의 겹침인지 사진으로 구분 | 내부선을 그리는 것만으로 입구가 열리지 않는다. 뒤쪽 수납 구조는 별도 확인한다. |
| V 입구 포켓 | 상단 V 윤곽을 가진 별도 판 | 입구를 제외한 연결 구간을 대응시킨다. |
| 숨은 안감·보강재 | 확인된 것만 추가 | 수량·깊이·재질을 임의 확정하지 않는다. 실·엣지코트와 재단 가죽을 구분한다. |

부품별 ID, 수량, 완성 외곽, 재단 외곽, 접어 넣는 여유, 봉제 위치와 연결 상대를 표로 남긴다. 일반 직물의 바깥 시접과 가죽 가장자리에서 안쪽으로 들어온 봉제선을 혼동하지 않는다. 사진에서 칼선·접힘선·봉제선을 구분할 수 없으면 그 값을 아직 확정하지 않는다.

## 3. 2D 패턴과 내부선을 만든다

[Polygon](https://support.marvelousdesigner.com/hc/en-us/articles/47358178952345-Polygon)은 `2D Pattern → Create → Polygon`에서 외곽을 만들며, 생성 중 우클릭 창에서 다음 구간 길이를 지정할 수 있다. 시작점으로 돌아오면 닫힌 패턴이 된다. 곡선점 생성과 대칭 옵션이 문서에 있지만, 대상이 비대칭이면 편의를 위해 전체를 대칭 복제하지 않는다.

1. 먼저 몸판 외곽과 기준 접힘 영역을 만든다. 사진 비례를 좌표로 옮긴 값은 잠정값으로 기록한다.
2. 포켓 각 판을 독립 패턴으로 만든다. 이름에 판 ID와 앞/뒤 역할을 넣고 현재 참고와 나란히 대조한다.
3. [Internal Polygon/Line](https://support.marvelousdesigner.com/hc/en-us/articles/47358276422297-Internal-Polygon-Line)으로 봉제 기준선·접힘 후보·입구 위치를 구분해 표시한다. 문서의 Position은 외곽과 내부선 사이 거리를 지정하는 기능이다. 내부 다각형은 시작점을 다시 누르고, 열린 내부선은 마지막 점을 더블클릭해 끝낸다.
4. 내부선은 그 자체로 절개·구멍·입구가 아니다. 카드 슬롯을 선만 그린 상태로 완료 처리하지 않는다.
5. [Convert to Hole/Internal Shape](https://support.marvelousdesigner.com/hc/en-us/articles/47358440603161-Convert-to-Hole-Internal-Shape)는 내부 형상을 구멍으로 바꾸거나 다시 채우는 기능이다. 한 장의 가죽에 유한 폭의 닫힌 슬롯을 만들 때 검토할 수 있다. 열린 단일 내부선이 곧바로 폭 없는 칼집이 된다는 설명은 이 자료에서 확인되지 않았다. 칼집 방식은 별도 기능 확인이 필요하다.
6. 카드 입구 끝단의 절개와 봉제용 바늘구멍을 구분한다. 바늘구멍을 없애라는 디자인 범위에서는 장식 구멍을 새로 만들지 않는다.

## 4. 연결 표를 만든 뒤 봉제한다

[Segment Sewing (2D)](https://support.marvelousdesigner.com/hc/en-us/articles/47358199517209-Segment-Sewing-2D)는 패턴 구간 또는 내부 형상/선의 구간끼리 봉제 관계를 만든다. `Sewing → Segment Sewing`에서 첫 구간을 선택하고 상대 구간의 방향 표시를 확인한 뒤 두 번째 구간을 선택한다.

| 구간 ID | 첫 판·방향 | 상대 판·방향 | 길이 차이 | 연결 여부 |
|---|---|---|---|---|
| 외곽 상단 | 대상별 기록 | 대상별 기록 | 실제 두 구간에서 확인 | 연결 후보 |
| 외곽 하단/측면 | 대상별 기록 | 대상별 기록 | 실제 두 구간에서 확인 | 연결 후보 |
| 포켓 입구 | 대상별 기록 | 없음 | 해당 없음 | 개방 |
| 중앙 자유 굽힘 | 대상별 기록 | 대상별 설계 | 대상별 확인 | 임의 봉합 금지 |

방향 표시가 교차하면 3D 봉제선도 교차하고 판이 뒤집혀 연결될 수 있다. 시뮬레이션 전에 표면 방향·배치·대응 구간을 확인한다. 문서는 길이 차이의 파란 표시와 1인치를 넘을 때 빨간 경고를 설명하지만, **그 경고 기준은 작은 지갑의 허용 오차가 아니다**. 작은 제품의 봉제 길이 차이는 제품 스케일에서 별도로 판단한다.

외피 여유를 모두 지우도록 길이를 강제 일치시키거나, 수치 차이를 숨기려고 입구까지 봉제하지 않는다. 길이 차이가 의도된 경우 양쪽 경로 길이와 배분 위치를 기록한다. 여러 겹의 동일 외곽도 모든 층을 서로 무차별 연결하지 않고 실제 연결 상대를 명시한다. 봉제 구속은 실 섬유 형상·꼬임·바늘구멍이 자동 완성되었다는 뜻이 아니다.

## 5. 가죽 물성은 굽힘·늘어남을 나누어 조절한다

[Bending-Weft/Warp](https://support.marvelousdesigner.com/hc/en-us/articles/47358432358809-FABRIC-PHYSICAL-PROPERTIES-Adjust-Bending-Weft-Warp)는 굽힘 저항이다. 값이 커지면 더 뻣뻣해지며 공식 문서도 가죽을 그 예로 든다. [Stretch-Weft/Warp, Shear](https://support.marvelousdesigner.com/hc/en-us/articles/47358420149017-FABRIC-PHYSICAL-PROPERTIES-Adjust-Stretch-Weft-Warp-Shear)는 패턴의 가로·세로·대각 변형 저항과 관련된다. 굽힘을 올린다고 면적 늘어남까지 자동으로 해결되지는 않는다.

[Physical Property Detail Setting](https://support.marvelousdesigner.com/hc/en-us/articles/47358427696025-FABRIC-PHYSICAL-PROPERTIES-Physical-Property-Detail-Setting)은 여러 물성이 상호 작용하고 슬라이더 단계와 상수 입력이 다름을 설명한다. 슬라이더의 수치를 실제 가죽의 측정 단위와 같은 것으로 해석하지 않는다.

- 외피·포켓·지지 내피에 서로 다른 재질 역할을 부여하고 결과를 기록한다. 가죽 재질 이름 하나만으로 실물 거동 일치를 주장하지 않는다.
- 한 번에 여러 저항값과 패턴 길이를 함께 바꾸지 않는다. 외곽 길이·층 배치·봉제 방향을 먼저 확인하고, 다음에 변형 원인별로 조절한다.
- 접힘이 지나치게 날카로우면 중앙의 폭과 면 분포, 판 배치와 저항을 함께 본다. 단일 선의 접힘 각도만으로 완성 측면을 보장하지 않는다.
- 이 학습에는 실물 굽힘/인장 시험이 없다. 보편적인 가죽 정답 수치나 대상별 확정 물성값을 제공하지 않는다.

## 6. 충돌 두께와 표시 두께를 분리한다

[Collision Thickness](https://support.marvelousdesigner.com/hc/en-us/articles/47358430412441-FABRIC-PHYSICAL-PROPERTIES-Adjust-Collision-Thickness)는 보이지 않는 충돌 간격이며 [Rendering Thickness](https://support.marvelousdesigner.com/hc/en-us/articles/47358450148761-FABRIC-PHYSICAL-PROPERTIES-Adjust-Rendering-Thickness)는 보이는 두께다. 표시 두께만 줄여도 겹 사이의 시뮬레이션 간격이 같은 만큼 줄어드는 것은 아니다.

공식 현행 충돌 문서의 기본 예는 면 양쪽 각 1.5mm, 합계 3mm다. 이는 얇은 가죽 지갑에 그대로 사용할 권장값이 아니며 MD9의 현재 설정을 실제 확인한 값도 아니다. 겹이 붕 떠 보이면 가죽 형상을 눌러 없애기 전에 판별 충돌 설정과 기준 물체의 간격을 확인한다. 실제 충돌 안정성과 겹 관통도 함께 평가해야 하므로 무조건 0으로 만들지 않는다.

Rendering 문서는 Fabric 단위 Thickness와 Pattern 단위 Add'l Thickness-Rendering을 나눈다. 이 항목들을 임의 합산해 실물 두께로 보고하지 말고 내보낸 메시의 실제 단면을 측정한다. 충돌 문서 Operation의 입력 설명에는 rendering이라는 표현이 남아 있으나, 해당 문서의 Objective·Location은 Collision이다. Rendering 문서와 교차 대조하여 두 설정을 같은 것으로 읽지 않는다.

**2026.1에서 충돌 방향이 표시 두께 방향과 맞도록 개선되었다는 갱신 설명은 MD9에 소급 적용하지 않는다.** 이번 학습은 해당 버전 차이를 확인한 것이며 구버전 실기 해결을 완료한 것이 아니다.

## 7. 측면을 먼저 비교하는 적용 순서

1. 최초에는 중립 재질과 단순 판으로 외곽·층·입구를 확인한다. 표면 결이나 실을 형태 판단의 대체로 쓰지 않는다.
2. 펼침 기준을 저장한 뒤 지정 측면 사진의 자세를 별도 후보에 맞춘다. 최신 사진과 다른 접힘 방향을 섞지 않는다.
3. 끝단 높이, 중앙 정점/최저점, 척추 폭, 곡률 전환, 판별 두께와 빈 공간을 비교한다. 카메라 높이·투영·축척 차이도 형상 차이와 구분한다.
4. 외피의 자연 길이와 지지 내피의 길이 차이를 확인한다. 겉면 볼륨을 얻기 위해 모든 판의 두께를 일괄 늘리지 않는다.
5. 열린 입구와 닫힌 U형 접힘은 별도 상태로 본다. 개별 정지 자세의 일치는 전체 접힘 동작·충돌 성공이 아니다.
6. 실제 시뮬레이션을 수행하는 단계에서는 별도 후보에 한 포켓군부터 확인하고 늘린다. 발산·뒤집힘·관통이 있으면 마지막 안정 상태로 돌아가 방향·배치·간격부터 수정한다. 기존 원본과 열린 작업을 덮어쓰지 않는다.

## 8. Blender 전달과 검수

[OBJ Import/Export](https://support.marvelousdesigner.com/hc/en-us/articles/47358223288601-3D-File-OBJ-Import-Export)의 객체 분리·용접·두께·축척/축 변환을 서로 다른 선택으로 관리한다.

- 편집용 기준 전달은 판 ID를 보존하는 Multiple Objects/Unweld/Thin 후보를 우선 검토한다. 이것은 대상별 적용안이며 정답 프리셋이 아니다.
- Thick 후보가 필요하면 별도로 출력해 실제 단면을 측정한다. Blender에서 다시 두께를 더해 이중 두께를 만들지 않는다.
- Weld는 봉제 경계 정점 결합이다. 실제로 분리되어 있어야 할 가죽 겹·입구를 하나로 만들지 않았는지 본다. Thin/Thick이나 Single/Multiple과 같은 의미로 취급하지 않는다.
- 알려진 기준 길이로 Blender에서 축척을 대조하고 법선·앞뒤·UV·객체 이름·겹 순서를 확인한다. OBJ를 내보냈다는 사실만으로 기존 리그·재질·형태 키 보존을 주장하지 않는다.
- 기존 렌더용 UV를 OBJ의 UV 추적으로 불러오는 것이 실제 재단 패턴 복원을 보장하지 않는다. 재배치·늘어남·중복 UV가 있다면 원본 재단과 다를 수 있다.
- 기준 물체를 가져와 충돌시킬 때 문서는 Avatar와 Trim을 구분한다. Trim은 해당 문서에서 충돌하지 않는다고 설명하므로 충돌용 물체로 무심코 선택하지 않는다. 기존 Avatar 교체 가능성도 원본 보존 절차에서 확인한다.
- 문서의 2026.0 전용 용접 기능은 MD9 사용 계획에서 제외한다. 실제 출력·재수입은 아직 미실행이다.

## 9. 통과 기준과 남은 확인

패턴 목록과 실제 판 수가 대응하고, 입구가 열려 있고, 봉제 방향이 일치하며, 사진과 같은 측면에서 층 두께·중앙 윤곽·양끝 높이가 맞아야 다음 단계로 간다. 카드 슬롯 뒤쪽의 미확정 구조는 실제 자료 또는 명시한 설계 가정으로 남긴다. 사용하지 않은 기능·출력·시뮬레이션을 검증 완료로 기록하지 않는다.

이번 완료 범위는 공식 문서 10개 본문 학습, 아래 영상 표본·자막 교차 검토와 매뉴얼 보강이다. 현재 환경의 실제 MD9 패턴 작성/내부 절개/봉제/충돌/저장·재열기, Blender 전달, 가죽 실측 및 제조 가능성은 **NOT_RUN**이다. 3D 제품 작업을 시작할 때 해당 단계의 메뉴·기능을 제한 확인하고 버전 차이를 기록해야 한다.

## 10. 영상에서 확인해 보강한 제작 순서

### 10.1 지갑을 판으로 나누고 연결하는 화면

[Academy Center — leather wallet Tutorial](https://www.youtube.com/watch?v=0QgKjLSlJus)은 53:54 길이이며 CLO `6.0.328` 화면으로 진행한다. 00:00~53:00의 1분 간격 화면과 추가 11시점을 검토했다. 제공 자막은 확인되지 않아 음성 설명·숨은 의도를 추정하지 않았다.

02:20~03:05의 선택 화면에서 외곽·내부선과 별도 판, 07:40~08:40에서 추가 패턴의 배치·봉제 관계, 16:00에서 연결 설정과 겹친 판을 확인했다. 41:20~42:40에는 서로 다른 배치/접힘 상태의 후보가 보인다. 이 구간명은 관찰한 시점들을 묶은 설명이며 그 사이 모든 프레임을 봤다는 뜻이 아니다.

적용할 원리는 **2D 판과 3D 층을 대응시키고, 봉제 상대를 확인한 뒤 배치·접힘을 비교하는 순서**다. 강좌의 직사각 포켓·로고·치수·후반 렌더는 대상 제품의 사양이 아니다. 화면에 cm 길이 표시가 있으므로 숫자만 mm 입력으로 복사하지 않는다. 이 영상은 대상의 교차 입구·세 카드 절개·실물 두께를 검증하지 않는다.

### 10.2 입구를 남기는 구간 연결과 방향 복구

[Marvelous Designer — Introduction: Sewing](https://www.youtube.com/watch?v=bZR8j70mA0Q)은 MD9.5 소개 강좌다. 04:44 중 23개 시점과 제공 영어 자동 자막 전체를 확인했다. 01:00~01:15의 시작 방향 표시, 01:30~01:50의 구간 일부를 잡는 Free Sewing, 02:35~02:45의 방향 수정, 03:00~03:45의 여러 구간 대응 화면을 대조했다.

지갑 입구까지 한꺼번에 연결하지 않도록 **판별로 개방 구간을 표시하고, 필요한 일부 경계를 별도로 지정**하는 절차를 추가한다. 잘못 교차한 봉제는 먼저 대응 시작점과 방향을 고친다. Free Sewing의 같은 길이 안내는 기준이지 의도한 여유를 없애는 강제가 아니다. 여러 구간 대응도 실제 연결 표가 정해진 부분에만 쓴다. MD9.5의 도구 묶음 UI를 MD9의 같은 아이콘 위치로 단정하지 않는다. 자동 자막의 `one to end`/`M to end`는 문맥과 시연상 1:N/M:N 연결로 읽는다.

### 10.3 물성·메시 밀도·겉실을 분리한다

[Marvelous Designer — 2025.1 Quickstart #6](https://www.youtube.com/watch?v=aekWcvgBLPQ)은 08:22 중 21개 시점과 영어 자동 자막 전체를 확인했다. 00:30~02:00에서 재질 배정, 02:35·03:00·03:15·03:30에서 메시 간격과 wire 표시, 04:10~06:00에서 겉실 조정 화면을 대조했다.

물성 프리셋 변경과 표면 맵 변경을 다른 조절로 기록한다. 강좌의 **5mm 메시 간격은 사람 크기 의류 예시**이므로 작은 지갑의 고정값으로 쓰지 않는다. 형태 작업과 마감의 메시 밀도를 나누고 입구·접힘 해상도를 실제 크기에서 판단한다.

봉제 구속과 보이는 겉실은 별도 단계로 관리한다. 겉실은 길이·폭·간격·굵기·경계로부터 거리와 출력 방식이 구분된다. 05:00/05:05 화면을 대조하면 자동 자막의 `text`는 굵기 단위 **Tex**를 가리키며, 뒤에 mm 단위로 바꾼다. mm 사진 추정치와 Tex를 같은 숫자로 넣지 않는다. 2025.1의 라이브러리·출력 UI·겉실 기능은 MD9에서 확인 전 확정 조작으로 쓰지 않는다. 이 강좌는 대상 가죽의 굽힘 상수나 실 섬유 꼬임을 측정한 자료가 아니다.

### 10.4 다음 지갑 후보에 적용할 확인 항목

1. 최신 승인 재단 계획의 아래층과 위층을 독립 판으로 유지하고, 가려진 경계도 전체 패턴에 포함한다. 투영선 교차를 새 절단·봉제점으로 만들지 않는다.
2. 판 ID별로 **연결 상대·시작 방향·개방 구간**을 정한 다음 봉제한다. 실을 놓는 단계와 구속을 만드는 단계를 구분한다.
3. 펼침·지정 측면·닫힘 후보를 구분해 층과 여유를 비교한다. 강좌의 접힘 상태나 cm 치수를 대상의 목표값으로 대신하지 않는다.
4. 메시 간격·물성·표시 두께·충돌 간격·겉실 단위를 별개로 기록한다. 값 하나를 바꾸어 여러 문제를 동시에 해결했다고 판정하지 않는다.

위 목록은 문서와 영상에서 도출한 적용안이다. 최신 승인 재단·사용자 보충을 우선하며 실제 MD9 조작·원본 보존·가이드·검수 절차를 생략하지 않는다.

## 11. MD9 패턴 이름·곡선의 제한 실기 근거

2026-11-05 별도 쿠폰에서 실행한 결과다. 이번에 직접 검증한 범위는 **실제 패턴 Name 입력, 일반 곡선 생성, 별도 프로젝트 저장·재열기 유지**다. 정확한 이차 Bézier 제어점과 2D 절대 배치는 미검증이다. 앞 절의 문서·영상 학습 당시 미실행 기록과 구별한다. 실기 보고와 검증 기록을 총괄이 직접 읽고 식별 해시를 대조했으며 원본 화면·비공개 제품 파일은 게시하지 않는다.

### 11.1 먼저 읽은 공식 문서와 버전 경계

학습자는 서로 다른 공식 문서 5개 본문을 실제 읽고 매뉴얼 초안을 작성한 뒤 실기를 수행했다. 삽입 영상 재생·전 프레임·자막 학습은 이번 5개 문서 학습에 포함하지 않았다.

### 11.2 실제 Name 입력·유지 확인

1. 현재 사용자 문서를 별도 보존하고 독립 쿠폰 두 장을 수치 입력으로 만든다. 시험 치수는 40×30mm 및 20×20mm였다.
2. Transform Pattern으로 판을 선택해 **Property Editor 최상단 Name**의 실제 값을 편집한다. 시험 최종 이름은 RECT40과 CURVE20이었다. 파일명·주석·보고서 ID를 내부 Name으로 대신하지 않는다.
3. 패널이 가려지면 현재 허용 창의 배치·속성 영역을 먼저 확인한다. 이번에는 화면 밖으로 커진 창을 복원하고 속성 구분선을 넓혀 해결했다. 다른 앱 조회나 전역 디스플레이·기본 레이아웃 초기화는 하지 않았다.
4. 별도 ZPRJ 저장 후 같은 파일을 Open/Garment로 재열어 두 Name, 두 판 대응과 기준 변 길이가 유지되는지 각각 확인한다. 실제 시험에서 이름과 기준 치수의 유지가 확인됐다. GUI 치수 표시는 0.1mm 단위이며 독립 메시 계측과 구별한다.

실제 제품에 적용할 때는 현재 패턴과 승인된 부품표의 대응을 먼저 확인하고 새 사본에서 이름만 변경한다. 동일 치수 판 둘을 이름만 보고 앞뒤·좌우 조립 위치로 추정하지 않는다.

### 11.3 곡선 생성과 정확 Q를 구별한다

20×20mm 쿠폰의 윗변에 Edit Curvature를 적용하고 Edit Curve Point에서 핸들을 확인했다. 저장·재열기 후 곡선 유지와 화면 길이 21.8mm 표시를 확인했다. 이 값은 0.1mm 반올림 표시이며 정확한 Q 계측 결과가 아니다. 관찰한 핸들 우클릭 메뉴에는 Delete Point/Convert to Curve Point가 있었고 수치 핸들 좌표 필드는 확인하지 못했다.

이차 Bézier `B(t)=(1−t)²P0+2(1−t)tC+t²P2`의 동등한 삼차 제어점은 `C1=P0+2/3(C−P0)`, `C2=P2+2/3(C−P2)`다. 이는 수학적 등가식이며 MD9 UI 입력 성공의 증거가 아니다. Q2mm를 R2mm 원호로 바꾸거나 곡선 위 보간점을 제어점 C로 취급하지 않는다. 길이 하나가 같다는 이유만으로 곡선 전체 일치로 판정하지 않는다.

### 11.4 수치 배치·자동화의 남은 제한

현지 패턴 속성을 아래 항목까지 읽었으나 2D 절대 X/Y 필드를 찾지 못했다. Arrangement의 Point Name을 좌표 필드로 해석하지 않았다. 공식 문서의 수치 이동 창은 **드래그 중** 우클릭/F1 조건인데, 사용한 자동화 drag는 한 호출 안에 시작·종료해 중간 입력을 삽입할 수 없었다. 따라서 해당 경로의 수치 이동은 미검증이며 MD9 기능 자체가 없다고 단정하지 않는다. 임의 입력 브리지·비공식 파일 편집으로 이 제한을 우회하지 않는다.

판정은 `Name 저장/재열기 PASS`, `일반 곡선 생성/유지 PASS`, `정확 Q UNVERIFIED`, `2D 수치 배치 UNVERIFIED`로 나눈다. 시험 성공을 제품 전체 형상·봉제·가죽 물성·수납 검증으로 확대하지 않는다.

## 12. UV를 가진 OBJ를 편집 가능한 패턴으로 가져오는 후보 경로

2026-11-06 공식 본문3개를 직접 읽고 정리한 **적용 전 학습**이다. MD9에서 실제 가져오기·패턴 생성·곡선 보존·저장/재열기를 검증한 결과가 아니다. 수치 Bézier 입력이 미확보일 때 기존 도구로 만든 기준 형상을 가져올 수 있는지 별도 쿠폰으로 확인하는 경로이며 DXF 지원을 가정하지 않는다.

[3D File (OBJ) Import/Export](https://support.marvelousdesigner.com/hc/en-us/articles/47358223288601-3D-File-OBJ-Import-Export)의 Objective, OBJ Import Detail Settings, Load as Garment 본문을 읽었다. 공식 문서는 `File → Import → OBJ`의 **Load as Garment / Trace 2D Patterns from UV Map**으로 UV 정보를 기반으로 패턴을 생성한다고 설명하며 ver4.2.0 도입 표기를 둔다. 별도 `Import (Add) → OBJ to Garment` 경로도 설명한다. 현행 갱신본의 도입 표기만으로 MD9 현지 옵션과 결과를 보증하지 않는다. Load as Avatar는 원래 아바타 교체 가능성이 있고 Trim은 의상과 충돌하지 않으므로 패턴 생성의 대체 선택으로 쓰지 않는다.

함께 읽은 [Polygon](https://support.marvelousdesigner.com/hc/en-us/articles/47358178952345-Polygon)의 Objective/Location/Operation은 2D Window에서 닫힌 패턴 생성과 길이 입력·Free Curve Point를 구별하는 근거다. [Edit Curve Point](https://support.marvelousdesigner.com/hc/en-us/articles/47358435895065-Edit-Curve-Point)의 Add/Move/Note는 가져온 외곽의 곡선점 편집 및 기존 AI Bézier에 Free Curve Point를 더하면 곡선이 바뀌는 위험의 근거다. 후자의2024 전용 선택 동작은 MD9에 소급하지 않는다. 이번3문서 학습은 영상 학습이나 native 실기를 포함하지 않는다.

제한 시험은 다음 순서로 한다.

1. 실제 Guide/좌표 정본의 단위·평면·방향을 기록하고 원제품과 다른 작은 Thin OBJ 쿠폰을 만든다. 객체와 UV 섬을 일대일 대응하고 찢어진 UV·의도하지 않은 내부 섬·UV 겹침을 배제한다. OBJ와 UV의 축척 관계를 명시한다.
2. 현재 사용자 문서를 먼저 보존한 뒤 새 시험 문서에서 실제 MD9 OBJ 가져오기 대화상자를 확인한다. Garment와 Trace 옵션이 없으면 다른 종류로 대신 가져와 성공으로 쓰지 않는다. 단위/축/기존문서 대체·추가를 구별한다.
3. 패턴 수·홀 수·경계·앞뒤·폭/높이와 기준 위치를 실제 2D/3D에서 대조한다. 3D Mesh로만 보이는 상태를 편집 가능한 패턴 생성으로 보고하지 않는다. 불필요한 새 봉제나 분할이 생겼는지도 확인한다.
4. 별도 ZPRJ 저장/재열기 후 실제 패턴 편집 접근을 확인하고, 기존에 검증된 Thin/mm OBJ 출력으로 경계를 재대조한다. 시뮬레이션·물성 검증은 별도 범위다.
5. UV 추적은 원래 해석적 곡선의 차수·제어점 보존을 보장하지 않는다. 원래 Q를 표본화한 입력은 **유한 분할 메시 후보**이며 chord 오차·반올림·자동 단순화·재메시 오차를 분리한다. 입력/재출력 경계의 측정 결과와 미검증 범위를 기록하고 새 허용오차를 임의 승인하지 않는다. 개수나 총길이만 맞아도 정확 Q로 통과시키지 않는다.

성공하면 그 실제 현지 근거를 추가한 뒤 본 패턴 인수에 사용한다. 실패하면 마지막 저장본과 특정 미지원 단계만 남기고 원제품을 보존한다. 비공식 native 파일 편집·새 브리지·추가 설치·다른 버전 구매·인증 변경으로 제한을 우회하지 않는다.
