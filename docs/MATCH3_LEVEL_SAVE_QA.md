# 매치3 · 레벨, 저장과 검증

[전체 흐름](MATCH3_WORKFLOW.md) · [해결 루프](MATCH3_RESOLUTION_SPECIALS.md). 강좌의 구현 관찰과 아래 보완 제안을 구분한다. 이 작업은 문서 작성이며 게임/세이브 파일을 변경하지 않았다.

## 점수와 목표를 다른 값으로 둔다

점수는 규칙에 따라 계산한 수치다. 목표는 특정 종류 수집·고정 장애물 제거·총 제거 등 클리어 조건이다. 수집 목표를 UI 아이콘의 색이나 태그 문자열만 보고 추정하지 않는다. 안정된 ID로 정의를 연결하고 실제 적용 이벤트에서 진행을 누적한다.

고유 제거와 타격은 다르다. 특수 효과가 빈칸을 지나가거나 이미 제거 예정인 조각을 다시 타격해도 목표를 중복 증가시키지 않는다. 장애물 HP 감소와 파괴 완료도 서로 다른 이벤트다. 목표 진행 수는 원본 정의를 바꾸지 않는 런타임 값으로 보관한다.

Taft는 `BlankGoal` 배열과 HUD 목록을 연결하고 나중에 ScriptableObject Level/World를 도입한다. 재플레이에 수집 수가 남아 곧바로 승리하는 현상을 P45에서 발견해 0으로 초기화한다. 더 안전한 구조는 불변 레벨 정의에서 새 세션 진행 객체를 만드는 것이다. Editor에서 원본 SO를 Play 중 수정해도 런타임 저장 시스템이 생기는 것은 아니다.

## 턴·종료·일시정지

| 사건 | 정해야 할 계약 |
|---|---|
| 무효 교환 | 이동 수·난수·목표 불변, 복귀 연출 동안 새 입력 차단 |
| 수락 교환 | 한 번만 수 감소, 연쇄 전체를 같은 턴으로 처리 |
| 마지막 수에 목표 달성 | 안정화 후 승리 우선 또는 다른 명시 정책 |
| 시간 제한 만료 | 해결 중인 턴의 목표/정산을 언제 확정하는지 |
| pause | 입력만 막는지, 시계·애니·해결도 정지하는지 |
| 종료 뒤 늦은 callback | move 상태 복구·점수/보상 재실행 거부 |
| 화면 완료 | 마지막 낙하·집계 표시가 끝난 뒤 결과/다음 명령 |

Taft의 `counter--`와 `<0`는 0에서 한 수 더 허용하는 문제가 있어 `<=0`와 clamp로 정정한다. 시간 모드도 소개 패널이 떠 있을 때 감소하는 문제가 뒤 편에서 보완된다. 1초가 넘을 때 매번 누적값을 0으로 버리면 긴 프레임의 초과분을 잃는다. 시계 기준과 pause 경계를 명시하고 실제 경과량을 계산한다.

PauseManager가 매 Update에 보드 상태를 pause/move로 덮는 구조는 종료·리필 상태와 충돌할 수 있다. 단순 bool 하나를 모든 상태로 재사용하지 않는다. 세션 상태와 해결 진행, 일시정지 정책을 구별한다.

## 레벨 정의와 선택 UI

레벨은 안정된 ID, 실제 크기/마스크, 종류, 목표, 이동/시간 제한, 시드/생성 프로필을 가진다. HUD나 버튼 수가 실제 레벨 수를 만들어 주지 않는다. Taft 마지막 3페이지·27버튼은 실제 27개 레벨 완성을 뜻하지 않는다.

표시 번호 1과 배열 인덱스 0을 경계에서 한 번 변환한다. 음수·상단 초과를 모두 검사하고 마지막 레벨 다음 해금을 무조건 `level+1` 배열에 쓰지 않는다. 저장된 진행도가 콘텐츠 수보다 크면 조용히 다른 판을 열지 말고 호환 정책을 따른다.

페이지 크기가 9라면 유효한 0기반 인덱스의 페이지는 정수 `index/9`다. int 나눗셈 뒤 Floor를 다시 하는 것은 불필요하다. panels가 비었거나 저장 최대 인덱스가 panels 범위를 넘을 때도 처리한다. 재활성 시 점수·별·페이지를 갱신하고 모든 별을 먼저 초기화한다. 3별을 표시한 뒤 1별 판을 열었을 때 이전 별이 남지 않아야 한다.

영속 서비스 객체는 씬의 UI 참조를 오래 보유하지 않게 한다. `DontDestroyOnLoad` GameData에 Splash 전용 panel controller를 붙이면 씬 재진입 후 파괴된 UI 참조를 가질 수 있다. 씬 조정자는 씬과 함께 생성/해제하고 저장 서비스만 영속시킨다.

## 별점과 진행 저장

별 임계값은 정렬·개수·중복·정확히 임계값과 같을 때를 검증한다. `>`와 `>=`는 다른 정책이다. 최고점보다 낮은 재플레이에서도 새 별점이 개선될 수 있으므로 ‘최고점 갱신’ if 안에 모든 진행 저장을 묶지 않는다. 저장 별은 명시 정책에 따라 최대값을 유지한다.

조각 하나 제거할 때마다 전체 파일을 쓰기보다는 안정된 진행 경계에서 검증한 스냅샷을 커밋한다. UI 표시 변경·앱 종료 알림만이 저장 근거가 되어서는 안 된다. 프로세스 종료나 모바일 중단으로 종료 콜백이 실행되지 않을 수 있기 때문이다.

| 저장 대상 | 보관할 예 | 보관하지 않을 예 |
|---|---|---|
| 옵션 | 음악/효과음, 명시 기본값 | AudioSource/씬 객체 참조 |
| 레벨 진행 | 안정된 stage ID, 해금/최고 기록 | 버튼 객체와 UI 텍스트 |
| 보상 거래 | 고유 거래 ID·원인 클리어·증분 | 승리 panel의 활성 여부만으로 지급 |
| 재개 정보 | 지원하는 버전·정의·상태·PRNG | 지원하지 않는 판 중간 상태를 임의 복원 |

Taft P46의 BinaryFormatter 파일 예제는 현재 저장 설계로 채택하지 않는다. P47의 `FileMode.Create` 정정은 최초 파일 생성 오류를 고치지만 손상 복구·버전·보안·원자성 전체를 해결하지 않는다. 현행 API 관련 근거는 [호환 대조](MATCH3_UNITY6_COMPATIBILITY.md)를 따른다.

저장은 버전·필수 필드·범위·프로필/리비전·콘텐츠 ID를 검증하고 임시 쓰기/원자 교체/이전 백업 등 실패 정책을 마련한다. 체크섬은 손상 탐지와 관련되며 클라이언트 부정행위 방지를 자동 보장하지 않는다. 보상 중복은 고유 거래를 기준으로 막는다. 읽기만으로 기존 저장을 덮어쓰지 않는다.

## 힌트·교착·셔플 정책

힌트와 교착 검사는 교환과 같은 합법성·특수 예외를 사용한다. 시험 후 원복, 검사 중 PRNG 미소비, 가장자리 가능한 수, 빈칸·잠금·특수 탭을 확인한다. 탐색의 첫 수를 찾는 기능과 최적 목표 달성 AI를 구분한다.

셔플을 한다면 보존할 조각 multiset·특수·원래색·ID·장애물 위치를 정한다. 무제한 재귀로 ‘매치가 없고 수가 있는 판’을 찾지 않는다. 재시도 상한과 실패 시 재생성/종료 정책을 명시한다. Catlike의 안정판 교착은 `NO MORE MOVES` 종료이고 Taft는 셔플을 만든다. 적용할 프로젝트의 교착 정책과 혼동하지 않는다.

## 실제 검증의 층

| 층 | 확인할 것 | 그 결과만으로 말할 수 없는 것 |
|---|---|---|
| 문서/정적 코드 | 순서·범위·호환 API·누락 | 실제 Unity 컴파일/동작 PASS |
| 순수 규칙 fixture | seed·명령·정확한 상태/이벤트 | 화면 타이밍·터치·기기 성능 |
| Editor/Play | 참조·pool·취소·애니 완료·재진입 | Android IL2CPP·백그라운드·Safe Area |
| 빌드/기기 | 터치·화면·중단 복구·저장 경로·성능 | 모든 단말/모든 레벨 품질 |

작은 고정판 검증에는 행/열 끝 run, T/L, 두 분리 그룹, 마지막 수 승리, 무효 교환 불변, 다중 특수 순환, 구간 낙하, 가능한 수가 가장자리에만 있는 판, 교착판을 포함한다. 저장에는 최초 생성·중복 클리어·마지막 레벨·손상/백업·미지원 버전·쓰기 실패·중단 후 재시도를 포함한다.

모바일 검증은 가로 Safe Area와 보드 실제 Rect, UI 위 터치, 두 손가락·취소, 앱 중단/복귀, 장시간 연쇄, pool 누수, 스코어/VFX가 많은 상황의 프레임·메모리·발열을 본다. 평균 FPS 하나로 완료를 판정하지 않는다. 기기/빌드/구간과 p95·최대 정지 등 실제 측정 조건을 남긴다.
