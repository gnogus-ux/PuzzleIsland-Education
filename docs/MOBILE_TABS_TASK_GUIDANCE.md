# 모바일 탭과 현재 작업·다음 행동 안내

2026-11-09 핵심 공식 자료 5개의 필요한 절을 읽고 기존 [버튼 상태 매뉴얼](UI_BUTTON_STATE_FEEDBACK.md)과 대조한 **적용 설계**다. 문서 작성자는 제품 코드·폰·앱·서버를 조작하지 않았다. 탭 구조·캔버스 복구·접근성의 실제 제품 통과를 주장하지 않는다. 기존 사진·입력·초안·저장/페어링·r16 및 검수 원본을 보존한다.

## 1. 기능을 찾는 스크롤을 줄이는 탭 구조

탭은 같은 작업의 기능 공간을 나누고 현재 패널 하나만 보여 준다. 모든 메뉴를 그대로 한 화면에 길게 쌓고 제목만 탭으로 바꾸지 않는다. 가장 자주 오가는 소수의 이름을 짧게 정하고, 해당 탭에 필요한 도구·설정만 패널에 둔다.

적용 예시는 다음과 같다. 실제 기능 경계는 기존 프로그램과 대조해 정하며 새 기능을 추가하는 명세가 아니다.

| 공간 예시 | 해당 패널의 내용 | 남겨야 할 경계 |
|---|---|---|
| 작업 | 기존 작업 열기·사진 선택·작업 정보 | 현재 작업과 입력 보존 |
| 측정 | 사진 위 점 선택·이동·관련 설정 | 점/사진의 원본 좌표와 측정 상태 |
| 입구 | 입구 편집·선택/자유 모드·완료 | 기존 점과 확인 상태 |
| 결과 | 기기 저장·결과 파일·기존 전달 기능 | 초안/파일/PC 접수·반영의 차이 |

이는 필수 4탭 규칙이 아니다. 좁은 화면에서도 이름과 현재 위치가 보이는 개수로 정리한다. 편집 중 꼭 필요한 저장/다음 행동은 다른 탭을 찾아가야만 누를 수 있게 숨기지 않는다. native가 바깥 기능 탐색을 맡으면 WebView는 그 기능 안의 도구만 맡는 등 소유 범위를 정해 같은 상위 탭을 두 번 나열하지 않는다.

탭 선택은 작업 완료·저장·다음 단계 달성과 다르다. 탭을 방문했다고 완료 체크나 진행률을 올리지 않는다. 선택한 화면과 실제 작업 진행은 별도 상태다.

## 2. 얇은 현재 안내와 접히는 상세

사진을 밀어내는 긴 제목·상태 줄·반복 오프라인 경고를 겹쳐 고정하지 않는다. 기본 화면은 짧은 탭 줄, 현재 작업/상태와 다음 행동 한 곳, 사진/편집 영역 순으로 구성한다. native와 웹이 같은 안내를 중복 방송하지 않게 한 곳을 주 소유자로 정한다.

| 항상 짧게 보이는 정보 | 접을 수 있는 상세 |
|---|---|
| 현재 기능·필요한 대상, 미저장 여부 | 긴 작업 설명·반복 사용법 |
| 현재 오류와 복구에 필요한 행동 | 원인 분석·기술 문구·진단 상세 |
| 기기 저장/파일 생성/PC 반영 확인 범위 | 오프라인 구조·연결 원리 설명 |
| 지금 가능한 다음 행동 하나 | 드물게 쓰는 설정과 도움말 |

예를 들어 “현재: 측정점 조정 / 다음: 점 선택”, “미저장 편집 있음 / 다음: 기기 저장”처럼 짧게 쓴다. 다음 행동은 실제 선택·입력·dirty·오류·기능 가능 조건으로 정한다. 사진이 없거나 내보내기 조건이 안 되면 실행 가능한 동작이나 이유를 보여 주며 성공을 미리 표시하지 않는다.

기기 초안 저장·결과 파일 생성·PC 접수·PC 적용을 합쳐 “완료”라고 쓰지 않는다. 휴대폰이 PC 적용 여부를 알 수 없으면 “기기 저장됨 · PC 반영 미확인”처럼 확인 한계를 적는다. 단순 탭 이동이나 파일 선택기를 열었다는 사실은 저장 증거가 아니다. 기존 [저장 상태와 실제 결과 구분](UI_BUTTON_STATE_FEEDBACK.md)을 유지한다.

반복 설명은 [WAI Disclosure 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)처럼 이름 있는 “상세” 버튼으로 펼친다. 웹의 실제 펼침 상태에 aria-expanded를 맞추고 필요하면 aria-controls로 연결한다. Enter/Space와 터치로 같은 동작을 제공한다. 현재 오류·미저장·PC 반영 미확인까지 상세 안으로 숨기지 않는다. 도움말 펼침이 입력을 지우거나 상태를 바꾸지 않게 한다.

## 3. 탭 의미·키보드와 좁은 화면의 고정 탐색

[WAI Tabs 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)에서 웹 tablist에는 tab들이, 각 tab에는 대응 tabpanel이 있다. aria-controls/aria-labelledby로 연결하고 실제 활성 tab 하나만 aria-selected=true로 둔다. 비활성 패널은 보이지 않고 그 내부가 키보드·화면읽기의 현재 작업 대상이 되지 않게 한다. 기존 `aria-pressed` 모드 버튼을 탭 구조와 혼동하지 않는다.

Tab키로 활성 탭에 들어오고 다음 Tab은 패널의 의미 있는 내용/컨트롤로 나간다. 좌우 화살표로 탭 초점을 옮기며 수동 활성화 방식은 Enter/Space로 패널을 연다. 초기 선택과 초점은 다를 수 있다. 사진·패널 표시가 느리면 초점 이동만으로 매번 로드하지 않고 수동 활성화를 사용한다. 자동 활성화는 패널이 지연 없이 표시될 때의 선택이다. 가로 탭에서 위/아래 키의 일반 스크롤까지 빼앗지 않는다.

native 기존 Views에는 HTML role을 붙이지 않는다. 현재 선택·실제 패널 표시·안내/접근성 의미를 함께 맞추고 기존 위젯과 공용 버튼 상태 기준을 재사용한다. 새 TabLayout/AndroidX/Compose 의존성이 이미 있다고 가정하거나 설치하지 않는다.

웹의 [CSS sticky 설명](https://www.w3.org/TR/css-position-3/#sticky-pos)은 가장 가까운 scrollport와 inset을 기준으로 한다. 어떤 컨테이너가 실제 스크롤하는지 확인하고 필요한 탭 줄만 고정한다. 문서와 내부 패널의 이중 스크롤이나 여러 sticky 줄이 서로 겹치지 않게 한다. 이 자료는 열람 시 W3C Working Draft이며 실제 브라우저 동작 검수를 대신하지 않는다.

화면 폭이 작거나 글씨가 커져도 탭 이름·현재 표시·상태가 잘리지 않아야 한다. 선택 탭을 찾기 위해 페이지 아래로 스크롤할 필요가 없게 하고, 가로 스크롤 탭을 택하면 넘치는 항목이 있음을 드러내고 선택 탭을 보이는 위치로 맞춘다. 가능하면 먼저 이름/개수를 줄인다. 고정 줄이 사진·하단 동작·소프트 키보드 위의 입력과 focus를 가리지 않는지 확인한다.

## 4. 입력과 사진 좌표·숨은 캔버스 보존

탭을 바꿀 때 저장/초기화/사진 재선택을 암묵적으로 실행하지 않는다. 현재 작업ID·사진ID·원본 좌표·기준선/확인·선택 점·모드·dirty·진행 요청을 기존 모델에 유지한다. UI를 감추는 것과 데이터를 삭제하는 것은 다르다. 재전환은 같은 데이터에서 표시를 복원하며, 오래된 패널의 지연 응답이 새 탭의 입력/저장 안내를 덮어쓰지 않게 한다.

[Android WebView API](https://developer.android.com/reference/android/webkit/WebView)는 saveState/restoreState가 display data를 저장·복원하지 않는다고 명시한다. 이 API 호출만으로 DOM 입력·사진·캔버스·초안을 보존했다고 주장하지 않는다. 기존 WebView/패널을 불필요하게 재생성·load/reload하지 않고, 재생성이 필요하면 기존 앱의 명시 상태/초안 복구 경로로 대조한다. restoreState를 이미 로드한 WebView에 무조건 덧씌우지 않는다.

숨은 패널에서 크기를 재면 0이거나 보이는 때와 다를 수 있다. 양수인 실제 표시 영역을 얻은 뒤에만 사진 맞춤·좌표 변환·렌더를 한다. 탭 재노출과 첫 사진 디코딩 뒤의 크기 확정도 검토한다. 폭 0으로 fit을 계산해 확대값/좌표가 망가지거나 나중에 클릭한 위치가 바뀌면 실패다.

[ResizeObserver 규격](https://www.w3.org/TR/resize-observer/)은 요소 크기 변화 관찰과 display:none, 관찰 시작 조건, CSS transform이 알림을 일으키지 않는 점을 설명한다. viewport resize만으로 모든 탭/컨테이너 변화를 잡는다고 가정하지 않는다. 재노출 후 양수 크기 확인·필요한 재렌더를 모으고 반복 크기 변경 루프를 피한다. API 지원과 실제 WebView 동작은 검수한다.

사진의 원본 픽셀 좌표는 패널 CSS 크기와 별개다. resize/스크롤/확대·DPR 변경으로 원본 점·단위·revision·사진 SHA를 다시 써서는 안 된다. 좌표는 실제 캔버스 위치·현재 변환으로 계산하고 다시 그릴 때 기존 데이터에서 복원한다. 탭 이동 중 진행 중인 터치/드래그는 기존 취소 정책으로 정리하고 숨은 영역에서 추가 편집이 이어지지 않게 한다.

## 5. 제한 검수와 출처 범위

탭마다 보이는 내용/선택/안내 일치, native·웹 중복 안내 제거, 좁은 폭·큰 글씨·키보드·TalkBack을 검수한다. 사진 로드 전후와 반복 탭 이동, 접힘 상세, 숨은 패널 resize, 확대/이동 뒤 원본 점의 표시·선택 위치, 탭 간 스크롤·미저장/취소/오류·지연 응답·복구도 확인한다. 표시 전후 실제 데이터와 dirty/저장 범위를 대조한다. 한 화면 캡처나 DOM 값만으로 모든 입력·접근성이 통과했다고 하지 않는다.

핵심 공식 5자료는 Tabs 패턴, Disclosure 패턴, Android WebView 상태 API, CSS sticky 절, ResizeObserver의 관련 절이다. 현재/다음 안내와 저장 구분·대비/기기 접근성 기준은 기존 공용 UI 상태 매뉴얼을 재사용한다. 자료 관찰·구체 배치 제안·아직 하지 않은 제품 실기를 구분한다. [자료별 선택 열람 기록](../reports/ExternalLearning/20261109_MOBILE_TABS_TASK_GUIDANCE_STUDY.json)을 참고한다.

제품 탭 구현·실제 저장/취소·회전·초안/좌표 보존·지원 WebView·큰 글씨/TalkBack·전체 WCAG 적합성은 **미검증**이다. 설치·계정·네트워크/라우터/서버 설정을 바꾸는 작업을 포함하지 않는다.
