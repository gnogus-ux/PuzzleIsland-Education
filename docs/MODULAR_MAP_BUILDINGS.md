# 벽·문·지붕과 중첩 건물

[전체 순서](MODULAR_MAP_WORKFLOW.md) · [접합 규격](MODULAR_MAP_GRID_KIT.md) · [인계와 임포트](MODULAR_MAP_BLENDER_UNITY.md)

## 원본 두 흐름의 차이

[Imphenzia 설원 집](https://www.youtube.com/watch?v=V1Xe2EptOOw)은 Blender 제작→Unity 조립을, [Christina](https://www.youtube.com/watch?v=0o-QnNs-stc)는 준비된 에셋의 분류→집 조립을 보여 준다. 전자는 8×8m 블록 설명으로 시작하고 후자는 2.5m 벽을 사용한다. 두 수치를 같은 규격으로 합치지 않는다. 어떤 스타일도 별도 프로젝트의 승인 아트로 간주하지 않는다.

## Blender에서 부품을 만들 때

원본 확인:

- 02:04–06:33: 빔에 쓸 엣지를 커브로 바꾸고 낮은 해상도의 단면과 틸트로 형태를 낸 뒤 메시로 전환한다. 외곽 빔과 팔레트 재질을 정리한다.
- 14:40–33:13: 덧문·문·문틀을 만들고 복제한다. 음수 스케일 후 법선 재계산과 의도치 않은 중복 복제 문제를 다룬다.
- 33:13–43:22: 나무·벽 균열에 Knife 등을 쓴다. 정적 로우폴리 스타일 전제이며 Subdivision용 면 흐름 설명은 아니다.
- 43:22–1:09:16: 지붕·굴뚝·급경사 지붕·도머 창을 만든다. 다른 지붕 깊이에서도 창이 붙도록 뒤쪽을 늘리는 사례가 있다.
- 1:09:16–1:42:36: 기초·간판·등·발코니·돌출 창을 별도 조합 가능한 부품으로 만든다.

적용 제안: 문/창은 규격 벽에서 차지하는 폭과 접합 위치를 먼저 고정한다. 문틀/손잡이 등 디테일은 통과 공간 밖에 둔다. 굴뚝과 부착 소품은 설치면 기준 피벗을, 회전 문은 경첩 기준 피벗을 따로 정한다. 조립용 바닥 피벗을 모든 움직이는 문에 강요하지 않는다.

## 계층과 재사용 — 적용 제안

```text
BuildingRoot
  Level_00
    Floors
    Walls
    Doors
    Decoration
  Level_01
  Roof
  Collision
  InteractionAnchors
```

이 구조는 원본의 층/바닥/벽/문/장식 구분을 보완한 예시이며 자동 생성 코드가 아니다. Floor와 Wall 등 부품 Prefab, 한 층 조합, 건물 전체 조합의 책임을 구분한다. 자식의 로컬 0이 맞으려면 서로 설계된 피벗과 기준 좌표가 있어야 한다. 임의 물체를 부모에 넣고 0으로 만들면 원래 위치를 잃을 수 있다.

Christina 14:33의 Default Parent는 새 물체의 소속을 돕는 기능이다. 피벗 정렬·Local 0·층 높이를 자동으로 맞춰 주는 기능은 아니다. 15:13의 Replace Selection 조작은 원본 Unity 6.2 화면의 예다. 현재 앱의 메뉴·필드·재질 보존 동작은 적용 전에 확인한다.

## 지붕과 코너

원본 Christina 19:34 이후에는 지붕과 처마를 한 조합으로 묶고 코너를 수동으로 맞춘다. 지붕 자동 생성 알고리즘은 구현하지 않는다. Imphenzia는 지붕 경사가 다른 집을 조립하고 굴뚝 길이를 다시 조절해 내보낸다.

적용 제안: 직선 지붕·끝/박공·내외 코너·처마·도머의 호환표를 만든다. 바닥 폭, 지붕 경사, 처마 돌출, 능선 높이가 다른 부품은 다른 접합 계열로 표시한다. 한쪽 지붕이 맞아도 반대쪽에서 틈/포개짐이 없는지 확인한다. 실내 사용 여부에 따라 안쪽 면·카메라 가림·충돌을 정한다.

## 문·소품·변형

원본의 회전/슬라이드 문 예제는 움직임 설명이며 실제 프로젝트의 문 동작 검증이 아니다. 문이 벽 뒤로 들어가 상호작용이 어려워지는 사례도 있다. 무작위 문 선택·재질 교체는 강사 자체 스크립트의 시연으로, 이번 문서에 전체 실행 코드나 재현된 도구를 제공하지 않는다.

적용 제안: 문이 닫힌/열린 상태의 통로 폭·트리거·카메라·경로 판정을 모두 시험한다. 소품은 선반/작업장/입구처럼 용도를 가진 묶음으로 두고 경로와 도착 지점을 비운다. 같은 벽 변형을 반복하기보다 층/지붕/간판 조합으로 구분한다. 재질만 바꾼 변형이 재질 인스턴스를 과도하게 늘리지 않는지 검사한다.

## 눈 생성·맞춤 셰이더 사례의 한계

원본 1:42 이후의 눈 생성 도구는 오류를 표시한 뒤에도 숨은 오브젝트를 만든다. 메시 수가 많아지고 Unity 임포트/원점/렌더 텍스처 문제를 여러 번 고친다. 1:56:45와 2:40:45 화면에는 자기 교차 다각형이 버려졌다는 경고가 남아 있다. 마지막 Play 시연도 발코니 위아래 눈에 동시에 영향을 주는 문제가 남는다.

따라서 이 구간은 완성된 모바일 눈 시스템의 조리법이 아니다. 도구 설치/구매는 수행하지 않았다. 복잡한 효과는 먼저 평범한 건물의 접합·충돌·재질 왕복 검사를 마친 뒤 별도 예산과 시험으로 다룬다.
