# 배우 이동·카메라·복원 상태 검수

[전체 순서](MODULAR_MAP_WORKFLOW.md) · [지형](MODULAR_MAP_TERRAIN.md) · [Unity 인계](MODULAR_MAP_BLENDER_UNITY.md)

이 문서는 **다음 제작에서 실행할 시험표**다. 원본 강좌의 일부 Play 시연과 이번 교육 문서 검토를 실제 게임의 보행·기기 검증으로 계산하지 않는다. 통과/실패/미실행을 시험별로 남긴다.

## 캐릭터와 공간 — 적용 제안

캐릭터 본체와 모자·가방을 포함한 시각 크기, 실제 충돌 폭/높이, 발 기준, 상호작용 접근점을 따로 기록한다. 원본 던전의 약 1.7m 배우·2m 지붕 언급은 예제다. 적용 캐릭터의 승인 치수로 통로·문·단차를 다시 정한다.

| 시험 | 재현 방법 | 완료 조건/남길 근거 |
|---|---|---|
| 직선/코너 | 양방향 걷기·모서리 대각 진입 | 걸림·관통·경로 이탈 없음 |
| 문/낮은 천장 | 열린/닫힌 문과 장비 포함 이동 | 머리 위 여유·차단/허용 일치 |
| 경사/계단 | 아래/위·비스듬한 진입·경계 정지 | 미끄럼·뜸·순간 높이 이동 판정 확인 |
| 절벽/해안 | 가장자리 접근·불가 지점 터치 | 낙하·지름길·물 뒤 우회 방지 |
| 다리/복원 | 파손→복원→재접속 | 시각·충돌·경로 상태 동기화 |
| 도착 지점 | 목적지 변경·무효 입력·최단 접근 | 지정 접근점에서만 상호작용 |
| 카메라 | 경로·목적지를 가리는 벽/전경 지나기 | 배우·목표가 보이고 입력 구분 가능 |
| 가로 화면 | 16:9와 긴 가로 Safe Area/HUD | 배우/목적지가 안전 영역에 표시 |

동일 조건 Solid/Wire 비교와 실제 플레이 화면을 구분한다. 메시가 무결하다는 결과만으로 이동 성공을 판정하지 않는다. 지형 경계 테스트는 서로 다른 LOD가 만나는 경우까지 포함한다.

## 경로 방식과 문

원본 Christina [16:40–17:46](https://www.youtube.com/watch?v=0o-QnNs-stc&t=1000s)는 NavMeshSurface의 수집 설정을 보여 준다. 문이 경로를 막자 문 컨테이너를 비활성화하고 베이크한 뒤 다시 켠다. 강사는 문제가 생길 수 있음을 인정하며 정해진 웨이포인트 경비병 예시로 한정한다.

따라서 이 방법만으로 문 개폐·동적 장애물·다른 층의 연결이 해결됐다고 쓰지 않는다. 적용 제안은 다음과 같다.

- 기존 격자 이동: 통행 셀, 인접 선분, 높이차와 문/다리의 상태를 검사한다. 시각 메시 교체만으로 경로가 자동 갱신된다고 가정하지 않는다.
- NavMesh 사용 프로젝트: 에이전트 크기·경사/단차·수집 레이어와 계단/문 정책을 기록하고 열린/닫힌/움직이는 상태를 시험한다. 링크/장애물/재베이크 방안은 요구에 따라 별도 결정한다.
- 경로와 충돌을 겹쳐 보며 갈 수 있는 경로가 실제 표면에 있는지 확인한다. Height Mesh 옵션만으로 층간 이동이 구현됐다고 판정하지 않는다.

이번 교육 때문에 기존 이동 코드를 NavMesh로 바꾸지 않는다.

## 복원/꾸미기 상태 — 추가 보완, 원본 5강 미구현

부품을 바꾸는 복원 시스템은 단순 Prefab 변형과 다르다. 다음 계약을 따로 설계하고 시험한다.

1. `파손/복원 중/완료`의 시각 부품·충돌·경로·상호작용 가능 여부를 한 표에 기록한다.
2. 교체 전후에 같은 루트·접근점·접합 경계를 유지한다. 장식 크기가 바뀌면 카메라·HUD 가림을 다시 확인한다.
3. 배우가 다리 위 또는 문 사이에 있을 때 상태 변경을 허용할지 결정한다. 단순 메시 비활성화로 배우를 떨어뜨리지 않는다.
4. 중단/재접속/저장 복원 뒤도 같은 상태인지 확인한다. 장식 교체가 보상·구매 거래를 반복시키지 않도록 기존 경제/저장 계약을 따른다.
5. 상태별 한 번의 화면만으로 끝내지 말고 앞뒤 경계 통과·목적지 재지정·이전 지역으로 돌아가기를 시험한다.
