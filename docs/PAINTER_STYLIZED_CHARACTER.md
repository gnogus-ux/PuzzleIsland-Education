## 재현 순서

### 1. 색 영역부터 만들기

대상 Texture Set을 선택하고 Fill Layer에 기본색을 둔다. 작업에 필요한 채널만 켜 불필요한 Height/Normal/Roughness 덮어쓰기를 막는다. 검은 마스크를 추가하고 Polygon Fill로 해당 면/UV 영역을 드러낸다. 경계가 복잡한 얼굴은 마스크 Paint로 다듬는다.

03:20 근처의 붉은 선은 Polygon Fill 작업 표시다. 지오메트리 리토폴로지가 바뀌었다는 근거가 아니다. Eyes 세트의 전체가 임시 분홍색이 되는 화면도 마스크를 정리하기 전 중간 상태다. 완성 피부나 눈 색으로 받아들이지 않는다.

### 2. 얼굴은 기본색·색 변화·거칠기를 분리

승인 피부색을 먼저 맞추고 눈가·코·볼·입술의 변화는 별도 Fill/마스크 레이어에 둔다. 색만 보는 화면과 재질 화면을 번갈아 본다. 고정 조명에서 강한 그림자를 색에 그려 넣지 않도록 한다. 브러시 크기/흐름/불투명도를 작업 크기에 맞추며 강좌 수치를 루미 처방으로 고정하지 않는다.

09:00 화면은 다른 Texture Set을 숨긴 상태에서 눈구멍·입안을 확인한다. 눈이 없어졌다고 피부 메시를 삭제한 것은 아니다. 본 강좌는 독립 안구 제작이나 눈꺼풀 움직임 검증을 보여주는 자료가 아니다.

20:00 원본 크기 화면에는 Eyes 세트의 `R` 레이어와 Roughness **0.2082**가 읽힌다. 이는 예제의 해당 순간 값이다. 루미 눈 전체/각막/홍채에 일괄 적용할 승인값이 아니다. 거칠기 작업은 색을 하얗게 칠하는 작업과 다르다.

### 3. 디테일은 범위를 제한

예제의 수염·주름·의상 로고는 루미 디자인과 무관하다. 큰 흰 브러시 자국이 보이는 중간 화면을 목표로 삼지 않는다. 필요한 경우 마스크와 레이어 불투명도로 디테일 범위를 제한하고 실제 게임 크기에서 보이는지 판단한다. 브러시/소재가 목록에 있다는 사실은 자산 사용권이나 다운로드 완료를 증명하지 않는다.

30:00 화면에는 **Position** 생성기, Global Invert=True와 하단으로 어두워지는 의상 마스크가 읽힌다. 챕터의 Ambient Occlusion 표기만으로 해당 화면을 AO 베이크라고 부르지 않는다. 위치에 따른 색 변화와 틈새 차폐는 서로 다른 근거가 필요하다.

### 4. 출력은 파일과 경고까지 확인

32:00 화면의 설정은 `Blender (Principled BSDF)`, PNG 8 bits, 세트 크기 기준, Dilation infinite다. Body 4096과 다른 시점의 Eyes 1024가 보인다. 이를 전체 세트 4K나 최종 모바일 규격으로 일반화하지 않는다.

이후 탐색기에는 BaseColor/Displacement/Normal/Roughness 파일들이 보인다. 그러나 33:00 화면 하단에는 **Body_Alpha.1001 생성 불가 경고**가 남아 있다. 파일 목록이 있다는 이유로 모든 출력이 정상이라고 결론 내릴 수 없다. 불필요한 알파인지 필수 맵 누락인지 목적과 대조해야 한다. 이 작업에서 실제 텍스처를 출력한 것은 아니다.

## 루미용 인계 기준

- 승인 이미지의 피부톤·눈/입 경계를 보존하고 강좌의 남성 캐릭터 인상·수염·로고를 도입하지 않는다.
- 피부와 눈이 다른 광택을 내야 하면 맵/마스크/재질 구조를 먼저 정한다. 메시를 바꾸려면 별도 Guide가 필요하다.
- 색 번짐은 Base Color 단독 보기, 표면 문제는 Roughness/Normal 단독 보기와 재질 보기를 함께 확인한다.
- 정면·사선·측면 및 눈가·입술 확대를 같은 조명에서 비교한다. 출력 누락·외부 경로 누락·UV 솔기를 기록한다.

베이크 준비의 모든 설정, 예제의 원본 메시 제작, 게임 엔진 성능은 이 표본 검토로 확인하지 않았다. [Blender로 옮기는 절차](PAINTER_TO_BLENDER.md)에서 출력 채널을 별도로 확인한다.
