# 1부. 사진 촬영과 3D 표면 복원

## RealityScan 2.2 CLI로 정렬만 시험할 때

2026-11-10 공식 문서 보강. 대상 실행 파일은 2.2.0.119430이며 문서 열람과 아래 제한 실기 결과는 구분한다. 입력은 같은 실물·같은 자세 후보만 고르고 원본 바이트와 SHA256이 같은 사본으로 준비한다. 색상이 다른 제품, 펼침·닫힘, 손으로 잡아 변형된 사진을 하나의 강체로 강제 정렬하지 않는다. 동일 실물 여부가 불명확하면 시험 가정으로 기록한다.

1. 사용자 인스턴스와 미저장 작업을 먼저 확인한다. 기존 인스턴스에 명령을 위임하거나 새 장면으로 교체하지 않고, 충돌이 없을 때만 별도 새 실행에서 시험한다.
2. 공식 `-headless`로 시작하고 `-stdConsole`의 표준 출력을 분석 폴더 로그로 받는다. `-disableOnlineCommunication`으로 온라인 통신을 끄는 방법도 공식 설정 명령에 있다. 열람한 본문에는 프로세스 종료 후 지속 여부가 명시되지 않아 이 명령을 프로세스 한정이라고 단정하지 않는다. 실행 전후 설정 근거가 없으면 사용자 설정 불변·복원 완료를 주장하거나 임의 복원하지 않는다. 이 명령으로 유효한 계정·라이선스나 인증이 생기지는 않는다. 로그인·연령·보안 승인이 필요하면 사용자가 직접 처리한다.
3. `-addFolder`로 사본 폴더를 입력하고 `-exportGlobalSettings`로 실제 설정을 기록한 뒤 `-align`한다. 기본값 표를 실제 적용값으로 간주하지 않는다. 이번 분석을 위해 `reset`, 전역 환경변수 변경, 캐시 위치 변경을 하지 않는다. 설정 변경이 필요하면 기존 값을 보존하고 해당 범위를 따로 검토한다.
4. `-save`로 새 `.rsproj`에 저장한다. `-exportReport output.html template.html`은 설치 폴더 `Reports`의 공식 `Overview.html` 템플릿으로 입력 수·컴포넌트 수·등록 카메라·재투영오차를 남길 수 있다. 결과가 없을 때도 파일 생성과 종료 상태를 확인한다.
5. `-setMinComponentSize`와 `-exportLatestComponents`로 작은 분리 묶음도 보존한다. `-exportXMP`는 이미지 옆에 카메라 메타데이터를 쓰므로 반드시 사본을 입력해야 한다. 최신 명령 표와 일부 옛 예시의 `exportComponent`/`minComponentSize` 표기가 다르므로 최신 표를 기준으로 한다. 다만 실제 2.2.0.119430은 `setMinComponentSize`를 실행하면서 deprecated 경고를 출력했다. 문서와 설치 버전의 이 차이를 기록하고 다음 버전에서는 대체 명령을 다시 확인한다. `-quit` 뒤 실제 프로세스 종료·반환 코드·내보내기·원본 SHA를 각각 검증한다. 프로세스 종료를 봤어도 반환 코드를 보존하지 못했으면 종료 코드 미확인으로 남긴다.

정렬 시험에는 메시·텍스처 생성 명령을 넣지 않는다. 정렬 성공은 정확한 두께·재질·포켓 내부·실측 크기나 편집 가능한 모델 완성을 의미하지 않는다. EXIF 렌즈·원본 해상도·겹침·고정 자세가 부족하면 카메라 보정과 연결이 불안정할 수 있다. 서로 분리된 컴포넌트의 오차가 작아도 지갑 전체가 연결됐다고 판정하지 않는다.

헤드리스도 팝업·오류·사용자 상호작용 때 창이 나타날 수 있다. `silent`는 경고 및 업로드 마법사 동작에 영향을 주며, 직접 인증을 대신하지 않는다. `appQuitOnError` 등 `set` 키는 앱 설정을 바꾸므로 무조건 추가하지 않는다. 연결 끊김은 실행 종료의 증거가 아니며 상태가 불명확하면 UNKNOWN으로 기록한다. 같은 오류는 합리적 최대2회까지만 확인하고 중복 실행·강제 종료·재시작으로 우회하지 않는다.

[프로젝트/입력 CLI](https://rshelp.capturingreality.com/en-US/tutorials/commandline.htm), [정렬 CLI](https://rshelp.capturingreality.com/en-US/tutorials/commandline_1.htm), [오류 처리](https://rshelp.capturingreality.com/en-US/tutorials/commandline_5.htm), [헤드리스](https://rshelp.capturingreality.com/en-US/tutorials/headless.htm), [설정 명령](https://rshelp.capturingreality.com/en-US/tutorials/commandline_4.htm), [설정 키](https://rshelp.capturingreality.com/en-US/tutorials/setkeyvaluetable.htm), [전체 명령 표](https://rshelp.capturingreality.com/en-US/appbasics/allcommands.htm).

## 먼저 선택할 작업 방식

**예시 지갑에는 실측 치수와 기존 모델을 중심으로 삼고, 사진 복원 결과를 외형·무늬·주름의 참고로 사용하는 방식이 적합하다.** 아래 선택 기준과 제작 절차는 강좌 원리를 지갑 프로젝트에 맞춰 작성한 적용안이다. 실제 제품을 새로 촬영하거나 복원한 검증 결과는 아니다.

| 가진 자료 | 선택할 방식 | 얻을 수 있는 것과 확인할 한계 |
| --- | --- | --- |
| 같은 지갑·같은 자세를 여러 방향에서 촬영한 원본 사진 | 여러 사진을 이용한 포토그래메트리 | 겹쳐 보이는 표면과 카메라 위치를 추정한다. 가려진 포켓 내부와 실측 두께는 별도 확인한다. |
| 사진 몇 장과 실측 치수 | 치수 기반 모델링 + 사진 대조 | 기존 외피·내피·포켓 구조를 유지하며 실루엣과 패턴 위치를 맞춘다. 부족한 시점은 추가 촬영한다. |
| 직선과 원근이 분명한 사진 한 장 | fSpy 카메라 맞춤 + 직접 모델링 | 사진과 같은 시점의 투시를 맞춘다. 뒷면·깊이·정확한 두께가 자동으로 생기지는 않는다. |
| 가죽을 가까이 촬영한 사진 | 별도 재질·높이맵 작업 | 색·결의 참고 자료다. 사진 밝기가 실제 높이라는 보장은 없다. |

P1~P4는 여러 사진을 이용한 복원 계열, P5는 단일 사진의 원근을 맞춰 직접 모델링하는 계열이다. Gaussian Splat은 보기 좋은 공간 표현이 될 수 있지만, 포켓과 접힘을 편집할 수 있는 메시가 필요한 작업에서는 결과 유형을 먼저 확인한다. [Polycam 결과 유형 안내](https://learn.poly.cam/hc/en-us/articles/27425185907348-How-to-Use-Object-Mode), [fSpy 원리](https://fspy.io/basics/).

## 촬영 전에 정할 것

1. 지갑 하나와 촬영 자세 하나를 정한다. 펼친 상태, 닫힌 상태, 카드가 들어간 상태는 각각 다른 세트로 기록한다. 색상 조합이 다른 지갑이나 서로 다른 실물을 한 복원 세트에 섞지 않는다.
2. 휘어짐과 포켓 벌어짐을 막는 안정된 받침을 준비한다. 받침이 가리는 부위는 누락 목록에 적는다. 손으로 들고 돌리면 형태와 가림이 계속 바뀌므로 피한다.
3. 원본 사진, 촬영용 사진 사본, 정렬 프로젝트, 원본 스캔, 정리한 메시, 텍스처, 검수 기록을 구분한다. 파일명에 제품·자세·촬영 회차를 넣는다.
4. 같은 물체 위에서 식별 가능한 기준점 두 개 사이 거리를 재고 기록한다. 다른 위치의 길이도 하나 더 재어 검증용으로 남긴다. 주변 자를 쓸 경우 지갑과 함께 움직이지 않도록 고정한다.

사진은 보통 절대 크기를 스스로 알려 주지 않는다. 알려진 거리를 지정해야 미터·밀리미터 기준으로 보정할 수 있다. [RealityScan 거리 보정 안내](https://rshelp.capturingreality.com/en-US/tutorials/scaling.htm).

## 빛과 카메라 준비

가죽의 반사광과 진한 그림자가 시점마다 움직이면 대응점을 찾거나 색을 합치는 데 방해가 된다. 넓은 확산광 아래에서 촬영하고, 노출이 날아가는 반짝임과 검게 뭉개진 접힘을 먼저 줄인다. 완성 가죽 제품에 분필·무광 스프레이를 바르는 방법은 이 프로젝트의 촬영 절차에 넣지 않는다.

- 한 촬영 묶음에서는 렌즈·줌을 유지한다. 휴대폰이 근접 촬영 중 다른 렌즈로 자동 전환하는지 확인한다. 렌즈가 바뀐 사진은 구분해 기록한다.
- 노출과 화이트밸런스를 가능한 한 일정하게 한다. 초점은 필요한 표면을 선명하게 유지하도록 확인한다. 설정을 고정한 탓에 흐릿한 사진을 계속 찍지 않는다.
- 지갑이 화면을 충분히 채우되 모서리가 잘리지 않게 한다. 거리는 초점과 표면 선명도를 기준으로 정한다. 화분·건물 강좌의 촬영 거리를 작은 지갑에 그대로 옮기지 않는다.
- 촬영 직후 확대해서 가죽 결, 봉제 구멍, 가장자리를 본다. 흔들림·초점 이탈·노출 실패 사진은 다시 찍는다. 업스케일이나 강한 선명화는 사라진 입체 정보를 복구하지 못한다.

확산광·고정 초점거리·선명도·겹침을 우선하는 원칙은 [Meshroom 촬영 문서](https://meshroom-manual.readthedocs.io/en/latest/capturing/capturing.html)와 [RealityScan 촬영 문서](https://rshelp.capturingreality.com/en-US/tutorials/takingpictures.htm)로 대조했다.

## 지갑을 촬영하는 순서

1. 지갑을 고정하고 카메라를 이동하며 중간 높이에서 한 바퀴 촬영한다. 제자리에 서서 카메라 방향만 돌리는 파노라마 촬영과 구분한다.
2. 처음 위치로 돌아와 시작 구간도 다시 겹쳐 찍는다. 경로의 끝과 시작을 연결한다.
3. 조금 더 높은 각도와 낮은 각도로 각각 한 바퀴 돈다. 이전 높이에서 보인 가죽·봉제·모서리가 다음 높이에도 겹쳐 보여야 한다.
4. 포켓 입구, 척추, 코너, 엣지코트 등을 보강 촬영한다. 전체 사진에서 접사로 갑자기 뛰지 말고 중간 거리 사진으로 이어 준다.
5. 뒤집기 전 옆면을 충분히 찍는다. 뒤집어도 같은 자세가 유지되는지 확인한 뒤 별도 세트로 촬영한다. 구부러졌다면 동일한 강체 복원으로 억지로 합치지 않는다.
6. 각 세트에서 안 보인 부위를 기록하고, 확대 확인 후 촬영을 마친다. 사진 수보다 선명한 연결과 표면의 가시 범위를 우선한다.

지갑용 시작 기준은 **이웃 사진이 약 70~80% 겹치도록 천천히 이동**하는 것이다. 이는 제품에 맞춘 보수적인 시작값이며 성공 보장값은 아니다. Meshroom은 방향에 따라 측면 60%·진행 방향 80% 이상을 안내하고, Polycam은 70~75%를 안내한다. 실제 정렬과 누락을 보고 보강한다. [Meshroom 안내](https://meshroom-manual.readthedocs.io/en/latest/capturing/capturing.html), [Polycam 안내](https://learn.poly.cam/hc/en-us/articles/27425185907348-How-to-Use-Object-Mode).

P4의 위아래로 높이를 바꾸며 도는 경로도 같은 원리를 익히는 데 유용하다. 수동 촬영은 이동을 멈추고 한 장씩 찍으므로 흔들림을 점검하기 쉽다. 자동 촬영이 항상 열등하거나 수동이 항상 우수한 것은 아니다. [P4 경로와 수동 촬영](https://www.youtube.com/watch?v=BImnzs-rR_k&t=30s).

## 사진 선택 → 정렬 → 표면 복원

다음은 프로그램 버튼 이름이 달라져도 유지되는 작업 순서다. 강좌의 RealityCapture·Blender 화면은 당시 버전이므로, 가격·계정·메뉴 위치를 현재 규칙으로 받아들이지 않는다.

| 단계 | 할 일 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| 1. 사진 준비 | 원본 보존 후 흐림·반사·형태 변화를 확인한다. 필요한 밝기·색 보정은 일관되게 한다. | 제품·자세가 하나이고 공통 무늬가 이어진다. |
| 2. 사진 정렬 | 사진을 불러와 카메라 위치와 희소 점군을 계산한다. | 카메라가 실제 촬영 경로와 비슷하게 배치된다. |
| 3. 정렬 검수 | 분리된 묶음, 누락 사진, 뒤집힌 면, 이중 윤곽을 살핀다. | 필요한 면이 연결되고 서로 다른 면이 잘못 붙지 않는다. |
| 4. 복원 범위 설정 | 지갑을 포함하는 영역을 정하고 배경·받침 범위를 줄인다. | 실제 지갑 가장자리를 잘라 버리지 않는다. |
| 5. 시험 메시 | 가벼운 설정으로 표면을 만들고 회색 화면에서 본다. | 모서리·포켓 입구·두께의 누락과 오류를 구분할 수 있다. |
| 6. 상세 메시·텍스처 | 시험 결과가 유효할 때 상세 복원과 색 합성을 한다. | 텍스처를 꺼도 형상이 납득된다. |
| 7. 원본 보관·내보내기 | 고밀도 원본을 보관하고 작업용 사본을 내보낸다. | 메시와 이미지 파일, 축·단위·스케일 기록이 함께 남는다. |

Meshroom의 흐름은 사진 입력 → 특징점 대응 → 카메라 정렬 → 깊이 추정 → 메시 → 텍스처로 이해한다. P1에서 OBJ를 Blender에 가져온 뒤 정리하는 부분은 후처리 예시다. 풀·조명·배경을 추가해 보기 좋아진 장면과 스캔 자체의 완성도를 나누어 평가한다. [P1 메시 확인](https://www.youtube.com/watch?v=k4NTf0hMjtY&t=720s), [P1 Blender 가져오기](https://www.youtube.com/watch?v=k4NTf0hMjtY&t=810s).

## 앞뒤를 합칠 때: 마스크와 공통점

P3는 윗면·아랫면을 각각 정렬하고 시험 메시에서 받침을 잘라낸 뒤, 각 원본 사진에 대응하는 물체 마스크를 생성한다. 마스크가 불러와진 것을 확인하고 양쪽 사진을 다시 정렬한다. 실패하면 두 촬영 세트에서 같은 물리적 위치를 가리키는 공통점을 지정한다. [P3 마스크](https://www.youtube.com/watch?v=3mLBL7T-zgs&t=384s), [P3 공통점](https://www.youtube.com/watch?v=3mLBL7T-zgs&t=727s).

지갑에 적용할 때는 다음을 지킨다.

- 물체를 뒤집었는데 배경은 고정돼 있으면, 배경 대응점이 잘못된 정렬을 유도할 수 있다. 배경·받침을 제외한 마스크를 점검한다. 촬영 후 임의로 잘라 이미지 크기를 바꾸는 것과 마스크를 구분한다.
- 공통점은 동일한 봉제 구멍·특이한 흠집·식별 가능한 패턴의 정확한 위치로 잡는다. 반복되는 악어무늬의 비슷한 칸을 같은 칸이라고 추측하지 않는다.
- 한 공통점에 속하는 각 사진에서 위치를 확대 확인한다. 다른 위치에 새 점을 만든 뒤 같은 점으로 간주하지 않는다. 좁은 한곳에 몰린 점보다 서로 떨어진 여러 공통점을 확인한다.
- 지갑이 휘거나 포켓이 움직였다면 공통점을 늘려도 단일 강체라는 전제가 성립하지 않는다. 자세별 결과를 참고 자료로 남기고 치수 기반 모델링으로 이어 간다.

강좌의 “공통점 두 개로 해결된 사례”를 충분조건으로 일반화하지 않는다. 공통점의 수보다 정확성·배치·사진 간 식별이 우선이며, 강한 가중치로 틀린 대응을 강제하지 않는다. [공식 공통점 안내](https://rshelp.capturingreality.com/en-US/tools/controlpoints.htm).

## 복원 실패를 고치는 순서

| 증상 | 우선 확인 | 조치 |
| --- | --- | --- |
| 사진이 여러 묶음으로 분리됨 | 겹침, 흐림, 공통 표면 부족 | 중간 시점 보강 → 불량 사진 제외 → 마스크 → 정확한 공통점 순서로 점검한다. |
| 모서리나 봉제가 이중으로 보임 | 지갑 변형, 반복무늬 오대응 | 자세별로 나누고 같은 실물의 같은 위치인지 다시 확인한다. |
| 검정 외피가 뭉개지거나 구멍 남음 | 반사, 어두운 노출, 가림 | 확산광·노출·촬영 각도를 보강한다. 더 높은 품질 설정만 반복하지 않는다. |
| 파란 내피 결이 매끈하게 사라짐 | 촬영 거리·초점·얕은 요철 | 전체 형상과 미세 재질 촬영을 나누고 실제 입체 해상도를 검증한다. |
| 텍스처는 좋지만 회색 메시가 무너짐 | 사진에 가려진 형상 오류 | 치수와 실루엣을 기준으로 재촬영 또는 재모델링한다. |
| 바닥이 막혔지만 포켓이 사라짐 | 자동 구멍 메우기 | 막힌 면을 실제 내부 구조로 간주하지 않고 포켓을 별도 설계한다. |
