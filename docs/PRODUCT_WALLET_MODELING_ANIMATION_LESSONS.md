# 가죽 지갑 모델링·리깅·광고 영상 — 실제 문제와 교훈 (2026-11-22, Claude)

사용자 요청: "지금까지 지갑 모델링 및 애니메이션에서의 문제점이나 경험을 매뉴얼로 만들어서 깃에 올려놔".

## 이 문서의 성격

- 실물 가죽 반지갑을 Blender 5.2 + Cycles로 사진처럼 만들고 접힘 리그와 광고 영상까지 만든 실제 작업(2026년 11월)에서 **생긴 문제, 원인, 고친 방법**을 정리했습니다.
- 외부 교육 자료 3개를 학습한 매뉴얼이 아니라 **실무 경험 기록**입니다. 적힌 해결법은 이 작업에서 렌더·측정으로 확인한 것이고, 다른 제품에서는 다시 확인해야 합니다.
- 제품 고유 치수·파일 위치·비공개 사진은 넣지 않았습니다. 수치는 방법을 설명하는 예시입니다.
- 관련 정본: [Blender 색인](BLENDER_SKILLS_INDEX.md), [가죽 룩데브·디노이즈](LEATHER_LOOKDEV_AND_DENOISE.md), [제품 렌더 미세 흔적](PRODUCT_SURFACE_IMPERFECTIONS.md), [가죽 천 시뮬레이션→셰이프키](BLENDER_LEATHER_CLOTH_TO_SHAPEKEY.md).

## 1. 작업 방식에서 얻은 교훈

| 문제 | 원인 | 이렇게 한다 |
| --- | --- | --- |
| 같은 형태 결함을 5번 고쳐도 실패 | "턱을 없애라" 같은 말로만 지시 | **가이드 먼저**: 사진에서 목표 단면·윤곽을 그린 별도 가이드 → 현재 모델과 겹쳐 수치 차이 표 → 확인 후 그 선에 맞춰 수정. 가이드와 실제 수정은 분리 |
| 사용자 그림과 다른 모양(둥근 머리 → U자 판)이 나옴 | 그림을 말로 대충 옮기고 숫자 몇 개로 합격 판정 | 목표 단면을 직접 그림(치수 포함)으로 만들어 원본 그림과 나란히 비교. 결과는 실제 단면을 잘라 목표 그림에 겹쳐 판정. 숫자만으로 합격 처리하지 않음 |
| 사용자에게 계속 그림·치수를 요청 | 이미 받은 사진 100여 장을 열어보지 않음 | 질문 전에 사진 목록에서 같은 장면을 찾아 직접 열고 근거 사진을 적음. 없으면 그 장면을 렌더해 표시한 그림을 보냄 |
| 원인을 먼저 말했다가 틀림("포켓이 붙어 있다") | 재 보기 전에 판단 | 원인은 측정 후에 말함 |
| 다섯 곳을 한 번에 만들다 교차·뚫림 | 범위가 큼 | 한 번에 한 부위, 아래층부터. 다른 물체는 해시로 안 바뀐 것을 확인 |
| 안 보이는 층을 정확히 파다가 4번 실패 | 안 보이는 곳에 시간 낭비 | **보이는 면만 사진과 일치**. 숨은 층끼리 겹침·교차는 허용("숨은 겹침"으로 보고). 단 보이는 면 뚫림은 0 |
| 지시하지 않은 구조(포켓 안·밖 두 겹, 층 사이 빈 공간)가 생김 | 모델링 중 발명이 그대로 이어짐 | 실물에 없는 구조는 넣지 않음. 포켓은 가죽 한 장, 층 사이 빈 공간 없음 |
| 빈 지갑 마감과 카드 상태를 같이 고치다 꼬임 | 상태가 섞임 | 빈 지갑 상태로 마감을 끝낸 뒤 카드 상태를 따로 맞춤 |

## 2. 모델링 — 크기·형태

- **사진 척도는 바늘땀 수로 잡는다.** 모델의 바늘땀 간격(3.0 mm)을 자로 썼다가 실·결 크기를 모두 약 1.25배 크게 잡았습니다. 실물 사진에서 한 변의 바늘땀 수를 세어 간격(약 2.4 mm)을 구해 자로 씁니다.
- **1:1 측정표**: 0.1 mm 눈금과 자동 검출 경계를 넣은 번호 붙은 측정 그림을 만들고, 사용자가 맞는 선을 고르면 그 값으로 만듭니다. 사진과 렌더를 같은 배율로 놓고 첫 구멍을 맞춘 뒤 같은 번호 구멍끼리 선을 그어 수평인지 봅니다.
- **실 두께 ≠ 보이는 폭.** 둥근 실을 사용자가 말한 두께(높이)로 만들면 사진보다 가늘게 보였습니다. 위에서 본 폭을 따로 재서 납작한 단면으로 만듭니다.
- **가죽 결 크기**는 작은 그림을 눈대중하지 말고 1:1에서 무늬 반복 거리를 잽니다(눈대중 1/2 축소는 실제의 0.6배였음).
- **사진 기반 높이맵은 오목·볼록이 뒤집히기 쉽다.** 부호가 임의라 두 번 뒤집혀 지적받았습니다. 매번 두 방향 접사를 사진 옆에 놓고 결이 올라온 쪽을 고릅니다.
- **"결함"으로 보인 것이 실물 형태일 수 있다.** 바깥 가죽의 바늘땀 안쪽 둔턱을 오래된 노멀맵 주름으로 보고 지웠는데, 사진 밝기 단면에 실제 둔턱이 있었습니다. 지우기 전에 사진 밝기 단면으로 확인합니다.
- **둔턱·부풂·포켓 들림은 방사형으로.** 각진 경사(빗면) 둔턱, 카드 모양 평판 들림, 입구만 띠로 든 모양은 모두 거절됐습니다. 꿰맨 선에서 0, 양쪽 끝 감쇠의 곱(예: tanh(d/9 mm)), 입구 쪽이 가장 높고 카드가 들어갈수록 시간에 따라 부드럽게. 기존 셰이프키(GAPE 등)부터 확인합니다.
- **마감칠(엣지 코트)의 부드러움은 무광이 아니라 형태에서 나온다.** 거칠기를 올려 무광으로 만든 것은 틀린 방향이었습니다. 실물은 광택이 있고 가죽보다 도드라진 둥근 단면, 길이 방향으로 고르지 않은 굴곡입니다. 일정한 짧은 물결(약 1 mm 주기)은 낮은 각도에서 주름판처럼 보이니 섞어서 씁니다.
- **마감칠 경계를 불규칙하게 하려면 가죽 재질 쪽에서.** 마감칠을 자르거나 투명하게 하면 그 밑에 숨은 패치 이음이 검은 틈으로 드러났습니다.
- **윤곽 근처를 고친 뒤에는 뚫림 검사를 돌린다.** 마감칠이 가죽을 아주 얇게(수 µm) 감싸므로 근처 정점 이동이 쉽게 뚫고 나옵니다. 외곽선을 0.1 mm마다 따라가며 안쪽 띠를 양쪽에서 광선 검사하는 도구로 개수를 보고합니다. 외곽을 따라 긴 n-각 면은 정점이 움직이면 삼각분할이 바뀌어 뚫리므로 마주보는 정점끼리 잘라 둡니다.
- **포켓 입구 마감**은 메시를 건드리지 않고 입구 띠만 높이 맵(릴리프)으로 만들었습니다. 5배 확대해 본 뒤 판단합니다(처음엔 주름선의 그림자를 띠로 잘못 읽음).
- **미세 흔적은 실물에 있는 것만.** 실물 1:1 사진이 거의 새것이면 먼지·지문·긁힘을 넣지 않습니다. 밝은 점을 어두운 점으로 잘못 읽지 않게 확대해서 밝기를 봅니다. 자세한 절차는 [제품 렌더 미세 흔적](PRODUCT_SURFACE_IMPERFECTIONS.md).

## 3. 리깅 — 접힘·카드

- **닫힌 지갑은 쐐기 모양이라 경첩이 180°보다 더 돈다.** 등(경첩) 쪽이 두꺼워서, 180° 미만으로 두면 자유단이 벌어집니다. 실물 닫힌 단면에 맞춰 각도를 풉니다.
- **재질 좌표는 쉬는 자세(rest_position) 속성으로.** 물체 좌표(Object)를 쓰면 접힐 때 결이 미끄러집니다. 경첩 띠에 새 면·새 재질을 넣을 때도 같은 규칙.
- **근접에서 등에 띠·줄이 보임(가장 오래 걸린 문제).**
  - 증상: 경첩 뼈 12개에 선형 가중치를 주니, 뼈마다 평평한 조각이 생기고 바깥 면(두께만큼 바깥)에 뼈 이음마다 오목한 홈 줄이 생김. 판(leaf) 뼈와 경첩 뼈가 만나는 곳은 살짝 거꾸로 꺾여 "턱"으로 보임.
  - 진단: 모션 블러·초점·B-bone 분할을 꺼 봐도 그대로 → 원인 아님. 닫힌 단면을 0.4 mm 줄마다 꺾임 각도로 재서 "거꾸로 꺾이는 곳 수"를 셈.
  - 실패: Corrective Smooth(쉬는 모양 기준)는 바늘땀 자리에 점 모양 패임을 만들고, 테두리 가중치로 가리면 정점이 수 mm 튀어나감. 짧은 범위 가우시안은 잔물결, 판 뼈에서 갑자기 끊으면 −9°/+8° 꺾임.
  - 해결: 경첩 뼈 + 양쪽 판 뼈 3개씩을 한 줄로 놓고, 각 뼈 중심에서 그 뼈 길이에 비례한 폭의 가우시안으로 가중치를 다시 나누고, 끝 뼈 길이만큼은 원래 가중치와 부드럽게 섞음. 바깥 면의 단은 10 mm 폭으로 완만하게 이어줌. 결과: 거꾸로 꺾임 0, 꺾임이 0°→3.8°로 고르게 증가, 가장 많이 움직인 점 0.3 mm 미만.
  - 지갑 원본 파일은 저장하지 않고 장면 스크립트에서 실행 때만 적용.
- **셰이프키가 있는 메시는 정점 좌표만 바꾸면 아무 변화가 없다.** 모든 키 블록(Basis 포함)에 같은 변화량을 더해야 합니다.
- **카드는 위 카드부터 뺀다.** 아래 카드가 위 카드에 걸리므로 순서를 지키고, 뺀 카드는 렌더에서 숨김(값 0이 "슬롯 바로 밖"이라 다른 카드와 겹침).
- **Blender 5.2 지오메트리 노드 입력**: 값은 `md.properties.inputs[식별자]['value']`, 드라이버 경로는 `modifiers["이름"].properties.inputs.Socket_1.value`. 지오메트리 노드 곡선 출력은 이 장면 Cycles에서 아무것도 안 보였음 → 관(Curve to Mesh)으로 출력.

## 4. 광고 영상 — 카메라·조명·장면

| 증상 | 원인 | 고친 방법 |
| --- | --- | --- |
| 영상에서 두 번 번쩍임 | 카메라·조명 키가 일정(CONSTANT) 보간인데 모션 블러 셔터가 프레임 **가운데**라, 장면 첫 프레임에 앞 장면 카메라가 섞임 | 셔터 위치를 **시작(START)** 으로. 일정 보간 카메라는 그 프레임 값을 유지하고, 움직이는 지갑만 블러 |
| 한 프레임만 반사 모양이 바뀜 | 막대 조명이 목표 **바로 위**를 지나는 프레임에 `to_track_quat('-Z','Y')`가 퇴화해 90° 돌아감 | 막대의 긴 변 방향을 고정 기준축으로 직접 행렬을 만들어 조준 |
| 한 프레임만 초점이 다른 곳 의심 | 프레임마다 광선으로 초점 거리를 잡음 | 장면 안에서 앞뒤 5프레임 가운뎃값으로 다듬기(이번엔 원인이 아니었지만 안전장치로 둠) |
| 근접에서 지나가는 반사광이 안 보임 | 빛을 카메라 쪽에 둠 | 반사는 **거울 방향**(면 기준으로 카메라 맞은편)에 빛이 있어야 보임 |
| 사선 반사광이 밝은 얼룩이 됨 | 거친 가죽은 반사가 세로(깊이) 방향으로 늘어나 40° 기울이면 퍼짐 | 약 25°로만 기울이고 세기를 낮춤 |
| 근접 반사광 범위가 화면 1/5만 움직임 | 빛의 각도 범위가 좁음 | 빛을 곡면 둘레로 크게 돌림. 시작 각도는 윗면이 하얗게 날아가지 않게 |
| 먼 바닥에 회색 띠·사각형 | 바닥 광택이 HDRI 소프트박스를 비춤 | 지갑에서의 거리로 바닥 반사를 줄임(가까이만 남김) |
| 펼친 지갑 아래 갈색 얼룩 | 바닥 반사에 지갑 겉면이 흐릿하게 비침(바닥 반사 끄면 사라짐으로 확인) | 펼치기 시작할 때 바닥 반사를 서서히 0으로 |
| 검은 배경에서 "떠오름"이 안 읽힘 | 비교할 기준이 없음 | 사용자 판단: 띄우지 않고 바닥에 두고 스팟 라이트로 대신 |
| 안개 빛줄기가 배경 전체를 갈색으로 덮음 | 카메라가 위에서 빛 원뿔 안을 내려다봄 | 내려다보는 구도에는 안개를 쓰지 않음. 빛줄기를 보이려면 옆에서 보는 구도가 필요 |
| 스팟 아래 안쪽 가죽이 번쩍임 | 스팟이 카메라 거울 방향 뒤에 있음 | 스팟을 옆 뒤(약 60°)로 돌림 |
| 광원 막대가 화면·바닥에 흰 사각형 | 광원이 카메라·반사에 보임 | 카메라에 안 보이게 + 빛 연결로 지갑에만 비춤 |
| 지갑이 어두움 | 배경을 검게 두려다 주 조명 부족 | 지갑에만 비추는 앞쪽 부드러운 빛(빛 연결) + 노출 조정 |

- **번쩍임은 숫자로 찾는다.** 모든 프레임의 평균 밝기와 앞 프레임과의 차이를 재서, 장면 경계가 아닌 곳에서 한 프레임만 튀는 곳(앞뒤 평균과 차이)을 찾습니다. 사람이 영상에서 본 "두 번"을 이 방법으로 정확한 프레임에 연결했습니다.
- **장면 길이를 바꿀 때는 시간 맵을 쓴다.** 장면표가 프레임 번호로 짜여 있으면, 새 프레임을 옛 프레임으로 바꾸는 함수를 하나 두고 장면·지갑 움직임·조명 페이드·초점 구간이 모두 그 값을 쓰게 하면 뒤 장면을 건드리지 않고 한 장면만 늘릴 수 있습니다.
- **빠른 시험 → 전체**: 문제 프레임만 저해상도로 렌더해 비교표로 확인 → 바뀐 구간만 다시 렌더 → 영상으로 묶기. 바뀌지 않은 프레임은 재사용.
- **근접 반사광은 근접 2개 중 1개만**(사용자 판단). 모든 근접에 움직이는 빛을 넣으면 산만합니다.

## 5. 환경·도구

- **렌더는 GPU로.** 파일과 환경설정이 CPU로 되어 있어 느린 것을 다른 원인으로 잘못 진단한 적이 있습니다. 시간·성능을 말하기 전에 장면 장치와 계산 장치를 확인하고, 스크립트에서 실행 때만 GPU를 켭니다(설정 저장 안 함).
- **공장 초기화 금지.** `read_factory_settings`로 시험 장면을 만들다 확장 프로그램 파이썬 패키지가 치워졌습니다. 기존 파일을 열고 물체를 지우는 방식으로 대신합니다.
- **추천 전에 호환 확인.** 렌더러·애드온을 추천하기 전에 지원 Blender 버전과 내장 파이썬 버전(Blender 5.2 = 3.13)을 확인합니다. 확인 없이 말했다가 사용자가 설치한 뒤 못 쓴 일이 두 번 있었습니다.
- **소리는 들을 수 없다.** 효과음 위치는 프레임별 음량(dB)으로만 확인하고, 좋고 나쁨은 사용자 귀로 판단합니다. 장면 시간이 바뀌면 소리 배치도 다시 계산합니다.
- **지갑 원본 파일은 저장하지 않는다.** 광고용 수정(가중치·단 완만화·재질 광택 등)은 장면 스크립트가 실행 때만 적용해, 원본과 다른 장면에 영향을 주지 않습니다.

## 6. 검수 체크리스트

1. 목표 단면·윤곽 가이드가 있고, 결과를 같은 조건 단면 겹침으로 확인했는가.
2. 사진 척도를 바늘땀 수로 잡았는가. 1:1에서 비교했는가.
3. 높이맵 오목·볼록 두 방향을 사진 옆에서 골랐는가.
4. 들림·부풂이 꿰맨 선에서 0인 방사형인가.
5. 윤곽 근처 수정 뒤 마감칠 뚫림 검사 개수가 0인가.
6. 근접 렌더(등·이음·입구)에서 띠·턱·홈 줄이 없는가. 단면 꺾임에 거꾸로 꺾이는 곳이 없는가.
7. 셰이프키가 있는 메시는 모든 키에 같은 변화를 넣었는가.
8. 영상 전체 프레임 밝기 측정에서 한 프레임 튐이 없는가(장면 경계 제외).
9. 반사·광원 사각형·바닥 얼룩이 없는가. 조명은 카메라에 안 보이는가.
10. 렌더 장치가 GPU인가. 원본 파일·환경설정을 저장하지 않았는가.
11. 사용자에게 보이는 글은 모두 한국어인가.
