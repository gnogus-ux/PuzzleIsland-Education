# 눌림·선택·처리 결과를 구분하는 버튼 상태

2026-11-09 Android Views·WAI-ARIA·WCAG 공식 자료의 필요한 절을 읽고 교차 확인한 재사용 설계 매뉴얼이다. 문서 작성자는 제품 코드·앱·폰·서버를 조작하지 않았다. 아래 공식 설계와 후속 제한 실기 관찰은 구분한다. 일부 실기 통과가 전체 기능·접근성 적합 판정을 뜻하지 않는다. 기존 원본·초안·저장본·검수 후보를 보존하고 UI 표시 범위만 다룬다.

## 후속 제한 실기 — 이 PC와 S24의 버튼 표시

독립 검수 담당의 최종 저장 기록을 작성자가 대조했다. 수정 APK는 기존 Windows SDK의 실제 `--replace-version` 및 최종 badging으로 versionCode3 / r17-ui1을 확인했고, 기존 서명키를 보존한 v2/v3·같은 서명 업데이트 설치가 완료됐다. 설치 버전과 편집기 로드를 확인한 뒤의 화면만 UI 근거로 사용했다. 설치 직후 로딩 중 흰 화면 캡처는 성공 화면 근거에서 제외했다. 화면·사진·작업 이름·개인 경로·키/산출물 해시는 공개하지 않는다.

| 구분 | 확인한 범위 |

실제 결과 파일 내보내기 성공·그 SAF 취소·저장 실패 주입은 이번 시험에서 하지 않았다. TalkBack·글씨 크기 변경·기기 회전·다른 기종·전체 WCAG 준수도 미검증이다. 표시만 확인하기 위해 실제 점을 새로 수정하거나 가져오기/PC 적용·전송을 하지 않았다.

## 1. 먼저 버튼의 의미를 나눈다

모든 버튼에 마지막 클릭 표시를 남기지 않는다. 실제 화면/편집 모드와 단발 명령을 구분한다.

| 의미 | 유지할 표시 | 표시가 확정되는 근거 |
|---|---|---|
| 손가락/마우스로 누르는 중 | 순간 눌림·ripple·테두리 반응 | 현재 입력 접촉. 선택이나 성공이 아님 |
| 현재 화면·지속 편집 모드 | 진한 배경 + 명확한 체크/현재 표시 + 프로그램 상태 | 실제 활성 화면/모드 |
| 단발 명령 접수 | 짧은 눌림 반응, 필요하면 처리 중 문구 | 클릭을 받았거나 작업을 시작함 |
| 작업 진행 | 처리 중·진행 표시, 관련 재실행만 잠시 제한 | 아직 결과를 기다림 |
| 작업 완료 | 실제 완료 범위를 적은 문구/아이콘 | 해당 작업의 확인된 결과 |
| 실패·사용자 취소 | 실패 원인/취소와 보존 상태 | 실패/취소 결과. 완료로 표시하지 않음 |
| 비활성 | 사용 불가 형태와 이유, 실행 차단 | 현재 기능을 실행할 수 없음 |

예를 들어 측정/입구 같은 현재 화면과 점 조작/화면 이동 같은 지속 모드는 체크를 유지한다. 작업 열기·기기 저장·결과 저장·연결 요청은 단발 동작이다. 이 버튼의 체크를 현재 화면의 체크와 같은 뜻으로 쓰지 않는다. “버튼이 눌렸다”와 “실제 저장됐다”는 별개의 상태다.

## 2. 색 외의 단서와 실제 상태를 함께 바꾼다

[WCAG 색 사용](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)은 의미를 색 하나에만 맡기지 않도록 한다. 지속 모드에는 진한 배경과 대비되는 체크, 필요한 현재 상태 문구를 함께 둔다. 체크/모양/텍스트는 색을 구별하기 어려워도 남아야 한다. 선택·키보드 초점·hover·순간 눌림의 모양을 따로 설계하고, 초점을 옮겼다는 이유로 실제 선택이 사라지지 않게 한다.

실제 상태를 한 곳에서 정하고 모든 버튼·상태 문구·접근성 값을 그 상태로부터 갱신한다. 화면 재렌더 뒤 CSS만 지워지거나 화면과 다른 버튼이 체크되지 않게 한다. 상호 배타 모드는 정확히 하나만 현재 상태를 가지며, 명시적으로 모드가 없는 화면에서는 체크도 없는 상태를 허용한다. 비활성 상태가 현재 화면 표시까지 잘못 지우지 않도록 조합을 확인한다.

## 3. Android Views

[State list 문서](https://developer.android.com/guide/topics/resources/drawable-resource#StateList)는 `state_pressed`, `state_selected`, `state_activated`, `state_enabled`를 구분한다. pressed는 접촉 중이고 selected는 focus와 다르다. activated는 지속된 활성 선택의 표현에도 사용된다. 기존 위젯에 맞는 selected/activated 중 하나의 상태 모델을 일관되게 사용하고 실제 현재 화면에 연결한다.

selector는 위에서 아래로 **처음 일치하는 항목**을 사용한다. 기본 항목은 마지막에 두고 disabled·선택된 채 눌림·선택·일반 눌림 등 필요한 조합의 우선순위를 확인한다. 배경뿐 아니라 글자/아이콘도 해당 상태에서 읽히게 한다. 상태가 바뀔 때 padding/최소 크기가 달라져 버튼이 흔들리지 않게 한다. 체크를 별도 그림으로 보여 주되 버튼의 기본 이름은 안정되게 유지한다.

[View API](https://developer.android.com/reference/android/view/View)는 `setSelected`와 focus의 차이, enabled, 접근성 상태 설명을 제공한다. `setStateDescription`은 API30부터이므로 지원 버전을 확인하고 하위 버전에서 무조건 호출하거나 새 AndroidX 의존성을 가정하지 않는다. 상태 설명은 “현재 화면”, “점 조작 선택됨”처럼 실제 상태를 짧게 전달한다. 기본 위젯의 상태 의미와 텍스트를 활용하고, TalkBack에서 같은 설명을 두 번 읽거나 시각적 체크 문자만 읽지 않는지 실제 확인한다.

일반 버튼의 기본 click/pressed 처리를 유지한다. 맞춤 touch 처리가 있다면 [MotionEvent ACTION_CANCEL](https://developer.android.com/reference/android/view/MotionEvent#ACTION_CANCEL)에서 입력 후보·순간 눌림을 정리하고 실행/선택 확정을 하지 않는다. 새 권한·앱 설치·보안 설정을 상태 표시의 해결책으로 추가하지 않는다.

## 4. HTML 버튼과 화면 내비게이션

[WAI 버튼 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/button/)에 맞춰 지속 토글 버튼만 `aria-pressed="true|false"`로 표현한다. 점 조작/이동처럼 버튼으로 구현한 배타 모드는 실제 모드에 따라 각 값을 함께 갱신하고 시각적 활성 클래스와 일치시킨다. toggle의 접근 이름은 상태 전환 때 바꾸지 않는다. 체크 장식은 필요한 경우 접근 이름에서 제외하고 상태는 ARIA로 전달한다.

현재 페이지/화면의 내비게이션은 [aria-current](https://www.w3.org/TR/wai-aria-1.2/#aria-current)의 해당 의미를 사용한다. 실제 tablist/tab 위젯이라면 `aria-selected`와 그 키보드 규칙을 따른다. 일반 버튼에 tab 역할만 붙여서 상태를 흉내 내지 않는다. 저장 버튼에는 지속 토글인 것처럼 aria-pressed를 붙이지 않는다. HTML 기본 button·키보드 Enter/Space 활성화·보이는 focus를 보존한다.

가능한 경우 HTML `disabled`를 실제 실행 불가 상태에 연결한다. [aria-disabled](https://www.w3.org/TR/wai-aria-1.2/#aria-disabled)라는 의미만 설정해 놓고 click/키보드 동작은 계속 실행되게 만들지 않는다. `aria-busy`는 해당 영역의 갱신 중 상태이며 실제 성공 표시가 아니다. busy를 해제할 때도 실제 결과를 별도 문구로 알린다.

## 5. 단발 명령의 처리 중·완료·실패

클릭 즉시 “저장 완료”를 표시하지 않는다. 작업 시작 시 “저장 중…”을 보여 주고 중복 요청을 필요한 범위에서 막은 뒤 실제 파일 기록·읽기 확인·서버 응답 등 해당 작업의 완료 조건을 만족할 때만 완료로 바꾼다. 결과가 오지 않았거나 확인할 수 없으면 진행/미확인으로 남긴다.

기기 초안 저장, 사용자 선택 파일로 결과 내보내기, PC 업로드 접수, PC 명시 반영은 각각 다른 완료다. 버튼의 결과 문구도 그 범위를 명시한다. 사용자 파일 선택 취소는 실패/성공과 구별하고 초안은 보존한다. 실패 후에도 저장되지 않은 입력과 현재 화면/모드는 남아야 하며 다시 시도할 수 있게 한다.

[WCAG 상태 메시지](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)는 중요한 성공·대기·진행·오류를 focus 이동 없이 보조기술로 전달하는 근거다. 웹은 적절한 `role="status"`/live region과 필요한 오류 안내를 사용하되 매번 강한 alert나 focus 이동을 강요하지 않는다. Android에서는 실제 위젯/상태 설명과 접근성 안내의 중복 여부를 검수한다. 모든 화면 재그리기를 성공 메시지로 방송하지 않는다.

## 6. 취소·지연 응답·회전·탭 이동의 일치

[Pointer Cancellation](https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation.html)은 일반 명령을 down이 아닌 click/up으로 확정하고 취소 기회를 주는 근거다. `pointercancel`·`touchcancel`·캡처 상실·창 비활성화에는 임시 pressed만 정리하고 선택/완료로 남기지 않는다. 이미 시작된 비동기 저장은 입력 접촉 취소와 별개이므로, 입력 취소만 보고 실제 쓰기까지 취소됐다고 표시하지 않는다.

화면 전환이나 모드 적용이 실패하면 실제 화면이 유지되는 한 체크도 그 화면에 남긴다. 전환 요청 중에는 목표를 진행 표시할 수 있지만 현재 화면 체크를 완료처럼 앞당기지 않는다. 실제 상태 변경 후 렌더가 끝나면 체크·프로그램 상태를 함께 맞춘다.

이전 작업/이전 탭의 지연 응답이 새 화면의 저장 완료를 덮어쓰지 않게 요청과 대상 작업을 대조한다. busy/오류 정리와 버튼 재활성화도 같은 작업의 결과에만 적용한다. 회전·재생성·재열기 시 실제 복구된 화면/모드·dirty/저장 상태로 표시를 다시 만든다. 순간 pressed와 처리 전 클릭 기록은 지속 저장하지 않는다. 저장하지 않은 초안·실제 저장/취소 정책은 기존대로 보존한다.

## 7. 좁은 화면·큰 글씨·대비·화면읽기 검수

[Android 접근성 안내](https://developer.android.com/guide/topics/ui/accessibility/apps)는 터치 대상 48×48dp 이상을 권장하고 작은 글자는 4.5:1, 큰 글자는 3:1 대비를 구분한다. 이는 고정 높이 안에 글자를 억지로 줄이라는 뜻이 아니다. native View를 개선하기 위해 Compose를 새로 도입할 필요도 없다.

웹에서는 [텍스트 확대](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)의 200%와 [reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)의 일반 세로 콘텐츠 320 CSS px 기준을 참고해 체크/이름/상태가 잘리거나 버튼이 겹치지 않는지 확인한다. 캔버스의 2차원 예외를 도구 모음 전체에 무조건 적용하지 않는다. Android는 기기 큰 글씨 설정과 좁은 세로/가로 화면에서 별도 확인한다. 웹 수치를 native dp와 같은 단위로 복사하지 않는다.

[비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)는 필요한 활성 상태 단서가 인접 색과 3:1로 구별되는 근거와 비활성 예외를 설명한다. 선택 체크/테두리·focus가 높은 대비 환경에서도 남는지 확인한다. disabled의 기준 예외가 사용 불가 이유를 숨길 근거는 아니다.

최소 검수는 정상 선택/해제와 상호 배타성, 길게 누른 뒤 밖으로 이동/취소, 비활성/중복 클릭, 성공·지연·실패·파일 선택 취소, 전환 실패, 재렌더·회전·탭 이동 후 복구, 큰 글씨·좁은 폭·높은 대비, 키보드와 TalkBack의 이름/역할/현재 상태 읽기다. 화면 표시와 실제 모드/저장 결과를 함께 대조한다. 에뮬레이션·정적 화면 확인·실제 기기·화면읽기 결과는 각각 기록한다.

공식 자료의 설계 지원과 위 네이티브12/웹4 제한 실기만 확인했다. 이 범위 밖 실제 저장 실패 주입·결과 내보내기 성공/취소·회전·큰 글씨·TalkBack·대비 측정·접근성 준수는 **미검증**이다. [자료별 학습 범위](../reports/ExternalLearning/20261109_UI_BUTTON_STATE_FEEDBACK_STUDY.json)를 함께 확인한다.
