# 지갑 패널의 넓은 곡면과 포켓 기준 높이 조정

2026-11-04 Codex 작성. 봉제 경계를 고정한 가죽 패널의 큰 곡면을 넓게 분배하고, 포켓의 볼록한 형상과 입구를 보존하며 기준 높이를 낮추기 위한 비물리적 형상 설계 절차다. **높이 진폭, 곡률 분포, 기준면 이동, 각도별 키 영향값을 따로 설계한다.** 제품별 실제 Guide와 동일 조건 검수가 필요하며, 아래 함수는 적용 후보이지 실측 가죽이나 보편 합격값이 아니다.

[겹 구조와 여유 길이](WALLET_LAYERED_SHELL_VOLUME.md), [기본 지갑 모델링](WALLET_MODELING.md), [가죽 반사 검수](LEATHER_LOOKDEV_AND_DENOISE.md)를 먼저 읽는다. 공식 Blender 5.2 문서의 기능 근거와 실제 열람 범위는 [학습 기록](../reports/ExternalLearning/20261104_WALLET_CURVATURE_DRIVER_STUDY.json)에 있다. 이 문서 작성에서 Blender 실행·씬 변경·실기 검증은 하지 않았다.

## 1. 대상과 좌표를 먼저 고정한다

실제 Guide에는 수정할 사각 영역, 고정 봉제 경계, 자유 입구, 보존할 모서리, 목표 단면과 이동 방향을 표시한다. 중앙 최고점만 지정하지 말고 가로·세로 단면 여러 곳에서 어디부터 올라오고 어느 폭에 걸쳐 낮아지는지 표시한다. 원본 보존 파일과 Guide, 실제 수정 후보는 분리한다. [공통 가이드와 점유 규칙](COMMON_WORK_RULES.md)을 따른다.

| 항목 | 사전에 기록할 기준 |
|---|---|
| 높이 | 월드 Z, 물체 로컬 축, 본판 기준면 법선 중 어느 방향의 높이인지 |
| 사각 영역 | 본판의 변형 전 chart 좌표와 경계 정점 대응, 필요시 모서리 둥근 영역의 별도 처리 |
| 경계 | 봉제 고정 구간과 자유 입구를 구별한 집합, 경계에서 복귀할 폭 |
| 포켓 보존 | 입구 간격·입구 곡선·안팎 단면·기존 Depth/Mouth/slack 키의 역할 |
| 동행 파트 | 덧댐·뒷면·두께·엣지코트·실이 각각 어떤 표면과 경계를 따라야 하는지 |
| 상태 | 각도 정의와 기존 키값, modifier 순서, 대상 물체의 변환·부모·제약 |

본판의 변형 전 2차원 기준 좌표를 여기서는 chart라고 부른다. 텍스처 UV와 반드시 같지 않다. 평면 본판의 기준점 `o`, 직교 단위축 `e_u, e_v`, 법선 `n`으로 위치를 분해하면 높이는 `h=(p-o)·n`이다. 사각 영역을 정규화한 `u,v`는 0~1이고, 실제 거리와 미분은 가로·세로 길이 `L_u,L_v`를 반영한다. 접힌 상태의 월드 XY로 영역을 다시 판정하면 마스크가 이동할 수 있으므로 변형 전 대응을 유지한다.

셰이프키 좌표와 본판 chart 좌표를 그대로 섞지 않는다. 물체 로컬 위치는 해당 물체의 월드 행렬을 통해 본판 기준으로 옮겨 비교하고, 만든 목표 위치를 역변환해 원래 물체의 로컬 키 좌표로 돌린다. 비균일 Scale이 있으면 길이와 법선 변환을 따로 취급한다. 기존 리그의 Scale을 일괄 적용해서 해결하지 않는다. 이 단순 chart는 평면 기준에 대한 설계안이며 이미 휘어진 본판의 전역 매개화나 모든 접힘 상태의 법선을 자동 해결하지 않는다.

## 2. 낮추는 높이와 넓게 퍼지는 곡면을 나눈다

높이장을 `h(u,v)=h_base(u,v)+A F(u,v)`로 나누면 `A`는 높이 진폭이고 `F`는 분포다. 같은 `F`에서 `A`만 줄이면 원래 좁은 봉우리의 분포가 그대로 남는다. 넓은 사각 경계부터 올라오는 형태를 만들려면 먼저 `F`의 지지 영역과 어깨 폭, 중앙의 곡률을 바꾸고, 그 다음 `A`로 최고 높이를 맞춘다. 기존 높이의 절반이나 키값 0.5는 이 두 목표를 한꺼번에 만족시키는 공식이 아니다.

`h_base`는 보존할 기저 형상으로 명시한다. 없애려는 기존의 좁은 봉우리까지 기저에 남겨 놓고 새 `A F`를 더하면 봉우리가 중복된다. 기존 혼합과 목표 높이장의 차이를 4절의 잔차로 작성해 기존 키 구조를 보존한다.

다음은 경계와 두 번의 미분을 부드럽게 연결하기 위한 자체 설계 예다. Blender의 완성 지갑 예제나 권장 수치로 인용하지 않는다.

```text
S(t) = 0                         t <= 0
     = 6t^5 - 15t^4 + 10t^3     0 < t < 1
     = 1                         t >= 1

R(u,a) = S(u/a) S((1-u)/a)       0 < a <= 0.5
F(u,v) = R(u,a_u) R(v,a_v)
         [1 - eta ((2u-1)^2 + (2v-1)^2)/2]   0 <= eta < 1
```

`S'(t)=30t²(t-1)²`, `S''(t)=60t(2t²-3t+1)`이므로 양 끝에서 값·1차·2차 미분이 바깥 상수 구간과 이어진다. 따라서 매끄러운 chart에서 이 변위장을 영역 밖의 0 변위와 붙이면 경계의 변위와 그 첫 두 미분이 0이다. 기저 표면이 기울어져 있으면 **추가 변위의 미분이 0**이라는 뜻이며 완성 표면의 기울기가 0이라는 뜻은 아니다.

`a_u L_u`, `a_v L_v`가 각각 어깨의 실제 폭이다. 아주 작은 값은 넓은 중앙 평탄부와 급한 가장자리 전이를 만들 수 있다. 넓게 부드럽게 올라오려면 가이드 단면에 맞춰 충분한 어깨 폭을 확보한다. `eta=0`이면 중앙 평탄부가 생길 수 있고, `eta>0`은 그 구간에도 완만한 중앙 굽음을 준다. 대칭 사각 영역과 이 매개변수 범위에서는 중앙 `F=1`, 경계 `F=0`이다. 비대칭 봉제·둥근 경계·한쪽 입구에는 이 식을 그대로 덮어씌우지 않고 실제 경계에 맞는 마스크를 설계한다.

이 식의 높이장은 비음수지만 모든 단면이 엄밀한 수학적 볼록 곡선인 것은 아니다. 봉제 경계로 매끄럽게 복귀하는 어깨에는 변곡이 생길 수 있다. 여기서 볼록한 포켓이란 제품 외관상의 볼록한 주 형상을 말하며, 전역 양의 곡률을 보장한다는 뜻이 아니다. 메시가 거칠면 연속 함수의 C2 성질도 그대로 재현되지 않는다. 필요한 면 흐름은 키 제작 전에 가이드로 정하고 기존 정점 대응을 보존한다.

## 3. 포켓 내부 형상을 함께 낮추고 경계에서 복귀한다

낮추기 전 실제 혼합 형상을 `q_i`, 한 기준 방향의 단위벡터를 `n`, 낮출 거리를 `d>0`라 하자. 내부에서 1, 고정 봉제 경계에서 0인 마스크 `W_i`로 다음 목표를 설계할 수 있다.

```text
q_target,i = q_i - d W_i n
```

`W=1`인 내부는 모두 같은 벡터로 이동하므로 그 내부 정점끼리의 상대 위치와 거리는 보존된다. 내부 기준면도 함께 `d`만큼 내리면 그 기준면에 대한 볼록한 높이 분포가 유지된다. 반면 본판에 대한 절대 높이와 내부 공간은 줄어들 수 있다. 각 정점의 서로 다른 법선 방향으로 움직이면 이 강체 이동 성질이 성립하지 않는다.

경계 `W=0`은 그대로 남고, 중간 복귀 구간은 변형된다. **고정 경계를 포함한 전체 포켓을 강체 Z이동하면서 그 경계도 같은 자리에 두는 것은 `d=0`이 아닌 한 불가능하다.** 내부 형상 보존과 경계 복귀 사이의 타협을 Guide에 명시한다. 자유 입구가 움직여도 되는지와 입구 양 끝이 봉제되는지는 따로 판정한다. 입구 전체를 움직여야 할 때 끝점을 고정하면 입구 곡선까지 완전히 강체 보존할 수 없다.

1. 승인 단면에서 낮출 기준점과 기준 방향을 정한다. 최고점만 맞추지 말고 입구·중앙·양옆의 목표 높이를 확인한다.
2. 기존 Depth/Mouth/slack의 혼합으로 만든 내부 볼록 형상을 출발점으로 삼는다. 기준점이 `W=1`이면 그 점의 높이 차이로 `d`를 정할 수 있다. 여러 점의 요구가 다르면 별도 재형상 문제로 기록한다.
3. 형상과 입구를 보존할 내부는 `W=1`, 고정 봉제 경계는 `W=0`으로 둔다. 복귀 폭을 실제 거리로 표시하고 전이의 기울기·곡률을 확인한다.
4. 두께를 가진 앞뒷면·입구 단면과 동행 덧댐에 같은 공간 변위를 대응시킨다. 서로 다른 로컬 Z나 각각의 bounding box 기준 마스크를 복사하면 이음새가 벌어질 수 있다.
5. 본판과 포켓 사이 간격, 입구가 열린 상태, 두께와 봉제 대응을 허용된 정지 상태에서 확인한다. 보존된 내부 거리만으로 전체 길이·표면적·밀폐 체적·물리적 수용량 보존을 주장하지 않는다.

모든 좌표의 Z를 0.5배 하면 원점·기준면에 대한 압축이 되고 내부 볼록 깊이와 두께도 달라질 수 있다. 모든 상대 키값을 0.5배 하면 Basis에 대한 변위만 줄어들어 Depth/Mouth 등의 작동도 달라진다. 어느 쪽도 위의 내부 기준면 이동과 동등하지 않다. 실제 높이 수 mm와 마스크 폭은 제품별 적용값으로 별도 기록한다.

## 4. Relative shape keys의 합산을 확인한다

공식 [Shape Keys Panel](https://docs.blender.org/manual/en/5.2/animation/shape_keys/shape_keys_panel.html)은 키가 위치 스냅샷이며 실제 변위는 Relative To 키를 빼서 계산한다고 설명한다. 기본적인 상대 키의 혼합을 modifier 이전 좌표에서 다음과 같이 정리할 수 있다.

```text
q_mix,i = B_i + sum_k value_k mask_k,i (K_k,i - R_k,i)
```

`B`는 Basis, `K_k`는 각 키의 저장 좌표, `R_k`는 그 키의 Relative To 좌표, `mask`는 해당 키의 정점 가중치다. 키 음소거·표시용 pin/단독 보기·실제 평가 상태도 함께 확인한다. 모든 키가 Basis 기준이고 마스크가 없으면 `B + Depth값×(Depth-B) + Mouth값×(Mouth-B) + slack값×(slack-B) + 새키값×(새키-B)`다. 합산값은 1로 자동 정규화되는 교대 비율이 아니다.

현재 혼합 형상을 복제해 새 Basis 기준 키로 만들고 기존 키도 그대로 켜면 기존 변위가 중복될 수 있다. 특정 기준 상태의 목표 `q_target`을 맞추려면 먼저 기존 키만의 `q_oldmix`를 계산하고, 보정 잔차 `Delta=q_target-q_oldmix`를 새 키로 설계한다. 새 키의 Relative To가 Basis, 값이 1, 유효 마스크가 1인 구간에서는 `K_new=B+Delta`다. 새 키값이 0이면 기존 혼합이 그대로 복원되어야 한다.

잔차에 공간 마스크를 이미 곱했다면 키 Vertex Group에서 같은 마스크를 다시 곱해 복귀 폭을 바꾸지 않는다. 반대로 Vertex Group에서 마스킹하려면 저장 변위와 경계값을 그 정의에 맞춰 설계한다. 0에 가까운 가중치로 목표 잔차를 무조건 나눠 거대한 저장 변위를 만드는 방식은 피한다. 마스크 0인 곳의 비영 목표는 해당 키로 달성할 수 없다.

이 잔차는 작성한 기준 혼합 상태에서의 해다. 각도나 기존 Depth/Mouth값이 달라질 때도 같은 보정을 적용할지는 별도 확인한다. Relative To가 Basis가 아닌 키를 임의로 Basis 기준으로 해석하거나 바꾸지 않는다. [Workflow](https://docs.blender.org/manual/en/5.2/animation/shape_keys/workflow.html)의 키 단독·혼합 보기와 함께 실제 `relative_key`, `value`, 마스크, mute를 기록한다. 같은 문서에서 New Shape from Mix라는 이름을 쓰지만 Panel 문서는 New Combined를 표기하므로 메뉴 이름을 추정해 자동 실행하지 않는다.

## 5. UV와 두께와 동행 파트를 보존한다

셰이프키는 기존 정점 위치를 저장하며 정점 수·연결은 공통이다. 기준 인덱스와 토폴로지를 유지하고 키 작성 중 재메시·정점 합치기·순서 변경으로 대응을 깨지 않는다. UV 데이터가 그대로여도 변형된 표면의 길이·면적이 달라지면 결의 물리 크기와 방향은 달라질 수 있으므로 대표 체커와 실제 재질을 따로 확인한다.

두께가 modifier라면 평가 순서와 결과 간격을 보고, 이미 닫힌 두께 메시라면 앞뒤 대응을 확인한다. 본판의 기준 법선으로 이동한 경우와 실제 표면 법선에 따른 두께 생성은 구별한다. 정점별 마스크가 달라지는 복귀 구간에서는 단순히 양면을 같은 식으로 처리해도 정확한 두께 보존이 보장되지 않는다. [Solidify 주의사항](WALLET_MODELING.md#3-외피와-등-가죽의-형태를-만든다)을 함께 따른다.

덧댐·실·엣지코트는 공유 경계·부착 위치의 대응을 확인한다. 단순 부모 지정, 키 이름 일치 또는 모든 물체에 같은 값 입력만으로 표면 동행이 검증되지는 않는다. 원래 UV·재질·기존 키·애니메이션 연결을 보존하고 지정하지 않은 부위로 수정 범위를 넓히지 않는다.

## 6. 기울기와 곡률과 반사띠를 함께 비교한다

C1은 위치와 첫 미분, C2는 그에 더해 둘째 미분이 이어지는 조건이다. 매끄러운 기저 표면의 변위가 경계에서 값·첫 두 미분 0이면 기저와의 접속을 보존하기 쉽다. 그러나 C2라는 이름만으로 반사 외관을 통과시키지 않는다. 실제 하이라이트는 표면 법선의 분포, 곡률, 거칠기, 광원의 크기·방향, 시점에 함께 좌우된다.

높이 변화가 `d`, 복귀 폭이 `w`인 동일한 모양의 전이라면 미분 크기의 척도는 기울기 `d/w`, 곡률 관련 둘째 미분 `d/w²`처럼 커진다. 이는 미분의 축척 관계이며 실제 곡률의 정확한 값이나 합격식은 아니다. 평면 단면 그래프의 곡률은 `h''/(1+h'^2)^(3/2)`로 기울기도 포함한다. 좁은 복귀 폭에서는 C2 함수라도 큰 기울기·곡률이 한 줄에 몰려 반사띠가 생길 수 있다.

1. 동일 카메라·해상도·재질·색관리·노출·광원·샘플 조건을 저장한다. 면광원 위치·방향·형상·두 크기·출력·Normalize도 기록한다. [Light Objects](https://docs.blender.org/manual/en/5.2/render/lights/light_object.html)는 광원 크기와 정규화 조건을 구별한다.
2. 같은 기준 단면에서 전후 높이, 첫 미분의 변화, 둘째 미분이 집중되는 구간을 비교한다. 정점 간격을 반영하고 비균일 간격에 단순 등간격 차분을 쓰지 않는다. 수치 허용오차는 단위와 샘플 간격을 함께 남긴다.
3. 동일 시점의 solid/wire로 봉제·윤곽·면 분포를 비교하고, 허용된 경우 같은 조명의 중립 반광 재질로 큰 면의 하이라이트를 비교한다. 요철을 줄인 대조는 전후 모두 같은 조건으로 만든다.
4. 승인 재질에서도 같은 조건으로 비교한다. 반사띠를 감추려고 후보에서만 광원이나 roughness를 바꾸지 않는다. 추가 사선이나 보조 광원 대조가 필요하면 그 조건에서도 전후를 한 쌍으로 확인한다.
5. 최고 높이 감소와 함께 넓은 면이 의도대로 올라오는지, 중앙이 뾰족하지 않은지, 경계 복귀부의 띠·입구 꺾임·덧댐 분리가 남는지 기록한다. 원인 분리는 [가죽 룩디벨롭과 디노이즈](LEATHER_LOOKDEV_AND_DENOISE.md)를 따른다.

이 문서에서는 함수의 경계 미분을 대수적으로 확인했으며 실제 메시 단면·렌더 전후는 미실행이다. 정지 검수만 허용된 프로젝트에서 재생·시뮬레이션·베이크·전체 충돌·전체 위상 검사로 임의 확대하지 않는다.

## 7. Native 드라이버의 잔여 매듭과 실제 키값을 검증한다

공식 [Drivers Introduction](https://docs.blender.org/manual/en/5.2/animation/drivers/introduction.html)은 드라이버 구성의 출력 `x`가 다시 F-Curve를 거쳐 최종 속성값이 된다고 설명한다. 그래프의 가로축은 이 출력값이며 일반 애니메이션의 프레임으로 해석하지 않는다. [Drivers Panel](https://docs.blender.org/manual/en/5.2/animation/drivers/drivers_panel.html)에서 변수 하나의 Average는 그 변수값을 내지만, F-Curve가 항등이라는 보장은 별도다.

native 경로의 설계는 예를 들어 `driver.type=AVERAGE`, 변수 하나 `type=SINGLE_PROP`, 정확한 ID와 RNA path, 의도한 F-Curve 매핑으로 구성한다. 사용자 속성 각도가 도 단위 숫자인지, 회전 RNA가 라디안인지 먼저 확인한다. Single Property는 부모·제약을 반영한 최종 Transform Channel과 다르다. 값이 정상처럼 보이는 fallback이 잘못된 경로를 가리지 않는지도 확인한다.

1. 새로 만들거나 재설정하기 전에 대상 ID·키 data path·array index를 확정하고 기존 드라이버/곡선의 매듭·핸들·modifier·extrapolation·mute를 보존 기록한다. 다른 드라이버 전체를 지우지 않는다.
2. 생성 API나 UI가 남긴 기본점 또는 이전 편집의 `(1,1)`을 포함해 **모든** 매듭을 실제 열거한다. 모든 Blender 생성 경로가 반드시 `(1,1)`을 만든다고 가정하지도, 요청한 점만 추가하면 나머지가 없어졌다고 가정하지도 않는다.
3. 해당 곡선을 완전히 재작성하도록 승인된 경우에만 그 곡선의 기존 점을 제거하고 목표 목록을 다시 넣는다. Generator·Noise·Limits 등 modifier와 sampled data도 별도로 확인해 의도한 매핑 하나만 남긴다. 승인된 기존 보정이 있다면 보존하고 목표 목록에 포함한다.
4. 매듭 수·좌표·보간·핸들·구간 밖 동작을 목표 목록과 비교한다. 예를 들어 목표점 `(0,0),(5,0),(90,1),(180,1)`에 잔여 `(1,1)`이 있으면 1도에서 의도하지 않은 돌출이 생길 수 있다. 이 예는 오류 구조 설명용이며 채택할 각도 곡선은 제품별로 정한다.
5. Linear는 점 사이 값이 선형이지만 기울기가 꺾일 수 있고, Bézier는 매듭 외 구간의 overshoot와 핸들도 확인해야 한다. Auto Clamped의 역할과 자동 핸들 변경 범위는 [F-Curve Properties](https://docs.blender.org/manual/en/5.2/editors/graph_editor/fcurves/properties.html)를 따른다. 화면상 부드러워 보이는 곡선도 목표 각도의 수치를 대조한다.
6. 의존성 갱신 뒤 `0/1/2.5/5/90/180도`의 허용된 정지 상태를 각각 설정하고 아래 표를 채운다. 재생 없이 상태를 바꾸는 검사도 해당 제품에서 허용됐는지 확인한다. 각도 정의가 반대면 열림/닫힘 의미와 입력 변환을 기록한다.

| 설정 각도 | 실제 제어 RNA·변수값 | 구성 출력 x | 의도한 곡선 출력 | 실제 곡선 출력 | native 키 value와 오차 |
|---|---|---|---|---|---|
| 0도 | 미실행 | 미실행 | 제품 설계값 | 미실행 | 미실행 |
| 1도 | 미실행 | 미실행 | 제품 설계값 | 미실행 | 미실행 |
| 2.5도 | 미실행 | 미실행 | 제품 설계값 | 미실행 | 미실행 |
| 5도 | 미실행 | 미실행 | 제품 설계값 | 미실행 | 미실행 |
| 90도 | 미실행 | 미실행 | 제품 설계값 | 미실행 | 미실행 |
| 180도 | 미실행 | 미실행 | 제품 설계값 | 미실행 | 미실행 |

위의 설명용 네 점을 Linear 보간하고 입력 `x`가 도 단위 각도와 같다면 여섯 각도의 예상값은 차례로 `0,0,0,0,1,1`이다. 이는 표 작성 예이며 제품별 목표 곡선과 실제 native 측정값을 대체하지 않는다.

[FCurve API 5.2](https://docs.blender.org/api/5.2/bpy.types.FCurve.html)의 `keyframe_points`, `modifiers`, `sampled_points`, `evaluate`, `update`는 좁은 점검에 참고할 수 있다. `update()`는 정렬·핸들 갱신이며 씬 의존성 평가를 전부 대신하지 않는다. `evaluate`의 인자 이름이 frame이어도 드라이버 그래프 대조에서는 가로축 입력의 단위에 주의하고, 보조 곡선 계산만으로 Blender의 실제 키값 읽기를 대체하지 않는다. slider 범위·mute·잘못된 ID·업데이트 지연 등도 최종값과 차이를 만들 수 있다.

원하는 구성 출력, 곡선 출력, 실제 native `key_blocks[대상].value`를 별도로 기록한다. Python에서 만든 예상값만 출력하거나 invalid 경고가 없다는 이유로 PASS 처리하지 않는다. 필요한 상태·저장·재열기 확인 후 사용자의 원래 제어값을 복원한다. 저장 성공과 전체 동작 검증도 구별한다.

## 8. 실제 제작 인계 순서

1. 최신 승인 참고와 기존 후보를 읽고 별도 Guide에 넓은 곡면 단면·포켓 내부 이동·고정 경계·복귀 폭을 표시한다.
2. 단일 점유를 인수한 제작 담당이 기존 키/좌표계를 확인하고 곡면 분포를 먼저, 높이 진폭을 다음으로 조정한다. 포켓은 기존 볼록 형상에 기준면 이동과 경계 복귀를 분리해 적용한다.
3. 새 키는 기존 혼합에 더할 잔차로 작성한다. UV·두께·입구·덧댐·실의 동행과 고정 경계를 확인한다.
4. 드라이버의 전체 매듭과 modifier를 검사하고 여섯 각도의 실제 native 키값을 대조한다. 발견한 기존 오류의 수리는 별도 승인된 제품 작업에서 수행한다.
5. 허용된 동일 조건 solid/wire·단면·반사 전후로 검수한다. 고정 경계 최대 이동, 목표/실제 높이, 내부 형상과 입구, 좁은 복귀부의 잔여 띠를 남긴다.
6. 후보와 검수 근거·미검증·마지막 저장/제어 상태를 인계한다. Claude는 기존 매뉴얼 기반 제작을 맡고 신규 교육·매뉴얼 보강은 Codex가 맡는다.

문서 기능 근거는 Blender Foundation의 위 5.2 공식 문서다. 함수와 절차의 조합은 이 용도를 위한 자체 적용 설계이며, 물성·길이/체적 보존·모든 접힘 상태의 성공은 보장하지 않는다. 공개본에는 제품 이미지·모델·개인 경로·외부 본문 전문을 포함하지 않는다.
