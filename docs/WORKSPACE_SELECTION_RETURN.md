# 작업 선택 화면과 작업 공간 사이의 복귀

2026-11-09 공식 자료 세 절을 읽고 작성한 적용 설계다. 제품 코드·폰·앱·서버를 조작하거나 새 선택 화면을 실기 검증한 기록이 아니다. 기존 [버튼 상태](UI_BUTTON_STATE_FEEDBACK.md)와 [모바일 작업 안내](MOBILE_TABS_TASK_GUIDANCE.md)의 입력·초안·사진·좌표 보존을 재사용한다.

## 1. 선택하고 크게 작업한 뒤 돌아온다

처음에는 짧은 이름의 일반 버튼으로 작업을 고르고, 선택한 작업 공간 하나를 크게 보여 준다. 작업 공간에는 현재 기능, 짧은 다음 행동, 실제 미저장/오류/PC 반영 미확인과 “작업 변경”을 둔다. 반복 설명은 상세로 접는다. 여기서 작업 변경은 기능 선택 화면으로 돌아가는 동작이며 현재 사진쌍·작업 파일을 교체하거나 저장하는 동작이 아니다.

일반 선택 버튼과 이름 있는 영역을 사용한다. 영구 탭 행을 사용하지 않는 이 구조에 tablist/tab/tabpanel, aria-selected 및 화살표 탭 키보드 규칙을 붙이지 않는다. 기존 모바일 안내의 §2 짧은 안내/Disclosure와 §4 상태·숨은 캔버스 보존은 적용하되 §3 탭 규칙은 실제 탭 위젯을 만들 때만 적용한다.

## 2. 보이는 목적지로 초점을 옮기고 복귀시킨다

[WAI Button Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/)의 활성화 후 초점 절은 맥락이 바뀌면 새 행동의 시작점으로 초점을 옮기는 것이 적절할 수 있다고 설명한다. 작업 공간을 실제로 드러낸 뒤 제목 또는 첫 관련 조작처럼 시작 맥락을 알 수 있는 곳으로 초점을 옮기는 방식을 적용한다. 비모달 작업 공간을 대화상자로 취급하거나 초점을 가두지 않는다.

“작업 변경”은 선택 화면을 먼저 드러내고, 원래 눌렀던 선택 버튼이 아직 유효하고 사용 가능하면 그 버튼으로 초점을 돌리는 것을 제안한다. 그 버튼이 없어졌으면 선택 화면 제목이나 첫 유효 선택지를 사용한다. 숨길 영역 안에 초점을 남기거나 보이지 않는 버튼으로 이동하지 않는다. 단순 저장 안내·렌더·확대마다 초점을 강제로 이동하지 않는다.

[WCAG Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)는 의미와 조작을 보존하는 논리적인 순서를 요구하며 특정 목적지 하나를 모든 앱에 강제하지 않는다. 위 제목/버튼 목적지는 이 작업 구조의 제안이다. 정적 제목을 프로그램 초점 대상으로 쓰더라도 불필요한 일반 Tab 정지점을 늘리지 않고 화면 배치·읽기 순서와 연결한다. native Views의 입력 focus와 TalkBack 접근성 focus가 자동으로 같다고 가정하지 않는다. 실제 키보드·화면읽기로 별도 확인한다.

## 3. 숨김은 삭제·저장·취소가 아니다

[WHATWG hidden 절](https://html.spec.whatwg.org/multipage/interaction.html#the-hidden-attribute)은 현재 맥락에 해당하지 않는 상태를 렌더하지 않는 Hidden 상태와, 숨겨져도 실행될 수 있는 스크립트/폼을 설명한다. 비활성 화면은 시각·키보드·화면읽기의 현재 대상에서 함께 빠지도록 하고 실제 CSS가 hidden을 덮어쓰지 않는지도 확인한다. 명시적 선택으로 여는 이 구조에 until-found나 숨은 영역으로 직접 가는 링크를 추가할 필요는 없다.

화면 전환에 전체 문서 reload·history 조작·하드웨어 Back 가로채기를 도입하지 않는다. 기존 WebView·패널·데이터를 유지하며 전환 전 blur/입력 확정 및 진행 중 터치 취소 정책을 적용한다. 숨겼다는 이유로 비동기 쓰기까지 취소됐다고 표시하지 않는다. 기존 모델의 작업·사진·원본 좌표·모드·선택점·dirty·저장/페어링 상태를 보존하고 지연 응답이 다른 작업 안내를 덮지 않게 한다.

재노출 후 실제 표시 크기가 양수일 때만 사진 맞춤/캔버스 변환을 계산한다. 기존 모바일 안내 §4의 resize·사진 디코딩·원본 좌표 보존 기준을 사용한다. 화면 선택 자체가 초안 저장·결과 파일 생성·PC 적용 성공을 뜻하지 않는다.

## 4. 검수 경계

확인할 항목은 선택→작업→복귀의 표시/초점, 숨은 화면의 키보드·접근성 제외, 작업 변경 전후 입력/사진/좌표/초안 보존, 재노출 크기와 조작 위치, 취소·지연·오류 뒤 현재 상태 일치다. 좁은 화면·큰 글씨·TalkBack은 실제 검수 결과를 별도로 기록한다.

이 문서는 공식 세 절의 학습과 적용 제안이다. 기존 탭 시제품의 시험 수치나 이전 버튼 실기를 새 선택 화면 성공으로 재사용하지 않는다. 새 선택/복귀 UI·초점·저장·회전·접근성은 **미검증**이며 설치·의존성·계정·외부 설정 변경을 포함하지 않는다.

[자료별 선택 열람 기록](../reports/ExternalLearning/20261109_WORKSPACE_SELECTION_RETURN_STUDY.json)을 함께 확인한다.

## 5. 공식 사진 편집 앱 화면에서 참고할 구조

공식 Google Play의 [Adobe Lightroom](https://play.google.com/store/apps/details?id=com.adobe.lrmobile&hl=en), [Google Snapseed](https://play.google.com/store/apps/details?id=com.niksoftware.snapseed&hl=en), [Google Photos](https://play.google.com/store/apps/details?id=com.google.android.apps.photos&hl=en) 소개 페이지와 게시된 편집 이미지 각 한 화면을 관찰했다. Lightroom은 큰 사진 아래 관련 조작·도구를, Snapseed는 사진 아래 이름 있는 도구 그룹과 강조된 선택을, Google Photos는 큰 사진 가까이에 선택 조작과 별도 실행 조작을 보여 줬다. 이는 공개 마케팅 화면의 관찰이며 실제 앱 탐색·저장 동작을 실행한 기록이 아니다.

재사용할 제안은 사진 공간을 먼저 확보하고 현재 작업에 필요한 소수 도구를 가까이 두는 것이다. 선택 화면에서 기능을 고른 뒤 큰 작업 공간을 열고 명시적으로 복귀하는 흐름은 이 문서의 적용 제안이며, 관찰한 세 앱 모두가 같은 흐름이라는 주장은 아니다. 아이콘만 모방하지 말고 짧은 한국어 기능 이름과 대비·체크/텍스트의 현재 상태를 함께 둔다. 중복 헤더·반복 설명은 줄이되 미저장·오류·PC 반영 미확인은 짧게 남긴다.

다른 앱의 체크/완료 표시는 이 프로그램의 저장 근거가 아니다. 기기 초안 저장·결과 파일 생성·PC 접수·PC 계산/명시 반영을 각각 구분하며 알 수 없는 PC 결과는 미확인으로 둔다. 브랜드·아이콘·사진을 복제하거나 원본 캡처를 공개 자산으로 사용하지 않는다.

열람 당시 소개 페이지의 업데이트 표시는 각각 2026-11-04, 2026-11-05, 2026-11-04였다. 숫자 앱 버전·이미지 촬영 버전과 전 세계 최신 배포 상태는 확인하지 못했다. 실제 앱 실행·설치·로그인·개인 사진 업로드·유료 기능 실행은 0이다. 위 배치 제안의 제품 조작·저장·접근성 통과도 별도 검수 전까지 미검증이다. [공식 화면 선택 관찰 범위](../reports/ExternalLearning/20261109_PHOTO_EDITOR_UI_REFERENCE_STUDY.json)를 참고한다.
