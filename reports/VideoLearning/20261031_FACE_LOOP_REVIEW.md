## 관찰과 자체 해석의 분리

- **직접 화면 관찰:** 초반 얼굴 위 표식·색선, 눈 주변 띠의 형성, 코 아래 V형 연결, 안쪽 눈 사이/콧대 패치 추가, 이후 볼·입 경계 추가, 사선·아래 시점의 면 배치. 이 순서는 실제 표본의 진행 차이를 읽은 것이다.
- **자체 제작 해석:** 기능별 루프를 먼저 정하고 연결을 설계하는 작업 순서, 현재 Blender 보존·Guide·단일점유·검수 절차, 폴과 밀도·경계 전환 문제를 해결하는 체크리스트. 강사의 정확한 발언이나 특정 수치의 요약으로 둔갑시키지 않았다.
- **도구 사실:** RF의 Source/Target 규칙과 PolyPen/Strokes 기본 사용은 설치된RF3.4.11 도움말·코드와 공식 RF 문서를 확인했다. Dikko 영상에 RF 사용이 보였다고 주장하지 않는다.
- **실제 챕터 내용 보정:** 제공된 40:28 이후 맥락을 전부 눈꺼풀이라고 묶지 않았다.40:28/41:00은 눈 경계·안쪽 방향 면,42:00~45:00은 주로 입술/구강 안쪽이며47:00 이후 표본은 목·몸통이다.
- **제한:** 검은 표식의 정확한 구두 설명·폴 개수, 음성상의 이유, 연속 조작·모든 변형 품질은 미확인이다.

## 기존 로컬 Qwen / FrameLens 실행

사용자가 알려준 기존 격리 설치를 이용했다. 앞선 일반 Ollama 경로 조사만으로 로컬 시각 모델이 없다고 판단하면 안 된다. 기존 `video-analysis` 도구 폴더의 README·런처·분석 스크립트를 읽었다.

- 기존 `127.0.0.1:11436` listener를 확인하고 `/api/tags`에서 `qwen3-vl:4b-instruct`, digest `84f7ed8042fa7cdbd902f7dcb7d0370e032095047cc3244179f263b77b5bc318`를 읽었다. 기존 서버를 재사용했다. 새 서버/모델 다운로드/기존11434 변경0.
- 기존 `analyze_qwen.py`를 사용했다. 전체52분을6장으로 요약하지 않고,08:00~10:00/10:00~12:00/12:00~13:55 세 구간을 로컬 clip으로 나눠 각6장씩 분석했다.
- script는 입력 이미지를640px 이내로 축소하고 응답을600토큰으로 제한한다. 실제 결과3개 모두 `model=qwen3-vl:4b-instruct`, `done=true`, `local_only=true`, 비어 있지 않은 content를 확인했다. 요청 endpoint와 코드상 전송 대상은 loopback이었다. 이 메타데이터만으로 의미 정확성이 보장되지는 않는다.
- Qwen에 영상의 도구가 RF라고 가정하지 말고 화면에 보이는 변화/추정을 구분하도록 요청했다. 결과는 아래 원본 프레임과 Codex가 직접 대조했다.
- FrameLens는08:00~10:00 clip에 기존 `Analyze-Video.ps1 -Tool FrameLens`로 실행했고 shot1개를 반환했다. 컷 검출 결과를 루프·용접의 의미 판정으로 사용하지 않았다.
- VideoReverse mock은 사용하지 않았다. 원본 음성·캡처·Qwen의 이미지 payload는 Git에 넣지 않았다.
