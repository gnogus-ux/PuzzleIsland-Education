2026-10-31. 기존 사용자 승인인 영상 학습·재사용 매뉴얼·문서 Git 게시의 후속이다. [매뉴얼 E절](../../docs/FACE_RETOPOLOGY_BASIC_LOOPS.md)의 코 연결 내용을 보강했다. Blender 점유·편집·저장, 리그·움직임 작업은 수행하지 않았다.

이번 코 학습은 **고유44장**이다. 첫 학습77장과 겹치는1095/1140/1200초3장을 제외하면 신규41장, 누적 고유118장이다. 13:55~18:00의 기존 입체 맥락과 기본 루프 기록은 이전 [학습 보고서](20261031_FACE_LOOP_REVIEW.md)를 재사용했다. 이번에 그 구간을 새로 연속 시청했다고 주장하지 않는다.

각 시각은 원본 시작을0으로 한 초다. Qwen clip은 시작 offset을 고정해 재인코딩한10fps 영상이며, 모델이 보고한 상대 표본 시각에 offset을 더했다. 원본 정지 프레임과 clip 디코더의 프레임 선택에는 수십ms 차이가 있을 수 있다. 화면 전후는 실제 표본에서 읽었고, 연속 동작·음성 설명·원본 .blend 데이터는 확인하지 않았다.

## 직접 관찰한 코 연결 진행

- **18:15~18:50:** 눈 안쪽과 콧대는 이미 녹색 면으로 덮여 있다. 코끝 쪽에 열린 패치가 있으며 갈색의 촘촘한 원본이 드러난다. 18:50 확대 화면에서도 이 영역이 보인다. 이는 실제 콧구멍 안쪽 벽을 보여준다는 증거가 아니다.
- **18:55~19:00:** 코와 입 위쪽을 사선·아래에서 본다. 패치가 앞쪽으로 돌출하는 모양과 주변 경계 관계를 읽을 수 있다. 정면의 평면 배치만으로 코를 판정하면 놓칠 깊이가 있다.
- **19:05~19:20:** 코끝 중앙의 녹색 면 띠가 보이고, 원본 노출 부분이 나뉘거나 줄어든다. 19:10에는 선택된 면과 그 아래의 원본 노출이 함께 보인다.
- **19:25~19:40:** 코끝 전면과 옆을 덮는 면이 늘고 작은 원본 노출 영역이 남은 단계가 보인다. 19:40 확대에서는 양쪽 작은 갈색 영역이 보인다. 이를 최종 콧구멍 구조라고 단정하지 않았다.
- **19:45~20:00:** 정면에서 코끝까지 녹색 cage로 덮인 상태가 보인다. 19:45 화면에는 Sculpt Mode와 브러시가 보이지만 정확한 브러시 설정·스트로크·변위를 모두 복원하지 않는다. 보이는 덮임은 실제 공유 정점 용접·닫힌 볼륨·교차 없음의 수치 증거가 아니다.
- **20:05~21:20:** 측면, 위, 아래, 전체 시점을 돌려 코 돌출·코옆과 볼 연결·얼굴 마스크를 확인한다. 귀와 정수리 쪽 외곽은 열린 마스크 상태다. 코 표면이 덮인 상태와 얼굴 전체 완성은 구분한다.

## 로컬 도구 실제 실행과 한계

기존 `127.0.0.1:11436` listener(PID22548)와 모델 목록을 확인해 서버를 재사용했다. 모델은 `qwen3-vl:4b-instruct`, digest `84f7ed8042fa7cdbd902f7dcb7d0370e032095047cc3244179f263b77b5bc318`이다. 기존11434 변경·서버 재시작·모델 다운로드는 없었다.

최초1095~1155초 clip을8장 입력으로 분석하다 HTTP400이 났다. 당시 오류 본문이 저장되지 않아 정확한 원인은 **미확인**이다. 입력 개수·컨텍스트 문제로 확정하지 않았다. 기존 성공 조건인6장으로 보정했고, 오류 본문을 보존하도록 로컬 임시 진단 사본을 사용했다. 설치된 분석 스크립트는 변경하지 않았다.

이후1095~1155/1155~1215/1215~1280초 세 clip에 각각6장씩 실제 호출했다. 세 결과 모두 `done=true`, `local_only=true`, 비어 있지 않은 응답이다. 앞의 두 결과는 `done_reason=stop`, 셋째는 `done_reason=length`,600토큰에서 끝나 문장이 잘렸다. 결과3개를 얻은 사실과 내용의 정확성을 구분했다. 짧은 반복 분석을 더 수행하지 않고 원본을 직접 대조했다.

| 모델 출력 | 실제 원본 대조 | 매뉴얼 처리 |
|---|---|---|
| 첫 clip에서 매 시각 피부·다각형이 더 명확하게 흐트러진다는 반복 | 18:20~19:10은 시점 전환과 코끝 면 추가 단계가 보이며, 반복 문장으로 구체적 변화를 설명하지 못함 | 형태 악화·개선의 근거로 쓰지 않음 |
| 둘째 clip 내내 콧대 뒤쪽이 열린 패치이고 원본이 보인다는 반복 | 19:40에는 작은 노출 영역이 있지만, 20:00/20:10에서는 코끝 표면이 녹색 cage로 덮여 있음 | 후반까지 계속 열려 있다는 주장 제외 |
| 셋째 clip에서도 갈색 원본이 코 경계를 따라 계속 보이고 코가 점차 내려간다는 서술 | 추가6장에는 덮인 코 표면과 시점·줌 변화가 보인다. 코의 지속적 하강을 입증할 고정 카메라·좌표 근거가 없음 | 원본 노출·하강 주장 제외; 문장 잘림도 기록 |

프롬프트로 열린 리토포 패치와 콧구멍을 구분하라고 요청했지만 오답을 막지는 못했다. 모델에 제공된 이미지 크기는 최대640px이며 출력600토큰 제한이다. 로컬 모델의 영상 입력 처리 성공을 곧 코 형태·접속 이해 성공으로 보고하지 않는다.

FrameLens도 첫60초 clip에 실제 실행해1shot을 반환했다. `semantic` 필드는 null이며 컷/움직임 검출 결과로 코의 위상·용접·폴을 판정하지 않았다. VideoReverse mock이나 외부 API는 사용하지 않았다.

## 자체 제작 지침과 미확인 범위

매뉴얼에는 코 연결 입구·랜드마크 → 중앙/콧대 → 코끝 곡면 → 코옆·콧방울/볼 전환 → 필요한 콧구멍 별도 설계 → 접속/표면 검수 순서를 자체 지침으로 추가했다. 경계 개수, 국소 전환, X seam, 면 중앙 이격, 폴·밀도, 동일 조건 solid/wire 확인은 프로젝트의 후속 제작·검수 기준이다. 강사의 정확한 발언이나 원본 데이터 검사 결과로 쓰지 않았다.

**표본으로 확인하지 못한 것:** 콧구멍 안쪽 벽의 깊이·종단, 정확한 폴 위치·valence와 모든 정점/면 수, 모든 면의 quad 여부, 원본과의 실제 공유 정점·용접 상태, 전체 자가교차, 음성상 설명과 정확한 도구 조작, 루미에서의 시각 개선·변형 품질.

자체 SVG `nose-connection-flow.svg`는 정면의 구역별 흐름과 측면 깊이 검수 위치를 설명한다. 원본 영상 tracing·화면 임베딩·루미 실측 좌표가 없으며, 실행 가능한 메시/Blender Guide가 아니다. 동일 기하의 로컬 PNG로 글자·선 겹침을 확인한 뒤 라벨을 조정했다.

루미 v021은 Target 내부 연결·X seam과 원본 용접을 구분했던 기존 판정을 유지한다. 원본 미용접, 눈 경계 전환, 코 곡률·밀도는 계속 **PARTIAL**이다. 영상 학습 완료를 실제 모델 수선 완료로 바꾸지 않는다.
